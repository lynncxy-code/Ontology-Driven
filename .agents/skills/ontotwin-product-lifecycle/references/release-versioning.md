# OntoTwin 部署版本号规则

适用于发布到 5501 和交付给工厂的版本。PRD 的写法和编号不受影响。本规则只管号码和名字，发布步骤见开发流程。产品于 2026-11-23 确认。

## 一、两种版本

| | 候选版 | 正式版 |
|---|---|---|
| 用途 | 放在 5501 给产品验收 | 交付给工厂 |
| 写法 | 候选 24（内部写 `rc.24`） | OntoTwin 2026.12.1 |
| 怎么编 | 5501 每发布一次加一，全局只往上数，永不归零 | 年.月.当月第几次正式发布 |
| 从哪来 | 最新 dev 加上待验收草稿，从存档代码完整打包 | 验收通过的某个候选原样转正，不重新打包 |

- 一个号码只对应一版内容，不复用、不改写。转正时记下“2026.12.1 由候选 31 转正”。
- 改动大小不靠数字表达，写在版本说明的“升级须知”里。

## 二、全产品一个号码

- 网页、后台、UE 同步插件、行为库、人物包共用一个版本号。任何一部分变了，整体出新版本。
- 某一部分是否真的要更换，按内容指纹判断，写进说明；没变的部分写“自 2026.11.1 起未变”。
- 号码不写进插件源码，安装时写在插件旁边的小文件里。UE 里显示的号码和网页不一致，就说明没装对。

## 三、每版必带的版本说明

- 版本号、候选或正式、发布时间、来源存档号；正式版另写“由候选 N 转正”。
- 本版新增编号：由发布命令从存档说明中自动收集。每个编号带上所属 PRD，这在登记编号时就写好；不属于任何 PRD 的写“无”。例：NEW-03（PRD 3.4.4 第一阶段）、BUG-26（无）。
- 各部分变化：哪些变了，哪些自哪一版起没变。
- 升级须知：要不要迁移数据、要不要关闭 UE、要不要重启后台。
- 台账里每个编号记下“首次进入：候选 N / 正式 X”。

## 四、命名

| | 候选版 | 正式版 |
|---|---|---|
| git 标签 | `rc.24` | `v2026.12.1`（贴在同一次存档上） |
| 镜像 | `ontotwin/platform:rc.24`、`ontotwin/db:rc.24` | 同一镜像再加名 `:2026.12.1` |
| 交付包 | 一般不出；需要时 `OntoTwin-rc.24-full.zip` | `OntoTwin-2026.12.1-full.zip` |

- 镜像前缀只用 `ontotwin/`。客户名不进版本号和镜像名，客户属于“环境”的名字。
- 文件名只用英文、数字、点和横线；包内说明用中文。
- 不建发布分支。

## 五、修 bug

只修最新版：修复进入下一个正式版，工厂升级后获得。工厂确实无法升级时，经产品同意可在旧版上修补，写作 `2026.11.1.1`。

## 六、在哪里看到

- 账号菜单：“OntoTwin 2026.12.1 · 正式版”或“OntoTwin 候选 24 · 验收版”，点开看版本说明。
- 台账“5501 当前运行的版本”填“候选 24”，“包含”填版本说明里的编号。
- 部署管理器：“当前 2026.11.1 → 待导入 2026.12.1”，下面列出升级须知。
- UE 插件版本面板：显示同一个号码。

## 七、和旧号码的衔接

- `4.8.0-rc.23` 及之前是旧写法，保留作历史，不改名（`v4.8.0-rc.21` 标签、`release/*` 分支、旧镜像）。是否清理归清理工作管。
- 5501 下一次发布就是候选 24。
- 第一个按新规则转正的版本，按转正那个月领取正式号，说明里注明“接替旧称 4.8.0-rc.23”。
- 已装在工厂的旧版，升级前仍显示旧号码。
- 接口路径 `/api/v2`、`/api/v4.8` 是接口代号，与版本号无关，不改。
