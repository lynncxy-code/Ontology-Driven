# 2D 视觉审计沉淀与提示词

## 何时使用

当用户提供截图、页面流程或视觉描述，并要求做 UX 审计、跨页面统一或把设计积累进技能时，先读本文件。它只负责提取和记录设计语言，不替代 `ontotwin-ui/SKILL.md` 中已经确认的 token、组件配方和交互约定。

## 1. 先分离证据、决策与提案

对每条结论标记来源：

- **观察事实**：截图或流程中直接可见的内容，附页面/步骤/区域；没有证据的状态（如 hover、键盘焦点）写成“未提供”。
- **既有决策**：技能文件中的现行规则，除非用户明确要求，不得被截图中的局部偏差覆盖。
- **待确认提案**：为了统一或改善体验而提出的新 token、组件或交互；必须列入待确认问题，不能直接写成既定规范。

不要从单张截图推断断点、动画时长、语义色含义或业务规则。可以提出验证建议，但要明确“不确定”。

## 2. 提取矩阵

按以下顺序记录隐式线索，尽量给出可复用的角色和值：

1. **页面骨架**：视口尺寸、内容最大宽度、导航/侧栏/主区关系、网格列数、对齐线、面板密度、滚动边界和响应式变化。
2. **视觉 token**：颜色及其角色（页面底、面板、文字层级、边框、hover、选中、错误/警示/成功）；字体族、字号、字重、行高、数字样式；间距、圆角、边框、阴影；图标笔画、尺寸和对齐。
3. **组件配方**：按钮、输入、下拉、表格行、标签、模态、Toast、Tooltip、空态、加载态、错误态的结构、层级、尺寸和状态。
4. **交互语义**：主/次操作、可逆性、确认模式、保存成功后的去向、就近错误、键盘顺序、焦点恢复、批量操作与选择模型。
5. **文案与信息架构**：用户任务、标题层级、字段标签、帮助文案、技术词翻译、空态下一步和危险后果说明。
6. **可访问性与适配**：对比度、非颜色线索、最小触控/点击区域、键盘可达性、焦点可见性、缩放、窄屏/宽屏和减少动画。
7. **禁止项与例外**：重复出现的反模式，以及必须保留的业务特殊性；说明例外的适用范围。

## 3. 可复制给 AI 的审计提示词

```text
你是 OntoTwin Nexus 的资深 UX 设计系统审计师。请基于我提供的截图、页面流程和文字背景，把隐式视觉线索转换成可执行的 2D 设计需求。目标是让多个页面共享同一套语言，而不是复制某一张截图。

项目基线：
- 规范来源：ontotwin-ui/SKILL.md；其中已定 token、组件配方、交互约定和禁止清单是当前事实来源。
- 风格基线：克制的黑白灰专业工具界面；语义色只做小面积提示。
- 未在材料中出现的状态或数值必须标为“未提供”，不得猜测。

输入材料：
- 目标用户与核心任务：{填写}
- 页面/流程及截图来源：{填写文件名、步骤或区域}
- 设备、视口和语言：{填写}
- 已确认业务/品牌约束：{填写}

请按以下顺序输出：
1. 设计背景与关键任务（不超过 5 条）。
2. 观察事实表：位置/元素、可见特征、来源、对用户的作用、置信度。
3. 设计 token 建议：颜色、字体、字号/行高、间距、圆角、边框、阴影、图标；每项给“沿用现有 / 截图观察 / 待确认”，不要擅自替换现有 token。
4. 组件规范：每个组件的 anatomy、尺寸、层级、默认/hover/focus/pressed/disabled/loading/empty/error 状态、键盘与读屏语义。
5. 页面骨架与响应式规则：容器、网格、断点、滚动和窄屏降级；区分证据与建议。
6. 交互流程审计：成功、失败、取消、撤销、切换、危险操作、加载和空态的反馈与用户控制。
7. 文案与术语：给出可直接使用的短文案，并标记需要业务确认的词。
8. 可访问性检查：WCAG 对比度、点击区域、焦点、键盘、减少动画和非颜色表达。
9. 禁止清单：从材料中提炼会破坏跨页面一致性的做法。
10. 待确认问题：只列会改变 token、组件行为、信息架构或业务语义的问题；每题说明两种选择的影响。
11. 沉淀补丁草案：指出应写入 ontotwin-ui/SKILL.md 的具体段落或新增 reference；仅使用已确认内容，未确认项保持“提案”状态。

输出要求：数值使用 px/HEX/对比度等可执行单位；同一角色只给一个 canonical 值；不要把 3D 液态玻璃效果带入 Web 编辑器。
```

## 4. 写回技能的规则

- 现有 token 与“已定决策”优先；局部截图差异先记为观察或提案，不直接改基线。
- 只有用户明确确认的提案才能写入 `SKILL.md` 的 token、组件或已定决策；其余放在审计记录的“待确认”区。
- 跨页面重复出现的规则写一次 canonical token/配方，页面特例必须写清适用范围和退出条件。
- 每次沉淀注明日期、来源页面和变更原因；不为一次性视觉偏好添加全局规则。
- 2D 规范与 `ontotwin-ue-glass-ui` 分离；Web 页面不得因为“统一”而引入背景模糊、折射、连续流光或玻璃透明度。
