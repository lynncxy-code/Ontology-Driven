## 3. S2 手工验收数据

准备一个非内置数据集，至少包含：

- 3 个设备类型、10 个实例；
- 1 份有效标定、1 个空间帧、2 个分区；
- 1 个 Overlay；
- 1 套漫游配置和 1 条路线；
- 1 个 Web 页面与交互绑定；
- 1 个 UE 资产引用、1 个本地路径、1 个故意缺失的资源引用；
- 已绑定的来源 UE 工程。

## 4. 导出验收

1. 在“我的数据集”找到未激活的数据集。
2. 选择“导出数据集包”。
3. 核对摘要包含类型、实例、空间帧、分区、路线、Web 页面和待核对资源。
4. 下载 `.otdataset` 文件。
5. 确认当前激活数据集未切换，来源 UE 绑定未改变，来源数据未变化。

否决条件：必须先激活才能导出；摘要只显示图谱；导出改变来源项目；下载内容是数据库 dump 或项目 JSON。

## 5. 导入验收

1. 在另一套空白或已有项目的 OntoTwin 中打开“我的数据集”。
2. 确认“导入数据集包”位于“新建空数据集”下方。
3. 选择包，确认预检完成前列表中没有新数据集。
4. 核对来源 UE、版本、内容数量、资源警告和排除项。
5. 如有同名数据集，确认系统建议“副本”名称且可编辑。
6. 确认导入。
7. 确认新数据集 ID 不同于来源 ID，且未激活、未绑定；原激活数据集不变。
8. 预览图谱，核对类型、关系与来源一致。

否决条件：预检即写入；覆盖同名项目；导入后自动激活或自动绑定；失败留下半成品。

## 6. UE 换机与运行隔离验收

1. 将来源 UE 源工程、兼容 OntoTwin 工具和数据集包复制到目标电脑。
2. 导入数据集包并手动激活。
3. 打开目标 UE 源工程，由 UE 主动绑定当前数据集。
4. 核对实例、模型、空间位置、Overlay、分区、漫游、路线和 Web 交互。
5. 核对缺失资源被明确标记，数据仍可编辑。
6. 在 Web 中激活另一数据集。
7. 确认已绑定 UE 仍显示原绑定数据集的上述运行内容，没有串到 Web 当前激活项目。
8. 尝试从 UE 修改未激活的绑定数据集，确认写入被阻断；只读运行保持正常。

否决条件：Web 切换激活数据集后 UE 内容切换、清空或混入另一项目；Web 交互或路线解说读取另一项目；未激活项目被静默写入。

## 7. 跨存储验收

分别执行：

- JSON 导出 → PostgreSQL 导入；
- PostgreSQL 导出 → JSON 导入。

比较业务数据与关系，不比较底层文件或数据表字节。两次均应满足新 ID、未激活、未绑定、项目配置守恒和运行隔离。
