## 3. 需要独立设计的技术契约

本节列交付约束，不预先批准数据库表、字段布局或文件格式。

1. **接管任务持久化**：环境、组织/工厂、项目、工程、场景、发起UE会话、源基线、审核版本、当前阶段、操作者、权限检查、失败码、备份位置、恢复状态应可回读。轮次证据不得复用通用文件名覆盖前一轮。
2. **身份与重复判断**：源身份至少限定环境、工程、场景与稳定源Actor身份，保存部件归属和实例映射。复制工程/关卡出现身份碰撞时阻断并核对；不按路径/名称猜同一对象。业务编号独立存储与唯一性规则需与现有实例编号接口兼容，不先修改存储。
3. **纯预览**：隔离候选实例、类型与分区，不走正式store激活、不建绑定、不触发运行订阅。证明预览保存/取消不会写源关卡或正式实例。授权与任务草稿写入可存在，但应与正式业务变化区分。
4. **权限与绑定**：完整显式项目上下文贯通所有读取、预检、提交与恢复；后台工作不能脱离任务授权。绑定版本变化使任务失效；工程身份、场景身份和zone不得混为一字段。不得绕过4.8项目编辑校验或冻结守卫。
5. **项目类型与空间目录**：新类型仅目标项目可见；不得调用无项目范围的Neo4j补丁冒充隔离。标准本体不自动写；空间分区使用现有目录语义。分区/类型草稿转正式及恢复时外部引用保护须有契约。
6. **双端切换与停用**：证明StaticMesh源对象在重开、PIE和打包运行下不会继续显示、碰撞或参与Tick；不得只SetActorHiddenInGame就声称停用。归档不改网格材质资产；保留原附着、变换、目录与原开关状态。对蓝图/序列等引用明确检测范围，不确定即阻断。
7. **数据库与关卡非单事务**：定义准备、不可见写入、回读、UE停用保存、运行生效、回执核验的阶段协议。对先后顺序、其他消费者可见性、崩溃后恢复、重试幂等、锁范围与释放责任给出可验证方案；不能仅数据库事务成功就清理源Actor。
8. **恢复及备份**：按批记录逆操作依据，先比较后续版本与引用；只恢复本批，不整库覆盖。保持源归档、关卡备份和数据库记录同一轮次。备份丢失、模型资源变化、双端状态不明时停止自动恢复，保留诊断。明确磁盘容量和权限错误。
9. **资产和变换保真**：复用render_parts前验证镜像、非均匀缩放及父子组合变换；记录材质槽/资源覆盖、碰撞与可见性。实例化网格、动态材质运行态和复杂组件不纳入首版无损承诺。坐标直接保留UE世界基线，不能再次套CAD标定。
10. **跨端授权**：浏览器仅凭短任务号不能接管；短时一次关联凭据与项目权限分离，任务绑定原UE连接，重新连接验证身份。用户撤权不得被旧任务令牌绕过；日志不得记录密码或长期授权令牌。

## 6. 2026-11-07 审计收敛规则

本节覆盖本文件中与新审计结论冲突的表述。

### 6.1 里程碑

- M1 只做 UE 扫描、网页分类、命名、编号、空间归属和接管方案草稿。草稿可持久化，但不创建正式实例、不改变场景绑定、不停用或保存源 Actor。M1 使用统一状态表中的“草稿、待预览、已取消”。
- M1 扫描入口已确认只开放指定 UE 大纲文件夹，界面如实显示扫描范围。当前选中 Actor 入口不属于本批交付，后续必须补齐稳定身份传递后另行验收。
- M2 在 M1 方案上增加临时预览、人工检查、一次性接管和单任务幂等。使用“待确认、执行中、已完成”状态。
- M3 再增加恢复、跨用户并发、故障注入和复杂补偿。数据库停用本批实例可作为可靠动作，UE 源物体恢复在关卡存在后续修改时转为人工核对，不能承诺二进制关卡自动回滚。

### 6.2 身份、粒度和重复扫描

- 源身份键固定为环境、UE 工程身份、关卡身份、源 Actor Guid。相同 Guid 的变换或外观变化是变更，新 Guid 是新增，旧 Guid 消失再出现是删除加新增。M1 清单必须分开显示新增、未变化、变更和源已消失，不能按名称或路径猜测。
- 实例最小单元固定为 Actor。Actor 内的 StaticMeshComponent 是渲染部件，不单独成为实例。一个实例可以有多个渲染部件，部件不能跨实例。母 Actor 自有网格归母实例，附着子 Actor 才能按整体或拆分选择。
- 现有 `migrate_ue_actors.py` 会在 dry-run 判断前调用 `activate`，并可能在正式运行时绑定当前激活项目。它只能作为解析逻辑参考，不能直接接入 M1 或 M2。

### 6.3 资产加载和阻断

- 当前运行时从 `asset_id`、`ue_asset_path` 或 `render_parts[].asset_path` 调用 `LoadObject`。M2 只接收能通过稳定 UE 包路径重新加载的资源。原地临时资源、外部未交付资源和无法证明路径稳定的资源阻断。
- M1/M2 只放行普通 Actor 根节点、SceneComponent 附着关系和 StaticMeshComponent 静态网格渲染。任何其他组件类型默认阻断，蓝图、关卡蓝图和序列依赖另做引用安全检查。当前导出函数仍缺少 Light、Audio 和 Physics Constraint 的完整检测，不能把现有字段当成白名单校验已经完成。

### 6.4 场景绑定、权限和跨端通信

- 现有数据库唯一约束是一个项目一个有效 `project_scene_binding`，以及一个 `ue_project_id + scene_id` 一个有效绑定。M1 只读取并核对，未绑定或冲突停在目标确认。向导不自动换绑，也不扩大同一项目的多场景绑定能力。
- 4.8 的项目 edit 校验要求管理员，或组织 editor、目标工厂成员和项目 permission=edit。每个 M1 草稿写入、M2 预览和确认、M3 恢复入口都重新调用同一权限校验。
- 网页和 UE 之间使用 Flask 任务接口轮询。网页提交请求后，UE 每 2 秒读取一次任务状态并回写阶段和结果。超过 30 秒只显示等待或断线状态，不新建任务、不重复写入。没有 WebSocket 或异步队列的实现依据时，不在产品文案中使用实时推送。

### 6.5 进入 M2 前的 P0 门槛

- 运行路由键和业务空间键必须分开。不能把房间、楼层等业务 `zone_id` 直接当作 UE 地图/场景筛选键。若无法建立独立映射，空间只保留在 M1 草稿，M2 不得正式接管。
- 旧的 `source=ue_migrated` 裸 ActorGuid 必须先进入“历史接管待核对”，不能直接判为新增。未核对项不得进入 M2。
- 附着树扫描必须为每个子 Actor提供 Guid、父子关系、相对变换和子树签名。缺失时只能整体接管，页面不得显示可执行的子 Actor 拆分。
- 工程和关卡身份不能只靠名称或地图路径。M2 需要稳定身份和一次性连接凭据，无法核验时停止。
- 必须完成源物体停用后的可见性、烘焙光照、编辑器定位和性能样品验证。未完成时只交付 M1 草稿。

### 6.6 恢复语义和验收

- “恢复”拆为两部分。数据库停用本批新实例是可验证动作，UE 归档源物体重新启用必须比较任务基线、当前关卡和保存结果。检测到后续修改、引用冲突或状态不明时显示“UE 源物体待人工核对”，不强制覆盖。
- 同一工程和构建下，变换字段按 UE 序列化值逐项相等检查，并配合视觉核对。跨构建容差由技术方案用实测确定，不在 PRD预设固定厘米、角度和缩放数值。
- M1 先验收草稿可回读、项目隔离、权限阻断、身份分类和无正式写入。M2 再验收临时预览、静态资源冷启动和一次性接管。500 单体、2000 部件、全故障矩阵和跨用户并发归入 M3 或发布前门禁。
- 业务编号沿用现有 3.0 实例身份证号目录和自动编号接口，不另建接管专用编号。
