## 1. 产品结论

OntoTwin 2.3.2 为“我的数据集”增加面向用户的数据集包导入和导出能力，使一个已经配置完成的 OntoTwin 项目能够在不同电脑、部署环境和交付现场之间安全迁移。

数据集包是不可手工编辑的产品级迁移载体，不是数据库 dump、原始项目文件或开放 JSON。用户导入后得到一个正常可编辑的新数据集。

首要使用场景是换机迁移：

```text
UE 源工程 + 兼容的 OntoTwin 工具 + OntoTwin 数据集包
→ 在新电脑启动 OntoTwin
→ 导入数据集包
→ 手动激活导入的数据集
→ 在目标 UE 工程中发起绑定
→ 核对资源可用性
→ 恢复项目工作
```

本版本不要求用户接触数据库、修改内部文件或重新手工配置类型、实例和标定信息。

## 2. 背景与现状

当前“加载数据”已经支持：

- 从 CSV 文件包加载本体数据；
- 从图数据库读取本体数据；
- 预览导入结果；
- 保存或发布为数据集。

当前“我的数据集”已经支持：

- 新建空数据集；
- 激活数据集；
- 预览图谱；
- 删除数据集。

现有能力解决的是“从原始数据建库”，没有解决“将一个已经配置完成的数据集整体备份、复制或迁移”。用户换电脑或迁移部署时，仍需要人工处理内部存储、数据库或重复配置，无法形成标准工程的低代码交付闭环。

OntoTwin 当前一个数据集对应一个自洽项目。除语义图谱外，还包含类型、构件、实例、标定、空间和项目级交互配置。因此，仅导出图谱节点和关系不能满足完整迁移。

### 2.1 项目级配置持久化诊断

现有 `ProjectStore` 已持久化空间剖面、空间帧、分区、Overlay 所需类型/实例配置、漫游、路线和 Web 交互；当前问题不是“只有资产被持久化”，而是部分 UE 运行时读取入口没有完整按“UE 所绑定的数据集”路由：

- 实例/资产快照、Overlay、空间帧、漫游和路线已经按 UE 绑定项目读取；
- Web 交互运行投影曾错误读取前端当前激活项目；
- 路线解说音频曾错误从前端当前激活项目查找；
- 项目配置编辑与写回仍应只允许当前激活项目，这是写权限边界，不属于本缺陷。

2.3.2 把“绑定项目的完整只读运行投影”作为换机迁移闭环的前置修复一并交付，不改变项目存储格式，也不放开非激活项目写入。

## 3. 用户与业务结果

### 3.1 主要用户

- 将标准 OntoTwin 工程复制到新电脑的交付人员；
- 在测试、演示和现场环境之间迁移项目的实施人员；
- 在重大配置修改或版本升级前备份数据集的项目维护者；
- 接收 OntoTwin 项目并继续编辑的客户或内部协作者。

### 3.2 用户结果

用户应能做到：

1. 从“我的数据集”导出任意一个已有数据集；
2. 在另一套兼容的 OntoTwin 环境中选择该数据集包；
3. 在任何写入发生前看到完整预检报告；
4. 将其导入为新的、未激活、未绑定的数据集；
5. 手动激活后，在目标 UE 工程中完成绑定；
6. 清楚知道哪些外部资源可用、缺失或需要重新配置；
7. 在资源齐全时恢复原项目的类型、实例、标定和项目级业务配置。

## 4. 目标

1. 提供单数据集导出和单数据集包导入闭环。
2. 使用稳定的 OntoTwin 数据集包产品口径，不向用户暴露底层存储结构。
3. 导入前完成版本、内容、关系、冲突、资源和敏感信息预检。
4. 导入默认创建新数据集，不覆盖、不合并、不自动激活。
5. 为导入的数据集生成新的外层数据集 ID，并保留来源追踪信息。
6. 保留数据集内部类型 RID、实例 ID 及其关系。
7. 保留项目级业务配置，排除平台级规则、凭证和临时运行状态。
8. 复用现有 UE 主动绑定链路，不因导入而自动恢复或抢占 UE 绑定。
9. 导入必须全部成功或全部失败，不留下用户可见的半成品。
10. 在 JSON 与 PostgreSQL 部署中提供一致的产品结果。
11. UE 已绑定某数据集后，即使 Web 激活了其他数据集，UE 仍从其绑定数据集读取实例、Overlay、空间帧、分区、漫游、路线、解说资源和 Web 交互配置。

## 5. 非目标

- 不导出或导入底层数据库 dump、数据表或可手工编辑的原始项目文件。
- 不支持一次导出或导入多个数据集。
- 不支持覆盖已有数据集。
- 不支持将数据集包合并进已有数据集。
- 不在导入后自动激活数据集。
- 不在导入后自动恢复、迁移或抢占 UE 工程绑定。
- 不把 UE 源工程、模型二进制、媒体文件或其他外部资源直接装进数据集包。
- 不随数据集包迁移或修改平台级全局映射规则。
- 不在本版本建设用户权限系统、密码包或加密分发体系。
- 不提供数据集包内部字段的手工编辑、修复或局部导入工具。
- 不提供定时备份、云端同步或增量备份。
- 不允许 UE 向未激活的绑定项目写入配置或运行时编辑结果；本版本只补齐只读运行投影。

## 6. 数据集包内容边界

### 6.1 包含内容

| 内容 | 首版口径 |
|---|---|
| 数据集名称与来源信息 | 包含；导入时可修改目标名称 |
| 语义图谱节点、关系和分类 | 包含 |
| ObjectType 及其项目级接口配置 | 包含 |
| 构件、实例清单和实例 | 包含 |
| 实例当前持久化业务属性和空间状态 | 包含 |
| 坐标标定、空间剖面、空间帧和楼层信息 | 包含 |
| 分区及实例目录关系 | 包含 |
| 项目级 Overlay、场景交互、路线和 Web 交互配置 | 包含 |
| 类型资产绑定、容器 Blueprint、媒体和音频等引用 | 只包含引用和说明，不包含资源文件 |
| 来源 UE 工程身份 | 只作为来源说明，不形成有效绑定 |
| 产品版本、包格式版本和数据结构版本 | 包含 |

### 6.2 排除或重置内容

| 内容 | 首版口径 |
|---|---|
| 当前激活状态 | 不迁移；导入后保持未激活 |
| 当前有效 UE 绑定 | 不迁移；导入后保持未绑定 |
| 在线状态、心跳、最后连接时间和临时运行标记 | 排除或重置 |
| 平台级全局映射规则 | 排除；仅报告能力依赖 |
| 账号凭证、访问令牌和运行会话身份 | 排除 |
| 平台运行日志和回收站历史 | 排除 |
| UE 工程文件、模型、贴图、媒体和其他资源二进制 | 排除 |

项目级配置中的本地路径、内部 URL 和外部资源标识可以作为引用保留，但必须在导出提示和导入预检中明确展示其可移植性风险。

## 7. 数据集包产品契约

用户看到的是单个“OntoTwin 数据集包”，而不是内部文件集合。

数据集包至少携带以下可识别信息：

- 数据集名称；
- 来源数据集 ID；
- 导出时间；
- 来源 OntoTwin 产品版本；
- 数据集包格式版本；
- 数据结构版本；
- 类型、构件、实例、标定和配置数量摘要；
- 外部资源引用摘要；
- 来源 UE 工程说明；
- 已排除内容说明。

包内数据不可被用户手工修改后作为受支持的数据集包重新导入。无法通过完整性检查的包必须阻断。

## 8. 导出流程

### 8.1 入口

“我的数据集”中每个非内置数据集提供“导出数据集包”操作。用户可以导出任意单个数据集，不要求先激活该数据集。

内置 Demo 不作为普通业务数据集导出。

### 8.2 主流程

1. 用户在目标数据集行选择“导出数据集包”。
2. 系统显示导出摘要：名称、数据规模、包含内容、外部资源引用和敏感信息排除项。
3. 用户确认导出。
4. 系统生成数据集包并提供下载。
5. 导出完成后，原数据集、当前激活数据集和 UE 绑定均保持不变。

### 8.3 导出失败

- 失败不得修改源数据集。
- 页面显示明确原因，并允许用户重试。
- 若数据集自身存在关系断裂或不可迁移字段，导出应阻断并指出问题，不生成表面成功但无法导入的包。

## 9. 导入流程

### 9.1 入口布局

入口位于“语义图谱总览 → 我的数据集”底部：

```text
新建空数据集
导入数据集包
```

“导入数据集包”位于“新建空数据集”下方，不放入 CSV/图数据库的“加载数据”页签。

### 9.2 主流程

1. 用户选择一个 OntoTwin 数据集包。
2. 系统只进行读取和预检，不创建数据集。
3. 页面显示预检报告。
4. 系统为目标数据集生成新的外层 ID。
5. 系统提供可编辑的目标名称；如名称重复，默认追加“副本”或序号。
6. 用户确认导入。
7. 系统以完整事务创建一个新的数据集。
8. 新数据集保持未激活、未绑定。
9. 导入成功页提供“预览图谱”和“返回我的数据集”，不默认切换当前项目。

### 9.3 预检报告

预检至少展示：

- 包名称、来源、导出时间和版本；
- 目标环境兼容结论；
- 类型、构件、实例、关系、标定和项目配置数量；
- 包含内容与明确排除内容；
- 目标数据集名称及重名处理；
- 来源 ID 与导入后新 ID 的关系；
- 内部类型 RID、实例 ID 的保留策略；
- 来源 UE 工程信息及“导入后不会自动绑定”的说明；
- 外部资源引用、目标环境可用性和缺失项；
- 本地路径、内部 URL 等可移植性风险；
- 自动升级说明；
- 警告、阻断原因和建议处理方式。

### 9.4 阻断与警告

以下情况阻断导入：

- 数据集包无法识别或完整性校验失败；
- 包格式版本不受支持；
- 数据结构版本高于当前系统；
- 核心内容缺失；
- 包内存在重复内部 ID、关系断裂或无法建立自洽项目；
- 导入会要求覆盖或合并已有数据集。

以下情况允许带警告导入：

- 来源数据结构版本较旧但可以安全升级；
- 数据集名称与现有名称重复且已生成新名称；
- 外部模型、UE 资产、媒体或音频引用在目标环境不可用；
- 来源 UE 工程与当前可见 UE 工程不同；
- 包中存在本地路径或内部 URL；
- 某些非核心平台能力在目标环境尚未就绪。

资源缺失不得伪装成成功就绪，但不应阻止用户先完成数据备份迁移。

## 10. ID 与冲突策略

### 10.1 外层数据集身份

- 导入时始终生成新的数据集 ID。
- 来源数据集 ID 只作为来源追踪信息保存。
- 不允许使用来源 ID 覆盖本地已有数据集。

### 10.2 数据集名称

- 名称重复时不覆盖。
- 预检默认生成可区分名称，例如“原名称（副本）”或追加序号。
- 用户可在确认导入前修改名称。

### 10.3 内部业务身份

- ObjectType RID、实例 ID、构件和实例关系在新数据集内部原样保留。
- 新数据集形成独立命名空间，因此不因其他数据集中存在同名内部 ID 而冲突。
- 包内自身存在重复 ID 或引用断裂时阻断导入。

## 11. UE 工程绑定与换机迁移

### 11.1 绑定原则

- 导入包中的来源 UE 信息只用于说明和预检。
- 导入后不形成有效 UE 绑定。
- Web 不要求用户手填 UE 工程 ID。
- 绑定必须由目标 UE 工程主动发起，以目标工程实际身份作为事实。
- 同一个 UE 工程身份只能绑定一个数据集。
- 数据集导入流程不得静默强制迁移或抢占既有 UE 绑定。

### 11.2 用户链路

```text
数据集包导入成功
→ 数据集状态：未激活、未绑定
→ 用户在“我的数据集”手动激活
→ Web 提示“请在目标 UE 工程中完成绑定”
→ 用户打开目标 UE 源工程
→ 在 TwinSceneManager 中执行绑定
→ 后端检查 UE 工程身份是否已被占用
→ 绑定成功
→ UE 同步资产目录并核对数据集资源引用
→ 数据集进入就绪或资源缺失状态
```

### 11.3 绑定冲突

如果目标 UE 工程已经绑定其他数据集：

- 本次绑定必须阻断；
- UE 和 Web 均显示占用关系；
- 用户应先明确解绑原数据集，或使用另一套 UE 工程身份；
- 首版数据集导入流程不提供“强制抢占”。

### 11.4 绑定后的资源核对

绑定完成后至少区分：

- 资源完整，可以进入运行验收；
- 部分资源缺失，数据集可编辑但三维表现降级；
- 关键资源或工程能力不兼容，阻断运行就绪；
- 来源 UE 工程与目标工程不同，需要人工确认资产路径和场景引用。

### 11.5 绑定项目运行隔离

- UE 运行读取以 UE 工程绑定的数据集为准，不以前端当前激活数据集为准；
- Web 切换激活数据集不得改变已绑定 UE 的实例、Overlay、空间帧、分区、漫游、路线、解说资源或 Web 交互；
- Web 侧无 UE 身份的预览和配置编辑继续读取当前激活数据集；
- UE 写回仍要求其绑定数据集同时处于激活状态，避免后台项目被静默修改。

## 12. 状态与用户反馈

### 12.1 导入过程状态

| 状态 | 用户含义 |
|---|---|
| 等待选择 | 尚未选择数据集包 |
| 正在预检 | 只读取，不写入数据集 |
| 预检阻断 | 必须先解决问题，不能导入 |
| 可导入但有警告 | 用户了解影响后可以继续 |
| 正在导入 | 不允许重复提交或切换文件 |
| 导入成功 | 新数据集已创建，仍未激活、未绑定 |
| 导入失败 | 未留下可见半成品，可修复后重试 |

### 12.2 导入后的数据集状态

| 状态 | 用户下一步 |
|---|---|
| 未激活、未绑定 | 预览或手动激活 |
| 已激活、待绑定 | 打开目标 UE 工程并发起绑定 |
| 绑定冲突 | 处理原绑定关系 |
| 已绑定、资源待核对 | 等待或发起资源目录同步 |
| 已就绪 | 进入 UE 运行验收 |
| 资源缺失 | 修复引用或补齐外部资源 |

## 13. 版本兼容策略

数据集包格式版本与数据结构版本分别管理。

- 当前版本包可以导入。
- 系统已有安全迁移能力覆盖的旧数据结构可以导入，并在预检中说明升级结果。
- 高于当前系统的数据结构版本必须阻断，不能忽略未知字段后继续。
- 不提供向旧版本系统降级导出。
- 自动升级不得发起外部资源请求、自动绑定 UE 或自动启用旧项目中不存在的能力。

## 14. 安全与敏感信息

首版不建设新的权限系统，但导出和导入必须遵守以下边界：

- 不导出账号凭证、访问令牌和运行会话身份；
- 不导出平台日志、服务运行状态或回收站历史；
- 本地绝对路径、内部 URL 和外部服务标识必须在导出前提示；
- 数据集包可能包含业务类型、实例编号、空间位置和内部资源地址，应提示用户按项目资料管理；
- 导入不得执行包内携带的脚本、命令或外部请求；
- 预检报告不得静默隐藏被排除的敏感内容。

## 15. 失败恢复与幂等边界

### 15.1 导出

- 失败不修改源数据集。
- 重试只生成新的下载结果，不改变数据集状态。

### 15.2 导入

- 所有校验通过前不创建数据集。
- 创建过程中任一步失败都必须撤销本次写入。
- 失败后“我的数据集”中不得出现半成品。
- 同一个包重复导入时，每次都按新数据集处理，并生成新的外层 ID 和可区分名称。
- 重复点击确认不得生成同一次操作的多个副本。

### 15.3 激活和绑定

- 导入后的激活失败不删除已导入数据集，数据集保持未激活。
- UE 绑定失败不改变其他数据集的绑定关系。
- 资源检查失败不回滚数据导入或绑定，但必须将状态标记为未就绪或降级。

## 16. 验收标准

### 16.1 导出

- 可从“我的数据集”导出任意一个非内置数据集，无需先激活。
- 导出摘要正确显示包含内容、外部引用和排除内容。
- 导出操作不改变当前激活项目、源数据或 UE 绑定。
- 导出失败不产生源数据修改。

### 16.2 导入与数据守恒

- “导入数据集包”位于“我的数据集”底部、“新建空数据集”下方。
- 选择包后先显示预检，确认前不存在新数据集。
- 导入后生成新的外层数据集 ID，并记录来源 ID。
- 重名时生成可编辑的新名称，不覆盖原数据集。
- 内部类型 RID、实例 ID 及其引用关系保持一致。
- 类型、构件、实例清单、实例、标定、空间帧、分区和项目级配置数量与包内摘要一致。
- 实例持久化业务属性和空间状态得到恢复，在线状态和临时运行信息被清除或重置。
- 导入结果未激活、未绑定，当前项目保持不变。

### 16.3 冲突与兼容

- 覆盖或合并请求不可从首版入口发生。
- 可安全升级的旧版本包能够导入，并显示升级说明。
- 来自更高数据结构版本的包被阻断。
- 包损坏、核心关系断裂或内部 ID 重复时被阻断。
- 外部资源缺失时允许完成数据导入，但预检和导入后状态均明确提示。

### 16.4 UE 换机迁移主验收

准备：

- 来源电脑上的完整业务数据集；
- 对应 UE 源工程；
- 兼容版本的 OntoTwin 工具；
- 至少包含类型、实例、标定、UE 资产引用和项目级配置。

步骤与结果：

1. 来源电脑成功导出数据集包。
2. 将 UE 源工程、OntoTwin 工具和数据集包复制到目标电脑。
3. 目标电脑启动 OntoTwin 并导入数据集包。
4. 新数据集保持未激活、未绑定，不影响目标环境原有项目。
5. 用户手动激活导入数据集。
6. 用户打开目标 UE 工程，由 UE 发起绑定。
7. 无冲突时绑定成功；有冲突时明确阻断，不抢占其他项目。
8. UE 完成资源目录核对。
9. 资源齐全时，类型、实例数量、空间位置、项目配置和三维表现达到来源项目的业务等价结果。
10. 资源缺失时，数据仍可编辑，缺失项和降级结果可定位。
11. 绑定成功后，在 Web 端激活另一数据集；目标 UE 仍保持导入数据集的实例、Overlay、空间帧、分区、漫游、路线和 Web 交互，不串读当前激活数据集。
12. 对未激活的绑定数据集发起写回时仍明确阻断，且不影响只读运行。

该流程中用户不需要导入数据库 dump、手工修改数据集包或理解底层存储。

### 16.5 存储后端一致性

- JSON 部署导出的包可以导入 PostgreSQL 部署，反向亦然。
- 两种部署对预检、冲突、ID、激活、绑定和失败回滚给出相同的产品结果。
- 验收比较业务数据和关系守恒，不要求底层文件或数据表逐字节一致。

### 16.6 安全

- 包中不包含账号凭证、访问令牌或运行会话身份。
- 本地路径和内部 URL 在导出摘要与导入预检中可见。
- 数据集包无法触发脚本、命令或静默外部访问。

## 17. S2 小样品

正式扩量前，先用一个代表性数据集完成可否决的小样品：

- 至少包含 3 个 ObjectType、10 个实例、1 份有效标定、1 个分区和项目级 Overlay 配置；
- 至少包含一个 UE 资产引用和一个在目标环境中故意缺失的外部资源；
- 在来源环境导出，在空白目标环境导入；
- 验证新 ID、未激活、未绑定、内部 ID 保留和数量守恒；
- 激活后由目标 UE 工程发起绑定；
- 验证资源完整与资源缺失两种结果；
- 另外验证名称冲突、损坏包和高版本包三个失败样本；
- 小样品通过后再进入完整页面和存储后端覆盖。

## 18. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 用户把数据集包理解为仅有图谱 | 导出摘要和预检明确列出完整项目级内容 |
| 用户把数据集包理解为 UE 工程包 | 明确 UE 源工程与外部资源需单独提供 |
| 外部资源路径在新电脑失效 | 引用清单、预检、绑定后资源核对和降级状态 |
| 来源 UE 绑定污染目标环境 | 来源信息只读保留，导入后清空有效绑定 |
| UE 运行时仍读取前端激活项目 | 所有 UE 只读运行入口传递绑定项目身份，并增加切换激活数据集的隔离回归 |
| 新旧版本数据静默丢失 | 旧版本显式升级，新版本阻断，不忽略未知内容 |
| 导入半成品污染数据集列表 | 确认前不写入，导入全成功或全失败 |
| 同名或同 ID 覆盖现有项目 | 新外层 ID、重名改名、首版禁止覆盖和合并 |
| 包中携带敏感环境信息 | 排除凭证并提示路径、URL 和业务数据敏感性 |
| 数据包范围持续扩张 | 首版固定完整项目级数据和引用清单，不做自选导出 |

## 19. 实施约束与版本策略

- 本需求是数据集管理能力的子版本，不新开 4.x UE 运行时编号。
- 首版优先使用现有项目数据能力，不改变 ProjectStore 文件格式或全局映射规则。
- 前端采用“我的数据集”现有页面的低风险增量，不新增页面和路由。
- 导入/导出能力必须同时覆盖 JSON 与 PostgreSQL 部署。
- 数据集包内部契约、接口和测试记录放入独立技术文档，不在 PRD 中展开。
- UE 工程绑定继续由现有领域能力负责，数据集导入只增加引导和来源说明。
- 实施任务按后端数据包服务、前端数据集入口、UE 绑定联调和跨环境验收分别交接，每个具体任务只设一个主责角色。
