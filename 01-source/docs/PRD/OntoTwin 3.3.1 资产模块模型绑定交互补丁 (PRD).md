# OntoTwin 3.3.1 资产模块模型绑定交互补丁 (PRD)

> 版本：3.3.1
> 所属主线：OntoTwin Nexus
> 所属模块：本体配置中心 / 资产模块 / 三维模型绑定
> 父级需求：OntoTwin 3.3 运行时模型加载与 ArtStudio 资产同步
> 状态：待开发

---

## 1. 背景

当前本体配置中心里，三维资产绑定区域使用了“3D GLB 资产绑定”的说法，但实际资产来源已经不再只等于 `.glb` 文件：

- 手动绑定可能来自 ArtStudio、本地模型路径、UE `/Game/...` 资产引用。
- 历史 UE 迁移实例可能携带 `source_asset_path` 或 `render_config.ue_asset_path`。
- 未来资产模块需要兼容更多格式和更多来源，UI 不应把用户认知锁死在 GLB。

同时，当前页面无法清楚回答一个关键问题：

> 这个 ObjectType 现在到底绑定了哪个模型？如果没有类型级默认模型，历史迁移来的实例实际用了哪些模型？

这会导致产品验收和数据治理困难：用户看到了实例，但不知道它的模型来源，也无法把迁移来的模型沉淀成类型默认模型。

---

## 2. 目标

1. 去掉资产绑定标题中的 `GLB` 限定，改为通用的“模型绑定”表达。
2. 在本体配置中心里明确展示每个 ObjectType 的模型绑定状态。
3. 同时展示两类模型来源：
   - 正向手动绑定：类型级默认模型。
   - 反向迁移来源：历史迁移实例携带的实际模型。
4. 支持用户从历史迁移模型中选择一个，提升为该 ObjectType 的默认模型。
5. 保持页面轻量，不新增独立“迁移分类工作台”或复杂资产治理页面。

---

## 3. 非目标

- 不在本轮实现完整资产管理系统。
- 不在本轮实现模型格式转换。
- 不在本轮实现 ObjectType 的完整增删改查。
- 不把历史迁移分类能力放进主产品线。
- 不要求自动判断哪个迁移模型最正确，只提供可见性和手动确认入口。

---

## 4. 术语

| 名称 | 含义 |
|---|---|
| 类型默认模型 | ObjectType 上保存的默认模型绑定。后续 OntoTwin 正向铸造新实例时默认使用它。 |
| 历史实例模型 | UE 历史迁移实例自身携带的模型路径，来自 `source_asset_path` 或 `render_config.ue_asset_path`。 |
| 手动绑定 | 用户在本体配置中心主动为 ObjectType 选择或填写模型。 |
| 迁移来源 | 老 UE 项目迁移进 OntoTwin 时，由实例反向带入的模型信息。 |
| 提升为默认模型 | 把某个历史实例模型写入 ObjectType 的默认模型字段。 |

---

## 5. 交互规则

### 5.1 文案规则

原文案：

```text
3D GLB 资产绑定
```

改为：

```text
模型绑定
```

或：

```text
三维模型绑定
```

原副标题：

```text
依赖: I3D_Representable.asset_id
```

改为用户语义：

```text
用于 UE 预览与实例生成
```

UI 中避免直接暴露 `asset_id`、`ue_asset_path`、`ObjectType` 等技术字段，除非处于调试/详情折叠区。

### 5.2 模块显示规则

“模型绑定”模块只在当前类型具备三维表现能力后启用，即已挂载或待挂载：

```text
I3D_Representable
```

如果尚未具备三维表现能力，模块显示禁用态：

```text
请先启用三维表现能力，再配置模型。
```

### 5.3 模型来源规则

模型绑定模块需要区分两个层级：

1. 类型默认模型
   - 来源：ObjectType 的 `asset_id` / `ue_asset_path`。
   - 用途：后续正向铸造实例时默认使用。

2. 历史实例模型
   - 来源：当前 ObjectType 下实例的 `source_asset_path` / `render_config.ue_asset_path`。
   - 用途：展示迁移来的真实模型候选。
   - 可被用户手动提升为类型默认模型。

不能把“历史实例模型”直接等同于“类型默认模型”。两者必须在 UI 上分开呈现。

---

## 6. 信息架构

本体配置中心右侧建议保留三块纵向结构，但重命名并调整表达：

1. 基础信息
   - 展示类型名称、RID、分类、描述、业务属性。
   - 只读为主。

2. 三维能力
   - 原“能力接口挂载”。
   - 回答：这个类型是否能在三维场景里存在，以及具备哪些三维能力。

3. 模型绑定
   - 原“3D GLB 资产绑定”。
   - 回答：这个类型在三维场景里默认长什么样，以及历史实例实际用过哪些模型。

不建议把“模型绑定”合并进“三维能力”。原因：

- 三维能力是能力开关。
- 模型绑定是资产选择。
- 两者相关，但用户问题不同。

---

## 7. 模型绑定模块设计

### 7.1 顶部：当前默认模型

模块顶部固定展示“当前默认模型”区域。

有默认模型时显示：

```text
当前默认模型
来源：手动绑定 / ArtStudio / UE资产 / 本地模型
模型标识：/Game/... 或 artstudio:... 或 /static/models/...
使用范围：新铸造实例默认使用
```

无默认模型时显示：

```text
当前默认模型
未设置
新铸造实例将使用占位模型，或由实例自身模型覆盖。
```

### 7.2 中部：历史实例模型

展示当前 ObjectType 下迁移实例实际使用过的模型，按模型路径聚合。

示例：

```text
历史实例模型

/Game/WarehouseProps_Bundle/Models/SM_Pallet_Truck_01a...
使用 2 个实例
来源：UE历史迁移
[设为默认模型]

/Game/WarehouseProps_Bundle/Models/Skeletal/SKM_Reach_Truck_01a...
使用 1 个实例
来源：UE历史迁移
[设为默认模型]
```

如果没有历史实例模型：

```text
暂无迁移来源模型
```

### 7.3 底部：手动绑定

保留现有三种输入方式，但文案需要更中性：

1. 从资产库选择
2. 填写 UE 资产引用
3. 填写本地模型路径

不再在一级标题里强调 GLB。格式限制如仍存在，应放在具体输入方式的提示或校验错误中。

## 8. 数据规则

### 8.1 类型级默认模型

继续使用现有 ObjectType 字段，不新增复杂结构：

```jsonc
{
  "asset_id": "...",
  "ue_asset_path": "..."
}
```

语义调整为：

```text
该类型的默认模型绑定
```

### 8.2 实例级迁移模型

迁移实例继续使用已有字段：

```jsonc
{
  "source_asset_path": "/Game/...",
  "render_config": {
    "ue_asset_path": "/Game/..."
  }
}
```

用于聚合“历史实例模型”列表。

### 8.3 提升为默认模型

当用户点击“设为默认模型”时：

1. 将该历史实例模型路径写入 ObjectType 的默认模型绑定字段。
2. 不修改原实例的 `source_asset_path`。
3. 不改变其他历史实例的实际模型路径。
4. 后续正向铸造的新实例使用新的类型默认模型。

## 9. API 建议

### 9.1 类型详情接口补充

现有类型接口建议补充返回模型绑定摘要：

```jsonc
{
  "rid": "ri.obj.xxx",
  "name": "叉车",
  "asset_id": "...",
  "ue_asset_path": "...",
  "model_binding": {
    "default_model": {
      "source": "manual",
      "asset_id": "...",
      "ue_asset_path": "...",
      "label": "SM_Pallet_Truck_01a"
    },
    "migration_models": [
      {
        "source": "ue_migration",
        "path": "/Game/...",
        "instance_count": 2,
        "sample_instances": ["ue_xxx", "ue_yyy"]
      }
    ]
  }
}
```

### 9.2 提升默认模型接口

可复用现有资产绑定接口；如果语义不清晰，新增轻量接口：

```text
POST /api/v2/object-types/{rid}/model-binding/promote
```

请求：

```json
{
  "source_asset_path": "/Game/..."
}
```

结果：

```json
{
  "status": "ok",
  "rid": "ri.obj.xxx",
  "ue_asset_path": "/Game/..."
}
```

## 10. 页面状态

### 10.1 未启用三维能力

```text
请先启用三维表现能力，再配置模型。
```

### 10.2 已启用三维能力，但无默认模型

```text
当前默认模型：未设置
```

如果有历史实例模型，提示：

```text
可以从迁移来源模型中选择一个设为默认模型。
```

### 10.3 已有默认模型

展示默认模型标识、来源和更新时间。允许替换。

### 10.4 默认模型与历史实例模型不一致

这是允许状态，不视为错误。UI 应明确区分：

```text
默认模型影响新实例；历史实例仍保留迁移时的模型。
```

## 11. 验收标准

1. 本体配置中心不再出现“3D GLB 资产绑定”标题。
2. 新标题显示为“模型绑定”或“三维模型绑定”。
3. 已绑定类型默认模型时，用户能在当前类型详情中看到模型标识。
4. 未绑定类型默认模型时，用户能看到明确的“未设置”状态。
5. 对于历史迁移来的类型，页面能展示该类型下实例实际使用过的迁移模型路径。
6. 历史实例模型按路径聚合，并显示实例数量。
7. 用户可以从历史实例模型中选择一个，设为类型默认模型。
8. 设置默认模型后，ObjectType 的默认绑定字段更新。
9. 设置默认模型后，原历史实例的 `source_asset_path` 不被覆盖。
10. 后续正向铸造的新实例使用新的类型默认模型。
11. 未启用三维能力的类型，模型绑定模块显示禁用态，不允许绑定。
12. 页面不新增复杂迁移分类工作台。

---

## 12. UI 约束

- 风格延续 OntoTwin 极简黑白灰工具界面。
- 语义颜色仅用于小面积状态点或提示，不使用大面积彩色卡片。
- 不使用原生 `alert` / `confirm` / `prompt`。
- 不使用 emoji。
- 不在主 UI 文案里暴露技术实现字段，必要时放入“详情”折叠区域。
- 按钮文案使用用户动作：
  - `设为默认模型`
  - `替换模型`
  - `清除默认模型`
  - `从资产库选择`
