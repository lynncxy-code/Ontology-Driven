# OntoTwin 3.4.4 接管已有场景向导（PRD）

> 版本：v0.2；日期：2026-11-07。状态：五项核心决策已确认，按审计拆分里程碑，M1 进入独立估点前的产品确认，尚未进入开发。
> 归属：3.4 场景管理与历史迁移主线，续接 3.4.1～3.4.3；编号由总经理本轮确认。编号不代表目标部署版本，也不代表已合入 4.8。
> 本轮仅编写文档。未运行迁移、修改代码或存储、操作真实 UE 工程、部署任何环境。

## 1. 用户结果与现状

现场人员已经在 UE 关卡摆好设备或家具，希望保留其外观、位置和组合关系，让它们成为可以从 OntoTwin 查看、编辑并驱动变化的实例。用户不需要 AI、命令行或手工搬运 CSV/JSON，经过分类、层级核对和 UE 预览后，明确点击“确认接管”。

“动态实例”指数据管理和变化响应，不代表自动生成动画、蓝图业务逻辑、传感器接入或完整工业语义关系。模型资源目录同步回答“有哪些可用模型”；本向导回答“关卡里已经摆好的每件物体如何纳入管理”，两者不能共用扫描结果冒充完成。

现有源码具备按文件夹导出、复合静态资产描述、离线分类、迁移和临时预览审计能力，但不是完整向导。现有工具仍涉及全局激活、旧工程级绑定和按结果文件删除源物体；缺少跨端身份确认、面向普通用户的审核、可靠进度及恢复闭环。源码核验范围和证据见独立《现状核验与开发交接约束》，不代表现场插件已经包含这些能力。

历史 3.4.1 的“仅离线分类、不新增主产品分类界面”由本需求在场景接管范围内替代；保留历史文档。3.4.2 的自由实例、3.4.3 的空间分区继续复用，不为了接管而补造 CAD 构件。本期不照搬旧手册“先清除源物体，再拉取预览”的顺序。

## 2. 已确认决策、范围与非目标

2026-11-06，总经理集中确认以下五项：

| 项目 | 已确认决定 |
| --- | --- |
| 编号 | 3.4.4，接管已有场景向导 |
| 类型缺失 | 管理员或有项目编辑权的编辑者可创建仅本项目使用的类型；不自动写共享本体库 |
| 颗粒度 | 支持整体接管、按已有子 Actor 拆分，逐组确认；不拆网格、不自由拼装 |
| 源物体与恢复 | 原关卡保留停用源物体及接管前备份；恢复只处理本次范围，有后续修改先核对 |
| 重复接管 | 首版仅纳入新增对象；未变对象跳过，变化对象只报告，不覆盖，也不自动删除数据库实例 |

完整路线包含 UE 编辑器内的独立静态网格物体，以及通过已有附着关系形成的复合静态资产，并走通人工分类、命名、空间归属、身份确认、临时预览、接管和恢复。本次先把它拆成三个可独立验收的里程碑，避免 M1 直接承担跨端恢复和并发治理。

首版只接管白名单内的普通静态网格对象，不接管复杂蓝图、骨骼动画、粒子、灯光、音频、物理约束、实例化网格批组件及其他未通过引用安全检查的对象。不从网格猜工业业务类型，不复制或上传全部模型资源，不同步维护源 Actor 与实例的双向变化，不增加跨组织迁移能力。打包运行程序、未加载的关卡、World Partition 外部 Actor 和跨关卡附着结构不在首版接管范围内，扫描时解释原因并允许排除，不能静默漏项。

仅含静态外观也不等于蓝图可安全转换。涉及关卡蓝图、序列或其他对象依赖源 Actor 的引用，若不能证明替换后仍正确，应列为阻断项。排除对象继续保留原有行为和显示。

### 2.1 里程碑和首批交付边界

| 里程碑 | 用户可完成的事情 | 数据和 UE 影响 | 本轮定位 |
| --- | --- | --- | --- |
| M1 草稿方案 | UE 扫描范围，网页分类、命名、编号、空间归属，生成可回读的接管方案 | 不创建正式实例，不修改绑定，不停用或保存源 Actor；只保存接管任务草稿 | 下一批独立开发与验收目标 |
| M2 预览接管 | 在原 UE 生成临时预览，核对后一次性接管静态对象 | 备份、写入新实例、回读核验、停用源 Actor并保存关卡 | M1通过后再立项 |
| M3 恢复和并发 | 从接管记录发起恢复，处理后续修改、断线、并发和故障注入 | 数据库停用本批实例可可靠执行，UE源物体恢复需要人工核对 | 发布前治理项 |

M1 的完成标准是“接管方案可复核”，不是“UE已经出现动态实例”。M1 允许任务草稿持久化，草稿必须与正式项目数据分开，不能通过激活项目、旧迁移脚本或共享本体补丁产生副作用。

### 2.2 产品技术契约

- 实例最小管理单元是 UE Actor。Actor 内的 `StaticMeshComponent` 只作为该实例的渲染部件，不能单独成为实例，也不能跨实例复用。按已有子 Actor 拆分时，每个子 Actor是候选实例，父 Actor自有的静态网格仍归父实例；无法分配就阻断。
- 源身份键为“环境、UE工程身份、关卡身份、源 Actor Guid”。同一 Guid 的变换或外观变化归为“变更”，新 Guid归为“新增”，删除旧 Actor再重新摆放产生“删除加新增”，不猜测成变更。M1 页面分开显示新增、未变化、变更和源已消失四类。
- 已有 `source=ue_migrated` 但只有裸 ActorGuid 的历史实例不能直接套用上述四类。首次扫描命中这类记录时显示“历史接管待核对”，由用户确认复用、排除或保留为独立对象；未核对项不能进入 M2。
- 接管对象必须能通过稳定的 UE 包资产路径在运行时 `LoadObject`。无法提供稳定路径的原地资源、临时资源或依赖未交付外部文件的对象在 M2 阻断。模型资源目录同步只提供资产发现和选择，不替代资源可加载性验证。
- 当前场景绑定契约是一个项目只有一个有效场景绑定，一个 UE 工程加场景只能有一个有效项目绑定。M1 只读取并核对绑定，未绑定或冲突时停止在目标确认，不自动换绑。
- 项目编辑权限依赖 4.8 现有校验。管理员可以编辑，普通编辑者必须同时是组织编辑者、目标工厂成员并持有该项目的 `edit` 授权。M1、M2、M3 的每个写入口都重新检查该权限。
- M1/M2 只放行“普通 Actor 根节点＋SceneComponent 附着关系＋StaticMeshComponent 静态网格渲染”的对象。出现其他组件类型、蓝图行为或序列依赖时，默认整件阻断；只有拆出后剩余单元完全满足白名单，才允许局部纳入。蓝图、关卡蓝图和序列引用另做独立安全检查，无法证明替换后引用仍正确时阻断。

### 2.3 开发前阻断条件

以下问题未形成技术契约和隔离样品证据前，M1 可以做无副作用草稿，但不得进入 M2 正式预览或接管：

1. **运行路由与业务空间必须分离。** `zone_id` 不能同时承担 UE 地图/场景路由和房间、楼层等业务空间归属。M1 可以收集业务空间草稿，但 M2 必须确认独立的运行场景键与业务空间键，或由现有绑定关系稳定推导运行场景键。若仍只能写一个 `zone_id`，则空间归属只能保留在草稿，不能完成正式接管。
2. **旧迁移实例必须先建立基线。** 对已有 `source=ue_migrated`、只有裸 ActorGuid 的实例，首次扫描不得直接归为“新增”。系统要显示“历史接管待核对”，由用户确认复用、排除或保留为独立对象；未核对项不能进入 M2。
3. **附着树数据必须支持拆分。** 若 UE 只提供根 Actor 汇总、没有每个子 Actor 的 Guid、父子关系、相对变换和子树签名，则该批只能选择整体接管，不能在页面显示可执行的“按子 Actor 拆分”。要支持拆分，先升级扫描契约并通过静态复现样品验收。
4. **工程和关卡身份必须可核验。** 工程名、工程路径和地图路径只能作为展示信息，不能作为唯一身份。M2 需要稳定的工程身份、关卡身份和一次性连接凭据；身份无法核验时停止，不因同名或路径相同而自动接管。
5. **接管后的可见性、光照、编辑和性能必须有实测基线。** 需要证明源物体停用后不会造成重复显示、空场景、烘焙阴影异常、编辑器无法继续定位或明显加载退化。没有基线时只能完成 M1 草稿，不能承诺 M2 接管。

## 3. 入口与主流程

UE 的 OntoTwin 工具菜单新增“接管已有场景”，与“插件版本与更新”“导出交付工程”并列。网页在当前项目“实例运维与监控”的现有标题操作区提供“场景接管记录”，不新增整套主导航。记录页可续办、查看结果或发起恢复；没有 UE 在线时不提供虚假的可执行接管按钮。

```text
UE 菜单：接管已有场景
  M1 → ① UE 扫描范围 → ② 网页分类、归属和编号 → ③ 生成接管方案
  M2 → 读取 M1 方案 → 网页发起预览 → UE 核对 → UE 确认接管
  M3 → 网页打开接管记录 → 网页核对恢复条件 → UE 确认恢复
```

M1 使用三个点状步骤，M2 在同一任务上增加预览和确认，M3 从接管记录进入恢复。每个里程碑只有自己的主操作。修改 M1 草稿不触发 UE 场景变化。M2 的“确认接管”和 M3 的“确认恢复”都只能在原 UE 完成，网页只提交请求并显示轮询状态。

### 3.1 跨端关联与身份

- UE 展示实际工程路径、关卡、后端地址，点击继续后打开该后端的审核页面。后端与网页必须核对同一环境身份，不能仅凭端口或名称判断。
- 未登录时先登录，完成后回到同一任务；账号不足以编辑目标项目时提示申请授权，不自动改用其他组织、数据集或管理员身份。
- 页面和 UE 显示同一短任务号，完整任务身份由系统管理。登录授权绑定发起的 UE 会话、工程、关卡与目标项目，链接本身不是授权凭证，不在地址栏携带长期密码或令牌。
- 浏览器多标签页各持有自己的任务上下文；切换日常工作项目不改变已创建接管任务。UE 换关卡、换后端、工程身份变化或项目绑定变化时暂停，重新核验，不自动跟随。
- 首次关联凭据建议 10 分钟有效；过期只需在原 UE 重新打开审核入口，已保存草稿保留。关闭网页、刷新或重新登录均从任务记录续办。重新连接 UE 必须核验原工程、关卡和任务，不能接到另一个同名工程。
- 跨端通信沿用 Flask 轮询，不假设 WebSocket 或异步队列。网页提交“预览请求”“确认请求”或“恢复请求”后，UE 每 2 秒读取一次任务状态，执行阶段和结果写回任务记录。页面等待超过 30 秒显示“等待 UE”，不创建新任务；UE 断线后可从任务记录继续核验。M1 只有网页写草稿，不需要等待 UE 执行。
- 首版一次任务只处理一个已保存、已加载的源关卡。选中多个关卡物体时按关卡列出数量，请用户选择本轮关卡，其他项可另开任务。

### 3.2 目标数据集与绑定

优先显示已核验的当前工程、关卡绑定目标。未绑定时只列出用户在该组织、工厂有编辑权的数据集；可经现有“我的数据集”流程创建空数据集后返回，不因打开向导而创建数据。

未绑定须显式完成绑定确认后才能进入正式审核。已有绑定冲突须去现有绑定流程处理，展示旧目标、新目标和影响范围；本向导不强制换绑。选择其他数据集使当前审核失效，必须重新确认范围和预览。绑定动作有独立记录，不与“扫描”“接管完成”混为一谈；取消或恢复接管不暗中撤销用户此前确认的绑定。

已有契约是一个项目只有一个有效场景绑定，一个 UE 工程加场景只能有一个有效项目绑定。出现冲突时显示旧目标、新目标和影响范围，用户回到现有绑定流程处理。本向导不自动换绑，不把同一个数据集绑定多个场景作为本轮能力。关卡身份与空间分区身份分别确认，不将楼层名称、分区或大纲路径当成关卡绑定键。

## 4. 页面字段与操作

### 4.1 第一步：选择范围

M1 首版只开放“指定大纲文件夹”，显示根物体数、附着后代数、渲染部件数、预计实例数及异常数。文件夹扫描是否包含子目录由明确勾选控制，默认包含。包含附着后代是独立规则，若后代在所选文件夹外，必须单列并让用户确认纳入；不能隐式扩展范围。界面必须明确标注当前扫描范围来自 UE 大纲文件夹。当前源码的导出函数实际按 `MigrationFolderName` 扫描，M1 不提供“当前选中物体”入口；后续若补做该入口，必须先完成稳定 Actor 身份传递和独立验收。

父子同时选中只计一次。单独选择附着子物体时，不自动拉入祖先；展示其依赖，不能安全独立处理的要求改选完整对象。空范围不进入下一步。扫描不建立正式实例、不激活项目、不改源物体的持久状态。

先保存源关卡的现有修改，再建立可重现扫描基线；用户取消保存则停留。未命名关卡先通过 UE 正常保存流程命名。只读关卡可以查看阻断原因，不能继续接管。

### 4.2 第二步：分类与颗粒度

| 字段/操作 | 表现与规则 |
| --- | --- |
| 建议分组 | 同模型和附着结构用于减少重复填写，不是业务类型结论；不凭同文件夹、同名或单个签名自动合并 |
| 组名称与样本 | 显示数量、样本名称、可定位 UE 中的对象；展开查看全部成员与部件 |
| 实例颗粒度 | 整体 / 按已有子物体拆分；展示操作前后实例数和部件归属，用户逐组确认 |
| 类型 | 搜索当前项目已有类型；缺失可填写中文名称创建项目类型草稿，仅具基本显示和空间能力 |
| 名称 | 批量填写名称或名称前缀；每件实例可覆盖，中文可用，不改变技术身份 |
| 处理方式 | 纳入 / 排除；“未分类”为待办状态，首版不能带着未分类正式接管 |
| 风险与原因 | 缺资源、不支持行为、源身份冲突、已有接管等分别列出；点击可定位具体对象 |
| 批量应用 | 先勾选，再应用类型、名称或排除；默认仅当前选中项，跨页需明确选择全部筛选结果并展示数量 |

“按已有子物体拆分”只在既有 Actor 边界上选择独立管理单元，不能把一个网格切成两件，也不能任意跨父级拼装。实例最小单元是 Actor，Actor 内每个 `StaticMeshComponent` 只作为渲染部件。每个源 Actor 和渲染部件只能归属于一个待接管实例。母体自有静态网格归母实例，附着子 Actor按用户选择归入整体或拆分为子实例；没有明确归属就阻断。组织容器无几何且拆分后为空时，保留源容器，不凭目录名生成设备实例。

一个复合实例包含不支持组件时，默认整件阻断；只有用户明确拆分出可独立处理的静态子物体、且剩余对象引用安全时，才允许局部纳入。排除后预览和汇总必须重新计算。

“类型”与“模型”分开：同一类型可对应多个实例外观，选择既有类型不改其默认模型，不影响其他实例；接管保留每件物体本轮确认的外观。新类型暂存于接管草稿，确认接管才写入本项目，不创建跨项目共享标准。

### 4.3 第三步：空间归属与身份

空间归属复用项目现有楼栋、楼层、房间、区域目录。集团与工厂是权限和项目归属上下文，不再重复创建为设备类型；不为本向导增加另一套空间树。用户选已有有效叶子分区，或按权限建立分区草稿；也可明确选择“暂不指定空间分区”。缺少上级时引导先补上级，不隐式生成目录。

原 UE 文件夹保留为来源信息，可建议填入实例展示目录，但不能据此自动建立楼层、赋予标定关系或计算高度。展示目录、空间归属、类型分列；导入后文件夹不持续反向改写数据库。

实例业务编号沿用现有 3.0 实例身份证号目录和自动编号接口，不另建一套接管专用编号。用户可以逐项填写或按现有规则批量生成，例如 CHAIR-001。预览生成结果并检查当前数据集、回收站保留项及本任务内重复编号；改规则重新生成必须显式确认，不覆盖手填值。M1 只做重复检查和方案内预留，不建立跨任务锁。M2 确认写入时再次调用现有编号唯一性校验，冲突返回具体对象，不覆盖已有实例。技术身份由“环境、工程、关卡、源 Actor Guid”组成的来源映射产生，改名不改变身份。业务编号不作为源对象去重依据。删除重摆记录为“源已消失＋新增”，不会猜测为变更。

### 4.4 M2：预览检查

网页点击“在 UE 中预览”，Flask 将任务状态置为“等待 UE 预览”。原 UE 每 2 秒轮询任务，读取后生成临时对象并回写预览审计。页面显示已处理数量、成功数量、阻断项，UE 提供“原场景 / 接管预览”切换，沿用同一视角。源物体仅被临时视图遮罩隐藏，不能保存隐藏状态；退出、取消或异常退出后的再次打开应恢复原状态。临时对象不进入正式关卡文件，不参加正式运行快照，也不能利用现有编辑回写入口修改正式实例。

必须比较实例数量、部件覆盖、世界位置、旋转、缩放、材质槽与材质引用、碰撞模式、可见性和组合结构。负缩放不直接判错，应验证镜像效果；无法无损描述的变换或材质状态列为阻断。缺模型不允许用占位盒通过。复合对象需同时验证整体和部件，不能只比较包围盒。

自动检查通过后，用户在 UE 勾选“已检查原场景与接管预览”，才可进入确认。任何源物体、相关资源、分类、颗粒度、目标绑定或相关项目数据变化使该次预览失效。系统保存预览对应的版本。变换字段在同一工程和构建下逐项比较 UE 序列化值，视觉核对作为第二条件。不同构建之间若需要容差，必须由技术方案通过实测确定，不在 PRD 预设 0.1cm、0.1°或缩放阈值。

### 4.5 M2：确认接管与完成

原 UE 显示最终摘要：目标环境、组织/工厂/数据集、工程/关卡、纳入对象和新增实例数、新增类型/分区数、跳过与排除数量及原因、空间与编号结果、备份位置和源物体停用规则。首版“更新既有实例”始终为零。用户点一次“确认接管”，此后按钮变为进度，不再次提交。

按真实阶段显示：准备备份 → 写入待切换数据 → 回读校验 → 停用源物体并保存关卡 → 切换实例并验证 → 完成。数据库写入成功不代表接管成功；关卡未保存或 UE 未确认时不得显示完成。

成功后 UE 当前视图只显示接管结果，原物体进入“接管归档”，保留原位置、附着和身份恢复依据，停止显示、碰撞及运行参与。归档放置方式先以隔离样品验证为准。优先评估独立的非运行归档子关卡，只有确认 Actor 身份和烘焙光照行为稳定后才可采用；否则留在原关卡的归档目录中并显式停用。临时预览仍不固化入关卡；重新打开编辑器可通过正常实例预览查看，启动运行时从数据库加载。完成页提供“查看实例”和“接管记录”。恢复入口属于 M3，归档不自动清理。

## 5. 状态、失败恢复和并发

全流程使用一张状态表。M1 只使用“草稿、待预览、已取消”中的前两态；M2 增加“待确认、执行中、已完成”；M3 复用“待核验/恢复”处理断线、结果不明和 UE 源物体人工核对。页面显示阶段和原因，不再为每个里程碑建立互相矛盾的状态名称。

| 状态 | 可进行的操作与离开条件 |
| --- | --- |
| 草稿 | 保存分类、空间草稿、编号草稿，返回步骤或取消；无正式业务写入 |
| 待预览 | M1 方案已确认，等待 M2 发起预览；范围或绑定变化时退回草稿 |
| 待确认 | 预览通过且用户已核对；复核目标与权限后确认接管 |
| 执行中 | 显示真实阶段和数量；开始写入后不能用关闭页面冒充取消 |
| 已完成 | 数据和 UE 切换均已验证，关卡保存确认；可查看结果或发起 M3 恢复 |
| 待核验/恢复 | 任一阶段结果不明确、跨端失联或源物体存在后续修改；显示已完成和未完成阶段，允许续办或人工核对 |
| 已取消 | 写入前撤销任务；清理临时预览并恢复视图，保留必要审计记录 |

**M2 执行保障。** 确认后短时锁定目标项目的相关编辑写入和源关卡变更，明确显示原因，读操作与其他项目仍可使用。尚未确认的网页草稿不冻结项目。按任务和确认版本识别重复点击，网络重试不能产生第二批实例。跨用户并发锁、故障注入和复杂补偿属于 M3，M2 先完成单任务、单操作者的幂等闭环。

**备份。** 必须包含本批源对象完整状态、原关卡恢复副本、数据库变更前依据和对象映射；记录校验结果与可访问位置。备份空间不足、失败、不可读或源关卡无法保存均阻止后续写入。模型资产仍引用现有资源，备份不能被描述为整个 UE 工程的完整交付包；相关资源后续变化时，恢复须重新验证。

**跨端失败。** 数据库与 UE 关卡不是一个事务。待切换数据不对常规运行消费者生效；源物体必须在数据回读和预览已通过后才停用。M2 只要求当前 UE 会话和网页任务可回读，发生异常时进入“待核验/恢复”，保留源物体和批次依据。其他消费者隔离、跨用户并发锁、故障注入及复杂补偿在 M3 验证。若 M2 无法保证临时阶段不出现双份或空场景，停止开发，不以最终一致掩盖画面错误。

| 失败位置 | 产品要求 |
| --- | --- |
| 备份前或备份失败 | 保持正式数据和源物体不变，保留审核输入，可重试 |
| 数据写入或回读失败 | 撤销本批待切换写入，源物体不动；补偿失败进入“待核验/恢复”并保留锁定范围 |
| 源物体停用、关卡保存失败 | 不开放新实例；按本批恢复原物体与数据，验证后才解除限制 |
| UE 已保存，但后端确认响应丢失 | 显示待核验；读取任务状态和双方凭据，禁止盲目重写或再次隐藏 |
| 数据已生效但 UE 回执丢失 | 同一任务核验实际场景与保存结果，不能把超时直接当失败回滚 |
| 浏览器关闭 / UE 断线 / 后端重启 | 保留阶段记录，重连展示真实阶段；不会自动删除源物体或换目标 |

自动补偿只处理能证明属于本批、且未被后来修改的数据。数据库层可以可靠停用本批新实例。UE 层重新启用归档源物体依赖关卡文件状态，系统只能先比较任务基线和当前状态，无法证明关卡没有其他修改时转入“待核验/恢复”，并在原因中显示“UE 源物体待人工核对”。状态不明时保留证据和相关锁，提示管理员从任务记录处理，不能无限重试或自动解锁让未核验对象流入正式运行。

**用户主动恢复。** M3 从记录点“恢复本次接管”，先展示将恢复的源对象、将停用的新实例、新建类型/分区引用情况及后续变化。操作者仍须有项目编辑权且能连接原 UE 关卡。先停止本批新实例参与运行，再尝试恢复原物体的可见性、碰撞、附着和文件夹并保存。数据库停用成功且 UE 源物体也完成人工核对后，任务回到“已完成”，结果栏显示“数据已恢复，UE 源物体已核验”。关卡存在后续修改、引用冲突或保存结果不明确时，保持“待核验/恢复”，显示“数据已恢复，UE 源物体待人工核对”，不提供强制覆盖。任一步失败都保持该状态，防止两份同时参与运行。

若本批实例已被编辑、引用、接管类型被其他实例使用或源对象/资源有变化，列出冲突，首版不提供强制覆盖，允许返回保留现状；由常规编辑处理依赖后再核验。不得整库回滚覆盖其他人的工作，不自动删共享类型、分区或改绑定，不开放永久删除源归档的功能。

## 6. 记录、权限和交互约束

记录列表显示任务号、源工程/关卡、目标数据集、创建人、时间、纳入/排除数量、阶段和操作；默认当前项目，按权限可查。详情保留每步选择、原始基线、预览报告、备份状态、源对象与实例映射、执行及恢复记录。记录权限与目标项目一致，不泄露无权项目名称或资源路径。

管理员和有目标项目编辑权的编辑者可分类、建项目类型/空间分区、预览、确认和恢复；仅有组织编辑者角色不等于有项目编辑权。查看者仅能查看有权项目记录。预览、确认、续办、恢复均重新检查权限；权限撤回后停止新的用户写入，系统只可执行已经授权批次的安全核验或补偿，不借此执行新的接管。

界面复用现有黑白灰表格、搜索选择和确认弹窗，保持原侧栏、图标和头像。内容区可滚动，步骤条和底部操作区不遮挡内容，长清单支持筛选分页；单个主操作，无原生 prompt/alert、无多层嵌套弹窗。字段错误就地提示，批量动作先显示作用数量。用户可见的是“类型、业务编号、空间归属、源物体”，技术标识和路径放在可展开核对区；环境与目标核对信息不作为可删除的小字说明隐藏。

## 7. 可否决小样品与验收

开发前的小样品用隔离测试工程：十把同模型椅子、一个含三个静态部件的设备、一个复杂蓝图。预期椅子拆成十实例、设备为一实例、蓝图排除保留；共十一实例，不因同文件夹而合并。样品必须展示以下五屏及前后状态，未经产品确认不扩展到客户场景。

```text
接管已有场景          环境 / 工厂 / 数据集          任务号
● 范围 ─ ● 分类 ─ ○ 归属 ─ ○ 预览 ─ ○ 接管
组             数量     颗粒度        类型       处理
椅子组         10       每把独立      办公椅     纳入
设备           1        整体(3部件)   检测设备   纳入
复杂蓝图       1        不支持        —          排除
                              [保存并退出] [下一步]

UE 预览：[原场景] [接管预览]   数量11 / 缺资源0
最终摘要：新增11，更新0，排除1；源物体停用归档
                              [返回核对] [确认接管]
```

| 案例 | 可操作步骤 | 通过标准 |
| --- | --- | --- |
| M1 静态单体与整体 | 扫描以上样品，人工确认类型/颗粒度/编号，保存并重新打开方案 | 在扫描回传完整子 Actor 数据时，10 把椅子和1台设备形成11个候选实例、13个渲染部件；排除蓝图继续运行；无正式实例和绑定变化。缺少子 Actor 数据时，拆分选项必须禁用并阻止进入 M2 |
| M2 静态单体与整体 | 在M1方案上生成预览，人工核对后接管 | 只有通过子 Actor 数据契约和路由映射门槛后，才验收11个新实例、13个渲染部件；排除蓝图继续运行；无占位替代、无重复显示或碰撞 |
| 新项目类型 | 无合适类型时在向导填中文名称，取消一次，再重新完成 | 取消不新增正式类型；完成仅当前项目新增，不改其他项目和共享本体库 |
| 范围边界 | 父子同时选中、目录外附着后代、多关卡选择分别扫描 | 无重复计入；范围扩展须明确确认；首版按一个关卡处理，未选源不动 |
| 空间与编号 | 同类型对象指定两个已有分区，再试重复业务编号 | 类型不因此分裂；重复编号阻断；来源文件夹不生成标定、楼层或新分区 |
| 运行路由与业务空间 | 给实例选择房间/楼层，再从对应 UE 场景拉取 | 业务空间变化不改变 UE 场景路由；路由和业务空间能分别回读；无法分离时阻止 M2 |
| 历史迁移基线 | 扫描已有裸 ActorGuid 的旧实例 | 显示“历史接管待核对”；未确认前不归为新增、不生成重复实例 |
| 附着树数据契约 | 用含多个子 Actor 的设备扫描并选择整体/拆分 | 每个子 Actor 的 Guid、父子关系、相对变换和子树签名可回读；缺字段时拆分入口禁用 |
| 工程与关卡身份 | 复制同名工程、改名地图后重新连接 | 身份变化被阻断或要求重新核验；不因名称或路径相同自动接管 |
| 接管影响基线 | 接管前后比较阴影、编辑定位、加载时间和帧时间 | 无重复显示、空场景或不可编辑区域；性能和光照差异有实测记录，超过门槛阻断发布 |
| 预览无副作用 | 记录正式实例、绑定、全局激活与关卡状态；预览、取消、重开 | 正式业务数据及持久源状态不变，临时对象不落盘；允许新增接管草稿记录 |
| M2 视觉一致 | 加入材质覆盖、负缩放和非均匀缩放，比较原场景与预览 | 同一工程和构建下变换序列化值逐项相等，数量、结构、材质槽及资源引用一致；镜像保留；无法加载的资产阻断。跨构建容差由技术方案实测确定 |
| 重复扫描 | 完成后重复扫描归档，另加两把椅子，再改变旧对象 | 不变项跳过；新增仅2；变更明确列出并排除出本轮，未经处理不能隐式覆盖或删除 |
| M1 项目隔离 | 两标签页、同名不同工程/关卡、两个数据集并行保存草稿 | 每笔草稿留在任务明确目标；缺上下文拒绝；不会改变另一个标签页、正式数据或绑定 |
| M2 项目隔离 | 在已确认方案上执行预览和接管 | 每笔写入留在任务明确目标；缺上下文拒绝；不会改变另一个标签页或其他绑定 |
| 权限 | 查看者、无项目编辑权的组织编辑者、授权编辑者分别操作 | 前两者直连接口也不能写；授权编辑者可完成当前里程碑；执行前撤权阻断 |
| M2 陈旧预览 | 预览后移动源对象或修改目标相关数据，再确认；双击确认 | 要求重新预览；同一确认版本仅执行一次，无新增重复实例 |
| M3 并发 | 两个编辑者同时确认或恢复同一任务 | 由并发锁和故障注入方案验证，不作为M1和M2的前置交付 |
| 中断恢复 | M2 注入一次 UE 断线或网页刷新；M3 再覆盖各阶段故障 | M2 记录真实阶段，未完成不冒充成功，续办不重复；M3 再验恢复和补偿 |
| 主动恢复 | 成功后停用本批实例；再测试 UE 关卡已有后续修改的情况 | 数据库停用可回读；UE 恢复在无冲突时由人工确认，有冲突进入待核对，不覆盖后来工作 |
| 冷启动 | 完成后关闭重开 UE 和后端，再进入该关卡运行 | 仍准确加载该批实例；归档源仍停用；预览没有永久固化，映射与记录可查 |
| 长清单可操作 | M1 使用代表性清单，M2 再增加大批量样品 | 页面可滚动到操作区；统计真实、进度持续可读；扫描/草稿可取消，无永久改动。500单体和2000部件容量测试移到发布前门禁 |

上述误差和容量为本稿拟定验收基线，不是现有能力实测结论。画面检查与数值检查都要通过；HTTP 200、脚本输出成功或数据库有记录均不能替代 UE 实物验收。

## 8. 版本、风险与交接

3.4.4 是场景接管能力主线编号，4.8 是当前多租户、项目权限和场景绑定的部署版本。3.4.4 M1 依赖 4.8 的显式项目上下文、项目编辑权限和场景级绑定接口，不能把3.4.4编号理解成另一个部署环境。文档版本与软件版本分开管理。已保存任务包含当时的插件、后端能力版本及审核版本；组件不兼容时停在能力检查，提示从既有更新入口处理，不继续半套接管。更新中不得丢弃未完成任务，旧任务至少可查看和进入明确恢复处理。

主要风险为：附着结构误判物理对象、关卡绑定与分区混用、源物体仍有外部引用、双端提交中断、归档占用增加以及旧脚本绕过项目权限。对策分别落在人工颗粒度确认、显式身份、依赖阻断、阶段记录/补偿、保留范围提示和开发门禁，不用“迁移无损”笼统承诺。
