## 1 目标与范围

现场操作者按 F10 进入编辑模式后，可以：

- 在编辑面板旁展开模型库，并排浏览当前工程的所有可用模型，单击后看清外形；
- 把模型直接拖进场景，或点「放置」后在场景里点选位置；
- 放下时决定它只是**场景陈设**，还是带业务编号的**实例**；
- 放错了可以删除，也可以用 Ctrl+Z 撤销。

工程维护者在 UE 编辑器里指定一个或几个文件夹作为模型库，打包时不会漏掉。

| 本期包含 | 本期不包含（另行登记） |
| --- | --- |
| 工程模型、本地 Models 的缩略图网格、搜索、单击大预览 | 模型分类 |
| 编辑器中的模型库设置、缩略图生成、打包检查 | Art Studio 真实目录（保留空状态页） |
| 拖入放置、按钮放置、放置信息小框 | 已有实例换模型、修改类型默认模型、恢复类型继承 |
| 场景陈设与实例两种身份、场景陈设命名、事后补填或修改编号 | 同名 GLB 覆盖后重载已摆实例 |
| F10 删除、撤销与重做放置 | 场景陈设“先摆后并入已有实例” |
| 网页实例列表中的「场景陈设」分组与业务入口限制 | 三轴旋转拖环、复制、完整旋转缩放入口 |

## 3 工程维护者：确定模型库

### 3.1 选择文件夹与更新

在 UE「项目设置 → OntoTwin → 模型库」中选择一个或多个 `/Game/...` 文件夹，点击「更新模型库」。插件依次完成：

1. 把这些文件夹加入打包列表（Cook 目录）；
2. 按 3.2 的规则找出可选模型；
3. 为每个模型渲染一张缩略图；
4. 生成随包的模型库清单，内容包括模型标识、显示名、资源类型和缩略图；
5. 列出本次的新增、删除、改名或移动、缺少显示名的模型。

资产目录组件上已有的「配置扫描目录用于打包」保持原用途，与模型库设置互不替代。

### 3.2 哪些算可选模型

- 文件夹及其子文件夹中的静态网格、骨骼网格和允许放置的 Actor 蓝图，全部列为可选模型。
- 被同一模型库中蓝图使用的零件网格，不单列。
- 材质、贴图等依赖不单列。关卡从其他路径引用的环境资产也不进入模型库。
- 不希望操作者看到的资产（如贴花、天花板构件），由维护者移出模型库文件夹，不另设排除名单。
- 模型库收录本工程全部模型，与当前打开的是哪个关卡无关。

### 3.3 显示名

- 默认显示名由资产名自动生成：去掉 `SM_`、`SK_`、`BP_` 等常见前缀，下划线换成空格。例如 `SM_Air_Duct_01_1m` 显示为 `Air Duct 01 1m`。
- 维护者可在模型库设置中为任意模型填写显示名，填写后以它为准。
- 资产改名或移动后，原显示名失效，回到自动名，「更新模型库」时列出这些模型。
- 标准模板预先填好「货架」「托盘」「机械臂」。

### 3.4 提醒与打包检查

- 编辑器打开时，如果尚未选择文件夹，或文件夹中的模型在上次更新后有增删改，就提示更新。
- 打包时检查清单：清单缺失或过期，则中止打包，并在日志中写明是哪个文件夹的哪些模型。
- 没有选择任何模型库文件夹时，只警告不中止，成品的「工程模型」显示空状态。

说明：UE 打包时的 Cook 在后台进程运行，不能弹窗，也不能渲染画面。所以缩略图只能在「更新模型库」时生成，打包时只做检查。

## 4 操作者：浏览与预览

### 4.1 布局

```
┌ 编辑面板（原有） ┐  ┌ 独立预览（选中后出现） ┐  ┌ 模型库 ───── [收起] ┐
│ 选中对象及属性    │  │                      │  │ 工程 / 本地 / Art   │
│ 位置与编辑操作    │  │  纯黑背景、模型旋转    │  │ [搜索………………]     │
│ [模型库]         │  │                      │  │ 缩略图网格          │
│                  │  │ 名称 [收起预览][放置] │  │ 三列，可滚动        │
└──────────────────┘  └──────────────────────┘  └─────────────────────┘
```

- 模型库从编辑面板旁展开，可随时收起。浏览期间，编辑面板继续显示当前选中对象的属性。
- 本次程序运行中第一次打开 F10 时，模型库是收起的，点编辑面板上的「模型库」展开。
- 同一次运行内，记住展开或收起，以及上次所在的来源页。重启程序后回到默认。
- 展开时不自动选中任何模型，仅显示列表；选中后在模型库左侧打开独立预览，不移动搜索框或挤占列表高度。收起预览、切换来源或收起模型库时关闭预览。

### 4.2 缩略图网格与搜索

- 每个模型一格，显示缩略图和显示名，按显示名排序。
- 搜索框按显示名过滤当前来源，不区分大小写，三个来源共用。切换来源时保留搜索词。
- 搜索无结果时显示“没有匹配的模型”，与“此来源暂无模型”区分开。
- 本地 GLB 的缩略图生成之前显示占位图标，不影响浏览。

### 4.3 单击预览

- 单击一格即选中，预览区换成该模型。同一时刻只渲染一个三维预览。
- 预览画布为不透明纯黑色；大图与模型库之间留出间距，宽度最多 560、高度按窗口空间收敛。修正预览灯光的同优先级冲突，不向操作者显示黄色渲染警告，也不关闭主场景的全局警告。
- 预览不响应鼠标：模型以固定的斜俯视角绕竖直轴旋转，约 12 秒一圈，自动缩放到填满预览区。切换模型时从正面开始。
- 在预览区点击、拖动、滚动，都不影响预览，也不传到场景。
- 蓝图模型在浏览时不运行脚本：预览区显示缩略图大图，并注明“放置后可查看完整效果”。
- 浏览和切换来源都不写数据，也不在场景中生成临时模型。

### 4.4 不可用模型

- 不可用的模型照常占一格：整格置灰，缩略图位置显示警示图标，名称下方写简短原因，如「文件损坏」「加载失败」。
- 单击后，预览区显示完整原因和处理办法；「放置」不可用，也不能拖动。
- 本地 GLB 在列出时只做轻量检查（能否读取、文件头是否为 GLB），完整解析放在生成缩略图时。解析失败再标为不可用。
- 没复制完的文件按“文件损坏”处理，刷新后可以恢复。

### 4.5 本地 Models

- 「刷新」重新扫描 Models 文件夹。切到「本地 Models」页、或重新展开模型库时，也会自动扫描一次。不实时监视文件夹。
- 「打开文件夹」打开程序实际读取的 Models 目录。
- 刷新只更新列表和缩略图，不影响场景中已摆放的实例。
- 刷新时保留当前选中项；选中的文件已被删除时，清空预览并提示。
- 缩略图缓存放在程序缓存目录，按文件内容判断是否需要重新生成。缓存可以删除，会自动重建。
- 列表显示文件名，不含 `.glb`。

## 5 放置

### 5.1 两种放置方式

- **拖入**：按住缩略图拖动，超过拖动阈值就进入放置。光标进入场景后，出现跟随光标贴地的临时模型，在场景中松手即确定位置。拖回编辑面板或模型库上松手，或者拖动中按 Esc，都会取消。轻点（没超过阈值）仍然只是选中加预览。
- **按钮**：选中模型后点「放置」，临时模型跟随光标，左键确定位置，Esc 取消。光标在面板或模型库上方时隐藏临时模型，点击面板不会放置。完成后库中仍选中该模型，可以接着放下一个。
- 模型库在放置过程中保持展开。模型还没加载完也可以拖动，临时模型在加载完成后出现。

### 5.2 放置信息小框

确定位置后，临时模型停在原处，弹出小框：

| 字段 | 规则 |
| --- | --- |
| 实例编号 | 选填。可以手输，也可以从实例清单中尚未投产的编号里挑选 |
| 名称 | 默认值：场景陈设取“显示名 + 序号”（见 6.1）；选了清单编号时取清单中的名称。可修改 |
| 类型 | 填了编号才出现，而且必选。只列出具备三维表现和空间能力的类型，不包括「场景陈设」。编号来自清单时，自动带出清单中的类型；清单类型匹配不上时，需要手动选择 |

- 不填编号，直接按回车或点确定，就保存为场景陈设。
- 点取消，什么都不保存，临时模型消失。
- 保存成功后选中新对象，属性区随之切换。
- 保存失败时，小框和临时模型都保留，可以重试或取消。同一次放置无论重试几次，只会创建一条记录。

### 5.3 编号冲突

填的编号已经对应一个后台实例时，确定按钮不可用，并按情况引导：

- 该实例在当前关卡中已加载：提示「已投产」，给出「定位」按钮。点击后取消本次放置，镜头移到该实例并选中它。
- 该实例已从场景移除：提示可在实例列表中重新加载。
- 该实例在回收站中：提示先在网页回收站恢复或彻底删除。

想给已有实例换成这个模型，留给后续的换模功能。

## 6 场景陈设与实例

| | 场景陈设 | 实例 |
| --- | --- | --- |
| 如何产生 | 放置时不填编号 | 放置时填写编号，或场景陈设补填编号 |
| 类型 | 「场景陈设」 | 操作者选择的业务类型 |
| 编号 | 内部编号不展示；F10 的实例 ID 单行显示「未编号（场景陈设）」，悬停说明「尚未分配业务编号，当前为场景陈设」 | 业务编号，即实例编号，与网页投产一致 |
| 实例清单（台账） | 不进入 | 编号原本不在清单中时，自动补登 |
| 网页实例列表 | 单独的「场景陈设」分组，不计入设备数量 | 归入所属类型分组 |
| 信息面板、业务归属 | 不可配置，提示“在运行中的三维场景按 F10，进入编辑模式补填业务编号” | 可配置 |
| 模型 | 实例自己的模型覆盖，不修改类型默认模型 | 同左 |

本体配置中心保留「场景陈设」卡片，以「系统预置」标签和蓝灰色左侧色条区分业务类型。此系统类型专用于场景陈设：铸造实例时不能选「场景陈设」，实例也不能改回场景陈设。

### 6.1 场景陈设命名

- 名称默认为“模型显示名 + 两位序号”，如「货架 01」「货架 02」。
- 按同一数据集、同一模型的现有默认名称（含回收站）取最大序号加一，超过 99 时自然延长。彻底删除或改名后允许再次使用原序号。名称允许重名，撤销、恢复和挂接按对象标识执行。无需保存历史最大序号。
- 名称可以在小框中、F10 属性区或网页中修改。

### 6.2 事后补填或修改编号

在 F10 中选中对象后修改编号：

- 场景陈设随时可以补编号，变成实例，需要选择类型。如果编号来自实例清单，名称和类型取清单中的。
- 实例在没有挂接外部实时数据、信息面板、业务归属、构件绑定时，可以改编号，用于修正笔误。
- 只要挂了上面任何一项，编号就锁定，属性区写明原因。外部实时数据的原因写“正在接收外部实时数据”。网页的“迁移编号”另行登记为 NEW-04；NEW-04 上线之前不显示迁移入口提示。
- 类型仅带信息面板能力或继承类型面板，不视为实例独立配置；只有实例自己的信息面板配置才触发该项锁定。仅按类型、分区规则自动匹配业务视图，不因此锁定；草稿、已发布及上一发布配置中显式包含或排除该编号的引用仍锁定，包括当前规则未匹配到的显式引用。实例自身的业务归属、构件绑定和外部实时数据规则不变。
- 修改编号后，旧清单项仅在来源明确为 F10 自动补登（`source=runtime_editor`）时移除；手工、导入、旧数据缺失来源或未知来源一律保留原清单资料，回到“待投产”。新编号已有清单项时沿用该项，不重复补登；改号失败时实例和清单均不变。不新增存储字段。
- 新编号适用 5.3 的冲突规则。
- 修改在一次保存中完成，位置、模型和名称都不变。修改编号不进入撤销历史。

### 6.3 外部实时数据

平台没有测点配置入口，也不存历史数据。此前文档中的“测点绑定”按以下任一条件判断外部实时数据挂接。

- `runtime_source_policy.py` 的 `is_websocket_spatial_instance(id)` 返回真。
- 该项目最近一次 UE 心跳的 `realtime_channel.targets[].instance_id` 包含此编号。按当前关卡绑定的项目读取，心跳转为离线后仍按最近一次报告的名单判断。

命中时锁定编号。删除确认框列出“外部实时数据（外部系统按此编号推送）”，提示“删除后外部推送将对不上”。两项都没命中时，继续检查信息面板、业务归属和构件绑定。

## 7 删除与撤销

### 7.1 删除

- 选中对象后「删除」，支持多选，删除的对象进入回收站，在网页回收站恢复。
- 删除场景陈设只需一句确认。删除实例时，确认框列出它挂接的外部实时数据、信息面板、业务归属，并说明编号会回到实例清单的“待投产”状态。
- 「从场景移除」保留。两个按钮的说明要分清楚：移除只是不显示，记录还在；删除会进回收站。
- F10 的删除按当前关卡绑定的数据集校验并执行，不使用网页当前激活的项目。

### 7.2 撤销与重做

- Ctrl+Z 和 Ctrl+Y 与现有的空间编辑撤销共用一条历史，按时间倒序撤销。
- 撤销放置：立即把对象移进回收站，提示写明对象名称和“已移入回收站”。重做：从回收站恢复，编号不变。
- 撤销删除：从回收站恢复。
- 撤销一个已经挂接业务数据的实例时，弹出与删除相同的确认框。
- 撤销历史只在本次 F10 编辑期间有效，退出即清空。
- 「取消未保存修改」只撤回暂存的空间修改，不撤回已经保存的放置、删除和编号修改。

## 8 默认规则（未单独讨论，审阅时可改）

| 情形 | 默认处理 |
| --- | --- |
| 当前关卡未绑定数据集、只读，或操作者没有编辑权限 | 模型库可以浏览和预览；「放置」、拖入、删除、改编号在界面上直接不可用，并写明原因，不等到保存时才失败 |
| 当前数据集没有可用的业务类型 | 小框中填编号时提示“当前数据集还没有可用类型，请先在网页配置”，只能保存为场景陈设 |
| 导入的老数据集缺少「场景陈设」类型 | 第一次放置场景陈设时自动补建，不覆盖现有类型（沿用交付包草稿 5.2） |
| 已摆放对象使用的模型，在新版本中从模型库删除，或本地文件丢失 | 对象保留，显示可定位的缺失提示或占位模型，不删除记录（沿用交付包草稿 6.3） |
| 窗口高度不足 | 模型库和独立预览分别限制高度，缩略图网格滚动；预览按可用宽度缩小，不向列表插入内容；常规窗口中三栏分开，极窄窗口允许预览覆盖场景区域 |
| 网页在 F10 打开期间改名或删除同一对象 | 沿用现有的轮询刷新；F10 中对已删除对象的操作提示失败，不重新创建 |

## 9 对技术方案的要求

- **代码位置**：插件端的模型库、缩略图、拖放和小框放在 `RuntimeEditor/` 下的独立文件，`OntoTwinRuntimeEditorPanel.cpp` 只负责挂接入口。编辑器端的模型库设置和打包检查放进插件的编辑器模块。后端新能力放进独立模块，不往 `app.py` 里加逻辑。
- **后端接口**：
  - 放置接口需要接收编号、名称和类型，并保持现有的单事务、关卡授权和同次放置去重。
  - 新增按场景校验的删除、回收站恢复和修改编号接口。这些接口都按关卡绑定的数据集执行，不依赖网页当前激活的项目。
  - 修改编号要在一个事务中完成实例记录和实例清单的更新，并在事务内检查挂接项。
- **存储**：实例表的主键是数据集加编号，修改编号是更新现有记录，预计不需要改表结构。软删除的记录仍占用编号，因此有 5.3 的回收站冲突规则。场景陈设序号优先从现有记录（含回收站）推算，不另存计数器。如果技术方案认定需要新增任何存储字段，须先单独报产品同意。
- **网页**：实例列表增加「场景陈设」分组，并从设备数量统计中排除；信息面板、业务归属的选择入口排除场景陈设；场景陈设的编号位置显示「场景陈设」。
- **依赖**：缩略图渲染和拖放使用 UE 自带能力，不新增第三方依赖或构建工具。预览使用的 UMG Viewport 在 UE 5.6 中标为 Experimental，需要在性能验收中单独记录。

## 11 初验调整（2026-11-17）

产品初验后，本轮补充以下要求，涉及布局和 Art Studio 空状态时以本节为准。

- 模型库固定在屏幕右侧展开，与左侧操作面板分离；窗口变化时保留右侧边距并限制面板高度，原属性区保留。
- 模型库外框直接复用编辑面板的背景、透明度和圆角样式，文字、按钮保持一致。

- 扩充标准工程的预置可摆放模型，优先使用原工程的仓储、搬运、包装和安全用品；材质依赖随包，显示中文名称，建筑环境构件不列入该批模型。

补充验收：在标准厂房打开 F10，左右两栏分离且外框质感一致；浏览扩充后的工程模型，检查缩略图和预览；切到 Art Studio，可见未部署状态，点击管理员入口显示说明，不发登录或同步请求。

同日第二轮界面调整：未选中模型时只显示列表，不保留空预览和禁用的放置行；选中后才在上方展开大图与放置操作，提供“收起预览”返回列表。切换来源、重新展开模型库时回到列表状态。常规宽度下网格为三列，按实际可用宽度计算卡片、间距与按钮留白，窄窗口减少列数。两侧外框同时减少场景透色，保持相同的中性底色和透明度。补充验收应分别截图列表态、选中预览态，并检查预览收起及本地页切换。
