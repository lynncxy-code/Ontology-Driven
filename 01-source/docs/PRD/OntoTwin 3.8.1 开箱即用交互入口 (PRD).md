# OntoTwin 3.8.1 开箱即用交互入口（PRD）

状态：已实现并同步至 SCC2；源码与三目标编译已通过，待 PIE/Standalone 关卡验收  
日期：2026-08-12  
依赖：OntoTwin 3.8、3.7 顶部信息面板、4.0 场景交互层  

## 1. 背景

3.8 已交付页面资源、业务管理、页面绑定、解析预览、发布、UE 单例网页宿主和 Web Bridge，但 UE 侧只提供了以下 C++/Blueprint 可调用函数：

```text
OpenProjectHome
OpenZone
OpenBusinessView
OpenInstanceDetail
```

这些函数没有接入 TwinSceneManager 默认交互。用户即使已经把 TwinSceneManager 放进关卡、完成页面配置并发布，仍然找不到可点击的运行入口，只能自行编写蓝图或代码。该状态不符合“插件放入场景即可使用”的产品预期，也使 3.8 无法被非 UE 开发人员直接验收。

3.8.1 只补齐 UE 默认交互入口，不重做 3.8 的数据模型、解析规则或网页宿主。

## 2. 产品目标

当关卡中存在一个正常工作的 TwinSceneManager，且 Nexus 已发布有效的 3.8 配置时，用户无需进入人物漫游、无需编写蓝图、无需填写实例 ID、无需增加新的快捷键，即可在 UE 中完成四类操作：

1. 打开项目主页。
2. 打开指定空间分区页面。
3. 打开指定业务管理页面，可明确限定一个空间分区形成交集。
4. 打开当前实例详情页。

所有入口必须复用同一个 `WebInteractionManager` 和同一个 Screen Space 网页宿主。

## 3. 非目标

3.8.1 不包含：

- 新增后端 API、字段或存储结构。
- 修改 3.8 页面解析优先级。
- 修改 Nexus Web 交互工作台。
- 为项目制作关卡蓝图、角色蓝图或实例蓝图。
- 新增全局快捷键。
- 让单击模型立即弹出网页。
- Level Streaming、Data Layer、World Partition 或加载前过滤。
- 把网页业务数据交给 OntoTwin 编辑。

## 4. 已确认交互

### 4.1 使用前提

用户只需要：

1. 把 TwinSceneManager 放入关卡。
2. 保持场景交互和 Web 交互组件启用。
3. 在 Nexus 发布有效的 3.8 配置。

不要求任何蓝图接线，也不要求先按 `F7`。Runtime Editor 编辑模式会暂时独占鼠标选择；退出编辑模式后恢复 Web 实例选择。

### 4.2 实例详情

实例详情属于全局场景选择能力，两种运行状态共享相同的二次确认状态机：

- 普通运行状态：鼠标左键选择。
- 人物漫游状态：近景使用 `E/左键`，上帝视角使用鼠标左键。

```text
第一次选择实例
→ 记录当前实例
→ 保持现有顶部信息面板选择行为
→ HUD 提示“再次选择可打开网页详情”

再次选择同一个实例
→ 调用 OpenInstanceDetail(instance_id)
→ 按 3.8 优先级解析页面
→ 打开网页并选中、聚焦该实例
```

“聚焦”按实例有效模型包围盒计算观察中心与距离，并进行一次性平滑镜头移动，不表示持续跟踪。人物漫游状态下不得传送人物本体，而是进入可自由移动的观察相机；用户按 `V` 返回人物视角。

选择另一个实例时，新实例成为当前实例，必须再次选择才打开网页。点击空白区域时清除当前实例。

进入或退出人物漫游时清除二次选择状态，避免切换输入模式后的第一次点击被误判为“再次选择”。

该交互保证“打开详情”属于明确的第二次操作，避免浏览场景时一次误点就弹出全屏网页。

### 4.3 项目、空间与业务入口

`TwinSceneManager` 启动后创建一个全局场景交互 HUD。现有 `Tab` 操作抽屉在普通状态和人物漫游状态都可打开，其中包含“Web 业务”区域：

- `项目`：点击“打开项目主页”，调用 `OpenProjectHome()`。
- `空间分区`：先从已发布运行投影中选择分区名称，再点击“打开分区”，调用 `OpenZone(zone_id)`。
- `业务管理`：先选择已启用业务，再选择业务范围并点击“打开业务”。业务范围默认为“全部空间分区”，调用 `OpenBusinessView(business_view_id, "")`；明确选择一个分区时调用 `OpenBusinessView(business_view_id, zone_id)`。

选择下拉项本身不立即打开网页，避免误触和无法确认组合范围。下拉列表显示名称，内部传递稳定 ID；名称重复时追加 ID 以便区分。业务与分区的组合显式出现在同一操作行中，不能依赖用户之前打开过哪个分区。

点击“打开分区”或“打开业务”并成功解析后，系统先应用场景成员显隐，再按最终可见业务成员的联合包围盒执行一次性平滑取景。未分区常驻实例不扩大取景范围，空范围保持原镜头；下拉框仅改变待提交选项，不立即移动镜头。实例详情和网页 Bridge `focus_instance` 仍按单实例包围盒聚焦。

普通状态下抽屉标题为“场景交互”，只显示 Web 业务；进入人物漫游后标题变为“漫游控制”，在同一抽屉中追加线路、视角和人物操作。二者复用同一个 Widget，不创建第二套 Web 入口。

### 4.4 失败反馈

入口不得静默失败：

| 情况 | 用户反馈 |
| --- | --- |
| Web 配置尚未拉取 | Web 配置尚未就绪，请稍后重试 |
| 没有对应页面绑定 | 当前范围没有可用的页面绑定 |
| 绑定被 `block` 阻止 | 当前范围不允许打开页面 |
| 分区或业务不存在 | 当前选择已失效，请刷新后重试 |
| 网页加载失败 | 使用 3.8 宿主已有的重试、返回、关闭 |

失败信息显示在现有 HUD 说明区域；不使用额外弹窗。

## 5. 解析与运行规则

3.8.1 不改变 3.8 解析器：

```text
实例详情：Instance > Zone+Type > Type > Zone > Project
空间分区：Zone > Project
业务管理：BusinessView > Project；可选 Zone 只参与场景交集与 URL 参数
项目主页：Project
```

入口只提交上下文，不决定页面 URL：

- 实例详情提交 `instance_id`，运行时补齐该实例的 `zone_id` 和 `object_type_rid`。
- 空间分区提交 `zone_id`。
- 业务管理提交 `business_view_id`；选择限定分区时同时提交 `zone_id`。
- 项目主页提交当前 `project_id`。

只读取已发布配置。草稿变化不影响 UE；发布 revision 更新后继续沿用 3.8 的 HTTP 轮询热更新。

## 6. UI 与渲染约束

- Web 业务入口属于 `TwinSceneManager` 生命周期内的全局 Screen Space 场景交互 HUD，不创建 World Space 面板。
- 操作抽屉使用现有 Performance 级静态玻璃表面，不增加 Postbuffer、SceneCapture 或独立 RenderTarget。
- 只有按钮和下拉列表参与命中测试；玻璃、边框、标题和说明必须为 `Self Hit Test Invisible`。
- 网页仍使用 3.8 单例 Screen Space 宿主，按 High → Balanced → Performance 降级。
- 网页像素、文字和点击区域始终位于玻璃装饰层之上，不得被模糊或折射。
- 网页关闭或返回后恢复原有 UE 输入、鼠标状态和相机控制。

## 7. 生命周期

### 7.1 运行配置更新

WebInteractionManager 收到新 revision 后重建：

- 页面索引；
- 实例索引；
- 分区 ID/名称目录；
- 业务管理 ID/名称目录；
- 业务成员集合。

下一次打开 `Tab` 时刷新下拉选项。已被删除的选择不保留。

### 7.2 实例选择

当前实例选择只存在于本次运行会话的当前输入模式：

- 进入或退出漫游时清除；
- 实例销毁或失效时清除；
- 点击空白区域时清除；
- 打开网页后仍允许关闭网页并再次触发。

### 7.3 单例网页宿主

四类入口都调用同一个 WebInteractionManager。切换页面时复用已有宿主；不允许创建第二个 WebBrowser、Widget 或 Bridge 实例。

## 8. 实施范围

预计修改：

```text
OntoTwinWebInteractionComponent
  暴露可用分区、业务管理目录

TwinInteractionManagerComponent
  在普通状态与漫游状态之间共享实例二次选择状态机
  转发项目、分区、业务打开请求
  提供失败反馈

OntoTwinRoamingHUDWidget
  提升为 TwinSceneManager 生命周期内的全局场景交互 HUD
  普通状态只显示 Web 业务；漫游状态追加漫游控制

TwinSceneManager
  普通状态下把非 UI、非 Runtime Editor 的鼠标命中转为 Web 实例选择事件
```

不修改后端、ProjectStore、Web 交互 JSON 契约和前端路由。

## 10. 版本边界

3.8.1 解决的是“已配置能力没有默认入口”的可用性缺口。它不改变 3.8 的页面、业务或场景语义，也不宣称降低首次模型加载量或内存占用。

全局 Web 入口与人物漫游属于同一场景交互 HUD 的两种显示状态。后续新增与 Web 无关的常驻业务工具时，应单独评审，不能继续向当前抽屉无边界堆叠功能。

## 11. 本次实施结果

3.8.1 已完成以下落地：

- 实例详情：第一次选择实例，第二次选择同一实例打开详情页，不需要用户查找或输入实例 ID。
- 全局生命周期：普通运行状态无需进入人物漫游即可使用实例详情和 Web 业务抽屉；人物漫游只提供额外的准星/`E` 输入适配。
- 项目主页：在现有 `Tab` 操作抽屉中提供直接入口。
- 空间分区：从已发布分区目录选择名称，再明确点击打开。
- 业务管理：从已启用业务目录选择名称，可选择“全部空间分区”或明确限定一个分区后打开。
- 业务管理 + 空间分区：向 3.8 运行时显式提交 `business_view_id + zone_id`，覆盖交集场景，不依赖历史选择状态。
- 失败反馈：配置未就绪、无绑定或范围失效时，在现有 HUD 中显示原因。
- 运行时目录：3.8 配置 revision 更新后重建分区和业务名称目录，不增加后端接口或存储字段。
- 网页宿主：所有入口继续复用 3.8 的单例 Screen Space WebBrowser 与 Web Bridge。
