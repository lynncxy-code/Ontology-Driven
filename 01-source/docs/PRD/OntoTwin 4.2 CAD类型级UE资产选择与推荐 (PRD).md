# OntoTwin 4.2 CAD 类型级 UE 资产选择与推荐（PRD）

> 状态：已实现
> 日期：2026-08-18
> 通用按需目录同步更新：2026-08-19
> 适用入口：坐标标定工作台 → ② 类型审核

## 1. 目标

把“人工查看 CAD 类型名称，再去 UE Content Browser 人肉寻找资产路径”的操作，收口为 OntoTwin 内的一条闭环：

1. UE 工程只把完整 `/Game` 轻量目录树上报给 OntoTwin，不预先上传全部模型；
2. CAD 类型扫描完成后，用户在 OntoTwin 选择或填写本次应搜索的 UE 模型目录；
3. OntoTwin 向对应 UE 工程发出按需扫描请求，UE 只回传该目录及子目录的模型资产清单；
4. OntoTwin 只在本次资产清单中依据名称、历史确认、CAD 分类与尺寸比例给出候选；
5. 用户查看缩略图、路径、尺寸和推荐理由后，显式点击采用或在选择器中确认；
6. 提交类型时，把确认后的 UE 资产路径写为 ObjectType 默认模型；
7. 用户的确认进入该 UE 工程自己的对应记忆，供下次推荐；
8. 未绑定类型仍可提交，并可稍后在本体配置中心的模型库补绑。

自动推荐永远不等于自动绑定。没有显式确认的候选不得写入类型默认模型。

## 2. 已确认的产品边界

- 功能属于 OntoTwin 工具，不属于某一个 UE 工程的业务逻辑。
- 资产目录按稳定 `ue_project_id` 隔离；同名资产或同名 CAD 类型不会跨工程串用。
- 插件不得写死 `/Game/Art`、`/Game/SCC/Art` 或任何业务目录；手工配置的 `AssetRoots` 只保留为兼容入口。
- UE 轻量目录索引覆盖 `/Game`，只包含目录路径，不包含缩略图、包围盒或资产对象，因此不会把整个工程的重资产目录一次性上传。
- “推荐模型目录”由用户在类型审核页选择或填写，是本次按需同步与推荐的强制搜索范围。
- 未指定推荐模型目录时不得在全资产目录中盲目推荐；仍允许保持未绑定或人工选择。
- UE 离线时扫描请求保持等待状态；目录不存在时由 UE 返回明确失败，不得退回旧目录或全目录盲猜。
- 多个 CAD 类型可以复用同一个 UE 资产。
- 第一版只做类型默认模型，不做实例级覆盖。
- 类型允许不绑定模型；后续可在本体配置中心手动绑定或替换。
- 第一版推荐采用确定性规则；视觉 AI 只预留扩展位，不进入本期。
- 本期不修改 SCC W18 等现有业务/测试数据。

## 3. 当前加载能力结论

4.2 首次实施时 `TwinInstance::LoadMeshFromPath` 仅支持 StaticMesh。4.3.0 已把运行时扩展到 StaticMesh、SkeletalMesh 和经过校验的普通 Actor Blueprint；4.2 的选择器继续依据目录中的 `runtime_loadable` 标志决定是否允许确认。

| UE 资产类型 | 当前 TwinInstance 直接加载 | 本期选择器行为 |
|---|---:|---|
| StaticMesh | 是 | 可推荐、可确认、可绑定 |
| Actor Blueprint | 4.3.0 起支持 | 通过生成类校验后可推荐、可确认、可绑定 |
| SkeletalMesh | 4.3.0 起支持 | 可推荐、可确认、可绑定；直接加载为参考姿势 |
| 任意组合 Actor | 否 | 不伪装成单资产；后续另立组合模型方案 |
| `assembly_v1` | 仅多 StaticMesh 部件 | 保留现有迁移链，不作为本期类型选择目标 |

## 4. 用户流程

### 4.1 UE 资产目录同步

- `TwinSceneManager` 挂载通用资产目录同步组件。
- 组件在编辑器、PIE 和运行时定时上报 `/Game` 轻量目录树，并轮询属于当前 `ue_project_id` 的按需扫描请求。
- 收到请求后，组件验证目录确实存在，只递归扫描该目录中的 StaticMesh、SkeletalMesh 和 Blueprint。
- 资产清单字段：工程 ID/名称、实际扫描根目录、资产路径、名称、目录、资产类型、运行时可加载状态、网格包围盒尺寸、可用缩略图。
- 按需清单仍通过原子替换保存；完整目录树、当前扫描请求和人工确认记忆独立保留。
- 缩略图只在 UE 编辑器已有可读取缩略图时发送；缺失时前端显示无预览占位，不阻断选择。

### 4.2 类型审核

- 工作台根据“合并目标类型库”绑定的 UE 工程加载对应资产目录。
- 用户必须先在页面顶部选择或填写“推荐模型目录”，并点击“同步并推荐”。
- 下拉数据来自 UE 上报的完整 `/Game` 目录树；手工输入不要求该路径已经存在于旧资产清单。
- 页面创建扫描请求后显示“等待 UE 同步”；UE 在线时自动领取，UE 离线时保持等待且不推荐。
- UE 回传完成后，页面自动刷新本次目录资产清单并启动推荐，不要求用户再次点击刷新。
- 后端只使用该目录及其子目录中的可运行资产参与排序；切换 UE 工程时清空该目录，避免跨工程串用。
- 指定目录后，每个 CAD 候选类型显示一个推荐结果，但初始状态仍是“未确认”。
- 用户可执行：
  - `采用`：确认当前推荐；
  - `选择资产`：打开项目级资产选择器，搜索并确认其他可运行 UE 资产；
  - `目录范围`：从本次同步到的目录中选择，或直接填写 `/Game/...` 前缀筛选；
  - `填写完整资产路径`：按 `object_path` 或 `package_name` 定位目录中的资产并确认；若路径尚未同步或不可运行，必须提示原因且不得绑定；
  - `清除`：恢复未绑定；
  - 保持未绑定并正常提交。
- 已确认与未确认必须有明确状态差异；提交只读取已确认值。

### 4.3 提交与记忆

- 确认路径同时写入 `asset_id` 与 `ue_asset_path`，保持现有快照/本体模型库兼容。
- 提交成功后记录 `CAD block_name / 类型名称 / 分类 → UE asset_path` 的工程级确认记忆。
- 记忆只用于下次排序，仍须再次人工确认。

## 5. 推荐规则

推荐只对用户指定目录及其子目录内可绑定的 StaticMesh、SkeletalMesh 和 Actor Blueprint 排序。目录范围是候选集硬过滤条件，不是加分项；基础评分由过滤后资产的可用信号归一化加权：

| 信号 | 说明 | 基础权重 |
|---|---|---:|
| 工程级人工确认记忆 | 同一 CAD 类型在该 UE 工程中曾确认 | 最高优先级 |
| 名称相似度 | 清洗前缀、分隔符、大小写后的名称相似度 | 0.58 |
| CAD 分类与 UE 目录 | CAD 主图层/分类与文件夹、名称 token 重合 | 0.16 |
| 包围盒尺寸与长宽高比例 | DXF 块包围盒与 StaticMesh bounds 的对数比例差 | 0.18 |
| UE 路径上下文 | 扫描根目录内的目录/标签上下文 | 0.08 |

缺失的信号不按零分惩罚，而是对剩余权重重新归一化。结果返回分数、置信度和人类可读理由。低置信度仍可供浏览，但不得自动确认。

## 6. 接口

### 6.1 `POST /api/v2/ue/assets/catalog`

UE 工程上报本次按需目录的完整资产快照。携带 `scan_request_id` 时，服务端原子替换目录并把对应请求标记为完成，同时保留目录树和人工确认记忆。

### 6.2 `GET /api/v2/ue/assets/catalog`

Web 端读取项目资产目录。可显式传 `ue_project_id`；未传时使用当前激活类型库绑定的 UE 工程。

### 6.3 `POST /api/v2/ue/assets/folders`

UE 工程上报完整 `/Game` 轻量目录树，不上传资产详情。

### 6.4 `POST /api/v2/ue/assets/scan-requests`

Web 端提交 `ue_project_id + folder_path`，创建新的按需扫描请求。

### 6.5 `GET /api/v2/ue/assets/scan-requests/pending`

UE 按自身工程身份轮询待处理请求；没有请求时返回 `idle`。

### 6.6 `GET /api/v2/ue/assets/scan-requests`

Web 端读取请求的 `pending / completed / failed` 状态，用于驱动等待和错误提示。

### 6.7 `POST /api/v2/ue/assets/scan-requests/result`

UE 在目录不存在或扫描无法启动时回传失败原因；成功结果由资产目录接口完成闭环。

### 6.8 `POST /api/v2/ue/assets/recommend`

输入必填的 `folder_path` 和 CAD 候选类型数组，返回该目录及子目录内每种类型的 Top-N 可推荐 UE 资产、评分与理由。目录为空、未同步或没有可运行资产时拒绝推荐。

### 6.9 `POST /api/v2/ue/assets/confirmations`

在类型提交成功后记录人工确认。只接受当前目录中存在且 `recommendable=true` 的资产路径。

## 7. 存储与兼容

- 资产目录与确认记忆存放在独立的 `backend/data/ue_asset_catalogs/`，不改变 `ProjectStore` schema。
- 同一工程文件中新增 `available_folders / folders_synced_at / scan_request`，旧目录文件缺少这些字段时按空值兼容。
- 目录文件名由 `ue_project_id` 的哈希生成，防止路径穿越；原始工程 ID 保存在文件内容中。
- 现有 `block_asset_mapping.json` 继续作为旧数据提示来源，但旧值只进入推荐，不直接视为本次人工确认。
- 本体配置中心继续读取 ObjectType 的 `asset_id / ue_asset_path`，可随时手动替换。

## 8. 验收口径

1. UE 项目 A、B 的目录和确认记忆互不串用。
2. 类型审核页能显示目标项目的目录状态、资产数量与最后同步时间。
3. 推荐出现后不点击采用，提交结果必须保持未绑定。
4. 点击采用或选择器确认后，提交结果写入类型默认模型。
5. 同一 StaticMesh 可被多个类型确认。
6. SkeletalMesh 与通过 Actor 生成类校验的 Blueprint 可确认；其他 Blueprint 可见但不可确认并解释原因。
7. 未绑定类型可以正常提交，之后可在本体配置中心补绑。
8. UE 缩略图缺失不会阻断目录同步、推荐和人工确认。
9. UE 上报的目录树包含 `/Game` 下的业务目录，但不上传全部资产详情。
10. Web 资产选择器可按目录前缀筛选，也可粘贴完整资产路径定位；不在当前目录或不可运行的路径不得确认。
11. 未指定“推荐模型目录”时不返回自动推荐；指定 `/Game/X` 后，推荐候选不得出现 `/Game/X` 之外的资产。
12. Web 输入 `/Game/SCC/Art` 后可创建待处理请求；UE 在线后只上传该目录及子目录资产，并自动触发推荐。
13. UE 离线时页面保持“等待 UE 同步”；UE 中不存在所填目录时显示 UE 返回的具体错误。
14. 源码与默认配置中不包含 `/Game/SCC/Art` 等项目专用硬编码。

## 9. 示例：`/Game/SCC/Art`

1. UE 上报目录树，其中包含 `/Game/SCC/Art`；
2. 用户在类型审核页选择该目录，或直接填写后点击“同步并推荐”；
3. 后端生成 `pending` 请求，页面进入等待态；
4. DigitalFactoryBase 的 UE 插件领取请求，验证目录存在并扫描其中三类运行时资产；
5. UE 上报资产清单并完成请求；
6. 页面自动刷新，只在 `object_path` 以 `/Game/SCC/Art/` 开头的资产中推荐；
7. 用户人工确认后才写入类型默认模型。
