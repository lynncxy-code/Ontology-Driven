# OntoTwin 插件版本与工程交付

## 入口

Windows UE 5.6 编辑器顶部「工具」菜单：

- **OntoTwin 插件版本与更新**
- **OntoTwin 导出交付工程**

菜单打开独立工具窗口，使用 UE 自带 Python，不安装额外依赖。窗口可在关闭 UE 后保留，用于安全更新和编译。

## 如何读版本

三种信息不能混为一谈：

| 信息 | 含义 |
| --- | --- |
| 版本名 + 源码编号 | `.uplugin` 的人工版本名，加上自动计算的 Source / 描述文件内容编号；每次源码变化均可区分 |
| 资源编号 | Content、Resources、Config、Tools 的内容编号；资源或交付工具变化也能识别 |
| 实际运行构建 | 编译进当前加载 DLL 的源码编号；不是读取磁盘文件冒充运行版本 |

同时显示当前工程插件真实路径、是否目录链接，以及所选**本机母本**的源码和资源编号。不查询远程发布，不把“有差异”武断等同于“母本更新”。源码编号包含文件内容，所以换行差异也会产生新编号。

当前人工版本名仍沿用已有描述文件，不冒充新发布版本。自动编号负责区分每次修改；正式发布时维护者再更新人工版本名。

运行构建是**打开工具时的快照**。重编译后需重新打开 UE 和此窗口再检查。资源编号代表磁盘状态，不能证明内存中已经重新加载资产。

## 更新

1. 先确认机器、工程路径和母本路径；有差异先确认母本包含所需功能。
2. 共享母本（junction）无需复制。源码变化后关闭 UE，点「编译更新」，成功后重新打开 UE。
3. 独立副本：关闭所有 UE 编辑器，点「更新独立副本」，确认替换。旧插件完整备份在工程 `Saved/OntoTwinPluginBackups/previous-*`，不放在 Plugins 内，避免重复插件。
4. 更新不复制母本旧 DLL。点「编译更新」，成功后重新打开 UE 检查。
5. 更新只处理当前工程的 OntoTwinSync。其他插件有独立依赖和版本，不静默替换。失败时保留诊断文件，不自动删除用户数据。

需要 Windows C++ 编译工具链。多 Editor Target 工程不猜编译目标，应在 Visual Studio 选择。编译日志保存在 `Saved/OntoTwinDelivery`。

## 导出可编辑交付工程

1. 保存所有关卡与资产。导出期间不要保存、编译或修改源文件。
2. 打开「导出交付工程」，确认当前工程、后端地址、UE 项目编号。
3. 点「读取数据集」：只按 UE 编号匹配，不改变平台激活数据集。无法唯一匹配时先确认绑定。
4. 指定**全新**输出目录，点击导出。默认带完整数据集包；仅工程选项必须明确勾选。
5. 成功目录包含 `.uproject`、Config、Content、Source、Build、Plugins、Art（存在时），目录链接展开为真实文件；排除缓存、Saved、Intermediate、版本库。工程根 Binaries 不复制，插件 Binaries 保留以兼容二进制依赖，但不承诺旧 DLL 与当前源码一致。
6. `OntoTwinDelivery` 内含数据集包（包括后台支持的 CAD、底图和网页附件）、版本清单、逐文件 SHA-256 和交付说明。

输出目录不能位于原工程或链接源目录内，不覆盖已有目录。数据集绑定错误、附件缺失、空间不足、复制中改动、链接循环会中止。带 `EXPORT_INCOMPLETE.txt` 的目录**不得交付**，原工程未被修改。

## 目标机

安装一致版本 UE 与 C++ 工具链 → 安装清单中的引擎级第三方插件 → 编译工程 → 启动兼容 OntoTwin 后端 → 通过「导入数据集包」导入并确认 UE 绑定 → 检查后端地址 → 验收漫游、空间跳转、底图和业务交互。

此功能**不是打包 exe**，也不包含 OntoTwin 后端安装、外部 WebRTC 网关、外部实时服务或工程外绝对路径资源；商业模型与第三方插件授权需另行确认。额外插件/资源根目录引用会阻止导出，须先迁入工程内。

## 开发验证

标准库测试：`python -m unittest discover -s ue_project/Plugins/OntoTwinSync/Tools -p test_delivery.py -v`

源码指纹协议与 `OntoTwinSync.Build.cs` 一致；禁止改为只读 `.uplugin` 版本号判断当前 DLL。不得在工程运行时覆盖 DLL，也不得将副本备份留在 Plugins 下。
