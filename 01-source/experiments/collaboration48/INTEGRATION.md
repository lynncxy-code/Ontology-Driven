# 4.8 页面联通测试环境

## 地址和边界

- 入口：`http://127.0.0.1:5148/nexus`；统一登录／初始化 `/account`，组织管理 `/organization`。
- Docker：`ontotwin-48-integration`，基于现有 test0316 后端镜像复用既有业务路由，前端只读挂载当前 `01-source/frontend`。
- 独立数据目录：`03-workspace/collaboration48-integration/data`。组织及成员保存在该测试目录，重启不清空；会话重启失效，重新登录。
- 不修改正式 5000、test0316 的 5100、原数据库或 UE 工程，不从它们代理业务写请求。
- 管理员测试账号 `admin / DemoAdmin2026!`；编辑者测试账号 `editor / DemoEditor2026!`（首次登录改密）。均为公开测试账号，不用于生产。

## 已接通流程

1. 原 Nexus／业务入口未登录时进入同站账号页；未初始化则创建本地环境，完成后返回原请求入口，默认进入我的数据集。
2. 原 Nexus 顶部组织按钮打开管理页，保留原侧栏；管理页不再重复显示自己的侧栏与头像。
3. 管理页在组织信息／成员管理间切换，可创建成员与授权；项目列表来自当前测试后端真实数据集，不使用独立虚构列表。
4. 原数据集页新建项目后，成员授权列表可见该项目，创建者取得测试模型编辑权。
5. 管理页返回原工作页；原侧栏继续切换业务页面；浏览器前后退可恢复导航。管理弹窗未提交时切换或退出提示放弃／继续。
6. 退出使服务端会话失效，再登录回原入口；直接访问受保护 API 未登录返回 401。

## 当前限制

这是页面和账号管理的联通测试，不是完整 4.8 权限实施。旧业务接口仍使用原全局激活机制，尚未全部按项目授权改造；为了避免把 UI 权限当成安全能力，旧业务写操作暂仅管理员可用，编辑者额外允许新建空数据集。旧业务读路径仅用于本环境公开试验数据，不能放入需要隔离的真实项目。

尚无真实 UE 场景级插件联调、生产身份加固及正式存储迁移。本次新增测试状态格式不修改 ProjectStore／数据库结构。外部 HTTP 服务调用已禁用，图数据库与中转站指向不可用的本机测试地址；依赖外部服务的功能不作为本次联通验收。

测试初始化保护依靠仅本机发布 5148 端口并严格检查请求 Host/Origin；不能直接复制到远程或反向代理生产部署。

## 验证与运行

`python -m unittest -v test_model test_integration_http`：模型与已初始化环境的 HTTP 联通验证。

浏览器实测：首次初始化→原我的数据集→原表单创建并激活测试项目→顶部组织管理→新增编辑者→返回工作页；容器重启后重新登录，组织、成员与已激活项目保留。前端静态文件通过语法检查。仅重启本测试容器即可加载 Python 适配层变更，正式环境无需重启。

代码入口 `integration.py` 只允许设置 `ONTOTWIN_48_ISOLATED=1` 的独立容器运行。生产端口不应启用此试验适配层。
