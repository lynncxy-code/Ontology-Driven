# OntoTwin MCP 测试指南 & 提示词手册

## 先说结论：测这些工具**不需要 UE**

UE 只是下游的「3D 显示器」——它轮询后端状态来渲染画面。这 30 个工具操作的是**后端数据层**（Nexus REST），UE 开不开都不影响工具好不好用。测工具 = 看它对后端的请求有没有正确返回数据。没有 UE，30 个工具照样全测，只是看不到 3D 而已。

有两种测法：
- **方式一（最快）**：跑 `selfcheck.py`，一条命令做**基础只读链路冒烟检查（10 个代表性只读工具）**，看链路通不通——不用 AI 客户端。注意它只是冒烟，不是全量工具覆盖，其余工具用方式二逐一验证。
- **方式二（真实用法）**：在 AI 客户端里用**提示词**让 AI 调工具，看它回什么。

---

## 方式一：自检脚本（一条命令，证明链路）

装好包后（这是**基础只读链路冒烟检查**，只打 10 个代表性只读工具，非全量）：

```powershell
python selfcheck.py
# 后端不在默认 88.66：先 set NEXUS_BASE_URL=http://你的IP:5000
```

**它会打印类似**（这是连当前 88.66、只有内置 demo 时的真实输出）：

```
[OK]   get_active_project      -> {'dataset_id':'demo','writable':False,'kind':'demo'...}
[OK]   list_projects           -> [{'id':'demo','is_active':True...}]
[OK]   list_object_types       -> [{'name':'Employee','category':'Personnel'...}]
[OK]   list_instances          -> []
[OK]   get_state_snapshots     -> []
[OK]   get_ue_binding_status   -> {'mode':'unbound','status':'ok'}
[ERR]  get_import_staging_graph-> [NEXUS_NOT_FOUND] 尚未导入任何自定义数据
[ERR]  list_components         -> [NEXUS_NO_ACTIVE_PROJECT] 请先用 activate_project 激活一个项目
```

**怎么看结果**：
- `[OK]` = 工具经真实 HTTP 打到后端、拿到了响应 → **链路通、工具好用**。
- `[ERR]` **不代表工具坏**，而是工具**正确报告了后端当前状态**：demo 是只读的、还没导入数据，所以「构件/清单/剖面」这类项目级查询会提示「先激活项目」。这恰好也证明了**错误映射**在工作（把后端 400/404 翻译成清晰的中文提示）。

> 想让 `[ERR]` 那几个也变 `[OK]`：先按下面「写工具测试路径」建一个空项目并激活，它们就会返回 `[]` 而不是报错。

## 方式二：AI 提示词手册

在 Claude Code / Cursor / Codex 里，**用大白话说需求，AI 自己挑工具调**。下面每行给一句能触发该工具的提示词 + 预期。

### A. 只读工具（现在对 demo 后端就能测）

| 工具 | 你说 | 预期 |
| :-- | :-- | :-- |
| get_active_project | 现在激活的是哪个项目？ | demo，且标注「只读（writable=false）」 |
| list_projects | 列出所有项目 | 只有一个内置 demo |
| list_object_types | 当前有哪些设备类型？ | Employee / Worker 等人员+设备类型 |
| get_object_type | 看看 Employee 这个类型的详情 | 该类型的属性/接口/资产绑定 |
| get_import_staging_graph | 看看最近导入暂存的图谱 | 「尚未导入任何自定义数据」 |
| list_instances | 场景里现在有哪些设备实例？ | 空（demo 无实例） |
| get_state_snapshots | 把整个场景的实例状态快照拉出来 | 空数组 |
| get_ue_binding_status | 当前项目绑定了哪个 UE 工程？ | unbound（未绑定） |

### B. 写工具 —— 先建个可写项目再测（**无需任何文件**）

demo 是只读的，写工具会提示「先激活项目」。**用下面这条链路，不用任何 CSV/DXF 就能把写工具的管路全测通**：

| 步骤 | 你说 | 预期 / 证明了什么 |
| :-- | :-- | :-- |
| 1 | 新建一个空项目，名字叫「MCP测试」 | create_empty_project → 返回新项目 id |
| 2 | 激活刚建的「MCP测试」项目 | activate_project → 切换成功（⚠ 会改全局激活态） |
| 3 | 现在激活的是哪个？可写吗？ | get_active_project → 这次 `writable=true` |
| 4 | 当前项目有哪些构件？有哪些清单？ | list_components / list_roster → 返回 `[]`（不再报错，证明项目级读工具通了） |
| 5 | 铸造实例前先预览一下会造哪些 | mint_instances(dry_run=true) → `to_create:[]`（空项目没得造，但**证明 dry_run 预览通了、不写库**） |
| 6 | 测完，激活回 demo | activate_project demo（收尾，别把测试项目留成激活态） |

第 3、5 步是关键：**writable 从 false 变 true**、**dry_run 返回预览结构**——这两点一旦看到，说明写工具的项目校验、dry_run 预览、错误映射全都在正常工作。

### C. 各写工具的提示词（要真数据时用）

要走完整业务链路（真导本体、真标定、真铸造），**样例文件已随包提供**，就在 `sample-data/` 目录：6 张本体 CSV（objectdef / linkdef / linksourcetype / linktargettype / propertydef / hasproperty）+ `demo.dxf`。直接把这些现成文件的绝对路径喂给下面的提示词即可，无需另外生成。提示词长这样：

| 工具 | 你说 |
| :-- | :-- |
| import_ontology_csv | 把这几个 CSV（objectdef.csv…）导入本体 |
| publish_ontology_dataset | 把刚导入的发布成数据集「五楼」 |
| parse_cad_dxf | 解析这个 DXF 文件，找出设备块 |
| calibrate_coordinates | 用这 4 个锚点算坐标变换矩阵 |
| save_components | 把标定好的构件保存到当前项目 |
| upload_roster | 上传这份设备清单 CSV |
| automatch_bindings | 自动撮合构件和清单编号 |
| bind_instances_batch | 按撮合结果批量绑定 |
| mint_instances | 把已绑定构件正式铸造成实例 |
| set_instance_state | 把 DW-007 这个实例设成告警状态 |

> 样例 CSV/DXF 已在包内 `sample-data/`（6 CSV + demo.dxf），直接用其绝对路径即可走完整写链路，无需另外生成。见 `sample-data/README.md`。

## 常见疑问

- **为什么有的工具报错？** demo 只读、且无导入数据，属正常。建个空项目激活后（B 步骤）就正常了。
- **写工具会不会把生产数据改坏？** 写工具都带项目校验；只要你操作的是自己建的「MCP测试」项目就安全。测完记得激活回 demo。
- **这台连不上后端怎么办？** 浏览器开 `http://后端IP:5000/nexus` 能出页面才算通；连不上先解决网络/地址（见 `安装说明.md`）。
