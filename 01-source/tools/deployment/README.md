# OntoTwin 部署管理 · 0.1.0 候选版

用于已经运行起来的 OntoTwin 4.8 接入环境。管理器独立运行；关闭 UE、暂停后台时，它仍能显示更新进度。

## 使用

1. 解压管理器到固定位置，例如 `D:\OntoTwinManager`，双击 **部署管理.cmd**。使用 UE 5.6 自带的 Python，无需另装 Python。未找到引擎时选择 UE 5.6 安装目录。
2. 选择一个固定环境目录，例如 `D:\OntoTwinEnvironment`。首次点 **接管已有安装**，选择原来实际使用的接入包解压目录，里面应有 `.runtime`。不会启动另一套空数据库。
3. 添加使用该后台的全部 `.uproject` 工程。第一版统一更新所有已添加工程，不允许只升级后台后留下旧插件。
4. 关闭上述 UE 工程。点 **导入更新包**，选择新版完整接入 ZIP。当前完整包即可作为更新包，无需解压到旧目录覆盖。
5. 检查目标版本和工程列表，勾选工程范围确认，点 **备份并更新**。后台会暂时不可访问；数据库、图数据、CAD、图片、上传模型及旧插件均自动备份。
6. 完成后打开后台和 UE。管理器显示“待 UE 重启验证”时，需确认原关卡加载了原数据集、实例和交互；不要据此声称目标工程已经完整验收。

此后均从“部署管理 → 启动平台”启动这一环境。不要继续运行原解压目录的启动脚本，以免重新切回旧镜像。原目录暂时保留。

## 保留范围

- 原环境编号、端口、凭据和 Docker 数据卷。
- 账号、权限、数据集、类型、实例、固定工程/关卡绑定；合法空数据集允许保留。
- CAD、底图、附件和模型文件；工程 `.uproject`、关卡、Content 和 Config 不改动。
- 插件中的额外客户文件保留。原包自带文件被本地改动时停止覆盖，先解决冲突。

维护时先关闭对外端口，再校验数据库业务表指纹与原文件内容；校验成功后才恢复端口。数据库和前端都在同一后台镜像中，插件按照同一发布清单更新。不会跟随网页当前激活项目重新绑定。

## 失败与恢复

更新失败或断电后重新打开窗口，点 **恢复上次更新**。程序会读取事务记录，不会盲目重放更新。更新尚未开放网页时，从自动备份恢复到新的数据卷，保留原卷；若新版已经开放网页，保留现有数据，仅回退同结构的程序和插件，避免丢失更新后的编辑。

“查看备份”可打开备份目录，内含四个数据卷归档、工程插件、必要配置和校验清单。备份包含私有数据和数据库凭据，属于当前环境，不能混入通用接入包。管理器给固定环境目录设置当前 Windows 用户和 SYSTEM 访问权限。

## 当前边界

- Windows / UE 5.6 / Docker Desktop Linux containers，已有 4.8 完整接入包安装；首次安装继续使用接入包原流程。
- 第一版不生成差分包；完整接入 ZIP 可以直接导入。仅兼容 PostgreSQL 16 同 schema、同 Neo4j 镜像的升级。跨结构升级需要独立验证的迁移方案。
- 共享母本/junction、本地改动与不完整包会停止更新。当前尚无自动枚举所有异机 UE 工程的能力，必须由部署人员添加完整工程范围。
- 恢复入口处理本次中断更新；任意历史时间点恢复、换机恢复、签名验证、自动检查远端版本不属于此版。保留备份并不等同于这些功能已经实现。
- SHA-256 检查传输完整性，不代替发布者身份认证。只选择可信来源的接入包。
- 前端运行页面暂不增加“导入包”按钮；主要入口是独立管理窗口，后续接入包的 UE 插件版本页提供跳转。
