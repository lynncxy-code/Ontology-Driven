# PAE 结构化动画说明与模板工作台（Beta）

> 实验产品 PRD。仅适用于 `D:\tmp\digital_twin_aircraft\beta`，不属于 OntoTwin 主线交付。

## 1. 产品定位

PAE（Procedure / Process Animation Editor）不是通用 UE Blueprint 编辑器，而是把业务人员填写的**结构化任务说明**适配成可审阅、可修订、带版本字段（Beta 不提供生产版本库）、可供 A 角语义表现路由复用的动画行为包。输入层描述业务事项，表现层才描述动画动作。

“工序”是首个模板，不是产品唯一输入。输入也可以是装配说明、巡检步骤、维修演示或设备状态说明。

## 2. 用户与真实结果

### 目标用户

- 工业数字化项目中的工艺/演示设计人员；
- 能提供结构化说明，但不希望直接编写 UE 蓝图的配置人员；
- 需要为 A 角语义路由准备可复用动作素材的产品/实施人员。

### 用户结果

用户导入或新建并补充一份结构化任务说明，选择模板后，能够：

1. 查看说明的层级、顺序、依赖和来源；
2. 自动生成一版可修改的动画草稿；
3. 将动作绑定到模型对象或受控表现槽位；
4. 在交互 3D 视口和时间轴中调整动作、时长和关键帧；
5. 校验缺失绑定、非法参数和时序问题；
6. 保存本地草稿并导出可供 A 角消费的行为包。

## 3. 背景与问题

原型展示了“OA 工序选择 → 工序结构 → 动画编辑 → 预览 → 渲染导出”的完整思路，但其中一部分字段和交互是 OA 专用的。若将 OA 作为固定数据模型，产品会无法服务装配、巡检和设备状态等相邻场景；若直接做任意蓝图编辑，又会落入 UE 资产编辑器的复杂度和兼容风险。

### 原型取舍

| 原型元素 | Beta 决策 | 处理方式 |
| --- | --- | --- |
| 工序选择、结构图和节点详情 | 保留并泛化 | “工序”成为模板之一；统一为 `steps/blocks`，保留顺序、依赖、说明、标准和目标引用。 |
| 对象树、素材库、时间轴和关键帧 | 保留 | 作为动画草稿的核心编辑面，动作只保存逻辑 `asset_ref`。 |
| 轻量视口、网格、选择、播放和导出页 | 保留并升级 | 使用无外部依赖的程序化 3D mock 网格进行可操作审阅；二维 SVG 平时隐藏，仅作 Canvas 能力不足时的降级层，不承诺 UE 级渲染或视频输出。 |
| OA 专用的系列号、零件号、工位/班组检索 | 改为可选来源元数据 | 不把这些字段写死在核心模型；需要时由模板或 `meta` 承载。 |
| 直接编辑任意 UE/AnimBP 图表、模型层级和骨骼 | 剔除 | Beta 只生产可交接的行为包，UE 执行由后续领域角色负责。 |
| 自动猜测对象、轴向、枢轴和安全动作 | 剔除 | 生成结果必须标记为候选草稿，缺绑定或能力不兼容时阻断导出。 |
| 生产渲染、相机/音频时间轴、视频封装 | 剔除/后置 | 不影响本轮验证“结构化说明 → 可复用行为素材”的产品边界。 |

本轮的判断是：保留原型中能帮助业务人员“看懂、改动、验收”的交互，剔除会把 Beta 变成 UE 资产编辑器或安全审批系统的部分。

因此 Beta 采用两层结构：

```text
结构化任务说明
        ↓ 套用模板
动画草稿（对象、动作、时间轴）
        ↓ 人工确认与校验
behavior package
        ↓
A 角语义表现路由
```

## 4. 产品目标

- 建立与业务领域无关的结构化任务说明模型；
- 用模板承载“工序”等领域规则，而不是把领域字段写死；
- 让自动生成结果可见、可编辑、可撤销；
- 产出稳定的 `behavior_id`、槽位、参数、来源元数据和回退契约；
- 用真实三角面、透视、遮挡和光照渐变呈现可旋转、平移、缩放、拾取的 3D mock 资产；mock 几何只用于审阅，不进入导出包。
- 用独立网页小样品验证 B → A 的产品边界和可复制性。

## 5. 范围

### 5.1 说明与模板

- 内置工序流程、装配步骤、状态演示三个模板；
- 面向业务人员的人工填写模板；编辑器将模板内容适配为结构化 JSON，JSON fixture 作为机器输入和回归样例，CSV 解析后置；
- 可选来源信息：说明编号、版本、修订号、来源描述；
- 事项支持名称、类别、顺序、开始条件、依赖、参与对象、结果状态、说明文本和标准引用；
- 模板生成的默认动作必须标记为“草稿”。

### 5.2 动画编辑

- 受控对象树与槽位绑定；
- 可新增对象并填写可选的 `mock_asset` 类型；导出可保留识别标签，但不导出网格、纹理等几何资产；
- 出现、移动、旋转、缩放、等待、闪烁、字幕等基础动作；
- 起止关键帧、可选中间关键帧、时长、缓动、循环；
- 顺序轨道和有限的并行组；
- 可旋转/平移/缩放/拾取的交互 3D 预览，网格、适配、键盘视角控制和播放控制；二维 SVG 只保留为降级层；
- 素材库的逻辑引用和兼容提示。

### 5.3 质量与交付

- 草稿自动保存和手动保存；
- 校验错误、警告和定位提示；
- 当前草稿状态和重新生成前的人工片段保护；
- 导出 `behavior-package-v1.json` 与可读 storyboard 摘要；
- 在导出页展示最小 B → A 调用样例（`behavior_id`、版本、目标槽位、参数、来源和回退）。

## 6. 非目标

- 任意 UE Blueprint / Animation Blueprint 图表生成、反向编辑或自动 Cook；
- 自动解析自然语言、扫描件、OCR 或未经确认的 LLM 推断；
- 自动猜测骨骼、枢轴、模型层级、动作轴或碰撞；
- 生产级灯光、渲染引擎、视频/音频导出和相机时间轴；
- IK、Root Motion、跨 Skeleton 重定向、复杂物理；
- 多人协作、权限、审签和生产发布；
- 用户自定义模板编排、模板注册和生产资产导入（列入后续评估）；
- 直接连接 `test0316`、OntoTwin 主线或 `git-main`。

## 7. 主流程

```text
选择模板/导入说明
    → 确认结构与来源
    → 一键生成动画草稿
    → 绑定对象与素材
    → 时间轴/关键帧调整
    → 交互 3D 预览
    → 校验并修复
    → 保存本地草稿
    → 导出行为包
```

自动生成不覆盖人工确认的动作；重新生成前提示会替换自动片段并警示可能重叠，当前仅保留人工片段，局部重算列入 Beta S2.1。

## 8. 核心数据边界

### 8.1 说明层

业务入口是人工填写的结构化任务说明；适配后的 `animation_spec` 只承载机器可读字段，不描述 UE 内部类名：

- `spec_id`、`title`、`template_id`；
- `source`（来源、版本、修订号）；
- `steps/blocks`（事项顺序、开始条件、依赖、结果状态、目标引用）；
- 可选的领域字段（如 OA 编号、零件号、工位）。

业务人员填写时不需要接触这些字段名，只需提供业务对象、事项、开始条件、结果状态和依赖关系；编辑器负责补齐机器字段与具体表现方式。

### 8.2 行为层

`behavior_package` 描述可执行的表现素材：

- `schema_version`、`package_id`、`behavior_id`、`behavior_version`；
- `source_spec_id`（兼容保留 `source_process_id`）或 `source_block_id`；`process` 顶层字段同样只是 OA 原型兼容别名，通用读取应使用 `spec`；
- `target_slot`、`required_capabilities`；
- `tracks`、`clips`、`keyframes`、`params`、`event_id`、`parallel/parallel_group`；
- `asset_ref`（逻辑资产引用）；
- `fallback`、`validation`、导出范围和对象的 `mock_asset` 识别信息（几何不随包导出）。

行为层不保存 A 角的业务状态判断；A 角以 `behavior_id + 参数` 为核心调用它，并按需读取版本、槽位、能力、来源和回退元数据。

Beta 首期动作字段是闭集：`id/event_id`、`kind/action/type`、`target/target_ref`、`duration_s/duration`、`start_s`、`parallel`、`params/extra`、`asset_ref`、`easing`、`loop`、`enabled`；未列出的输入字段不会自动推断或写入导出包，正式接入前由适配器完成字段映射。

## 9. 状态与边界

以下是目标状态模型；当前 Beta 以 `draft` / `validated` 两个持久化状态落地，“已绑定”“已调整”是界面语义，不另建状态机。

```text
导入
 → 解析待确认
 → 草稿（可生成/可编辑）
 → 已绑定/已调整（界面语义）
 → 已校验
  → 可导出
```

- 缺目标槽位或缺对象逻辑资产：允许占位预览，但不可进入“可导出”；动作级 `asset_ref` 缺省时使用基础原语引用，仍会随校验检查；
- 非法时间、关键帧逆序或未知动作：校验阻断；
- 模板变更：创建新的本地草稿和 `package_id`，不写入主线或覆盖外部资产；
- 浏览器刷新或异常：恢复最近一次草稿；
- 行为能力不兼容：显示原因并提供静态安全回退；依赖关系只做缺失/循环校验和展示，本轮生成仍按输入顺序，不做拓扑调度。

## 10. Beta 验收标准

1. 同一工作台可处理“工序流程”和“装配步骤”两种说明；
2. 每种模板都能生成至少三段可预览动作；
3. 自动生成结果明确标记为草稿，人工调整可保留；时间轴草稿片段以候选样式显示；
4. 对象绑定、动作时长、起止关键帧和字幕在 3D 预览中可见；用户可以拖拽旋转、平移、滚轮缩放、点击拾取对象、适配视图，并看到时间轴动作改变模型姿态/材质/闪烁；
5. 校验能识别未绑定目标、缺少素材、非法时长和关键帧错误；
6. 保存后刷新页面可以恢复草稿；
7. 导出的 `behavior-package-v1` 包含通用 `spec`（并保留旧 OA `process` 兼容别名）、`source_spec_id`、模板、来源、行为 ID、槽位、动作参数、并行信息、对象 `mock_asset` 识别和回退信息；
8. 导出页明确区分行为包与 storyboard 摘要；行为包样例至少包含 `behavior_id`、版本、目标槽位、参数、来源和静态回退；
9. 页面在没有后端和 UE 的情况下可独立运行；
10. 不修改 `frontend/`、`backend/`、`ue_project/` 或主线 Git 状态；本轮新增/修改仅限 `beta/pae`，仓库其它既有工作树变化不在本轮处理。
11. 修改内容或导出设置后旧校验自动失效；重新生成保留人工片段并在界面提示重叠复核。

## 11. 版本策略

- **Beta S2（本轮）**：内置模板、结构化 fixture、基础动作、时间轴、校验、行为包导出；
- **Beta S2.1**：模板复制/自定义模板注册、版本快照/旧版本回退、局部重算、更多动作原语和正式 3D 资产适配器；
- **后续评估**：若行为包契约稳定，再研究受控 UE 执行模板，不直接进入任意蓝图编辑。

## 12. 风险与恢复

- OA/说明只表达意图，不表达精确运动参数：自动结果必须是候选草稿，并要求人工确认；
- 资产命名和对象层级不一致：使用受控槽位与兼容状态，禁止静默错绑；
- 坐标/单位不同：行为包显式声明单位和坐标系；
- 模板或素材更新导致旧行为失效：当前 Beta 只保留本地草稿；版本快照和回退列入 S2.1，避免伪造生产级版本保证；
- 动画被误读为安全操作指导：页面标注“可视化辅助，不替代工艺批准”。
- 程序化 3D 只是可操作 mock 资产：行为包只携带逻辑 `asset_ref` 与可选的 `mock_asset` 识别标签，不携带网格、纹理或 UE 资产；正式执行仍需项目资产适配和验收。

## 13. A 角对接约定（实验）

B 角负责：说明模板、动作素材、行为包和兼容信息。

A 角负责：业务语义归一化、状态优先级和 `behavior_id` 路由。

UE 负责：在项目显式实现、平台默认行为或静态回退路径中执行具体表现。

本 Beta 只提供 JSON 文件和可读摘要，不自动写入 A 角或 UE 工程。Beta 包不是 A 角的 `I3D_Presentation` / `resolution` 主线协议，不能直接注册或喂入实时路由；适配器需要至少完成：`target_slot → slot`、Beta `behavior_id → 受控路由 ID`、`clip.id → event_id`（一次性动作时）、`kind/channel → route channel`、`static_pose → safe_fallback`，并补充 A 角所需的 `source/status/diagnostics`。Beta 时间轴是离线素材/Storyboard，不改变 A 角以实时状态驱动为边界。
