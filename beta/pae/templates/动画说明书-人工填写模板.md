> 给工艺、设备、培训、产品或项目人员填写，不要求具备动画知识。填写的是“任务中发生了什么、先后如何依赖、完成后是什么状态”，不是动画指令。动画编辑器再决定用出现、移动、旋转、字幕或其他表现方式呈现。

## 3. 事项顺序与依赖关系

每一行填写一个业务事项，或一组必须同时发生的事项。默认规则是“上一行完成后开始下一行”。“开始条件”就是该事项的触发依据，“完成后状态”就是编辑器判断是否可以继续的依据。

### 开始条件可以这样写

- 任务开始时
- 上一事项完成后
- 某对象已经到位 / 对齐 / 固定后
- 用户确认后
- 设备进入某状态后
- 与第 X 行同时发生
- 条件不满足时暂停并提示

不确定时填写“待确认”，不要猜时间或技术参数。

### 业务事项可以这样写

- 连杆进入装配基座槽位
- 左侧轴承与中心轴对齐
- 组件完成固定
- 设备进入运行状态
- 向操作人员提示检查结果

避免填写“播放某 clip”“拖动时间轴”“调用某蓝图”等实现语言。

## 5. 例外与约束（可选）

- 条件不满足时怎么处理：暂停 / 提示 / 回到上一事项 / 保持当前状态
- 是否允许跳过某事项：允许 / 不允许 / 待确认
- 是否允许重复执行：不允许 / 允许重复 / 待确认
- 任务结束时必须保持的状态：
- 需要人工确认的业务边界或安全注意点：

## 6. 交给表现编辑器后的处理

编辑器根据对象、事项、开始条件和状态变化，补充表现层信息：

1. 匹配逻辑对象和 3D mock 资产；
2. 将业务事项映射为合适的表现方式；
3. 根据依赖关系安排时间顺序或同时关系；
4. 补充时长、坐标、轴向、关键帧和字幕样式；
5. 生成可调整的表现草稿，由业务人员确认结果。
