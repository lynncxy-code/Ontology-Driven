# OntoTwin 2.3.2 数据集包导入/导出实施说明

## 1. 实施结论

本轮在不修改 `ProjectStore` 文件格式、PostgreSQL 表结构和全局映射规则的前提下，实现了单数据集包导出、导入预检、原子导入和“我的数据集”前端入口。

同时补齐两处绑定项目运行路由：Web 交互运行投影、路线解说音频。实例/资产快照、Overlay、空间帧、分区、漫游和路线原本已经能够按 UE 绑定项目读取。

## 2. 数据集包契约

- 用户文件扩展名：`.otdataset`
- MIME：`application/vnd.ontotwin.dataset-package`
- 当前包格式版本：v1
- 当前项目数据结构版本：沿用 `ProjectStore` v7
- 单包大小上限：64 MB
- 包含逻辑项目快照，不包含 JSON 存储文件或数据库 dump
- 包内完整性信息同时校验清单与项目载荷；包损坏或内容被改写时阻断
- 不执行包内脚本，不在预检时访问外部资源

逻辑项目快照包含语义图谱、类型、构件、实例、实例目录、标定、空间剖面、空间帧、分区、场景交互、漫游路线、Overlay 所需配置、媒体策略和 Web 交互。

导出时会：

- 把来源 UE 绑定转为只读来源说明；
- 清空有效绑定；
- 将实例在线状态重置为离线并移除最后在线时间；
- 移除凭证、令牌、会话字段和 URL 中的敏感认证参数；
- 只保留外部模型、UE 资产、图片、媒体和音频引用，不包含资源二进制；
- 只报告项目依赖的能力接口，不迁移平台级映射规则。

## 3. 接口

| 接口 | 作用 | 是否写入 |
|---|---|---|
| `GET /api/v2/ontology/datasets/{id}/package-summary` | 导出前摘要 | 否 |
| `GET /api/v2/ontology/datasets/{id}/package` | 下载单数据集包 | 否 |
| `POST /api/v2/ontology/dataset-packages/preflight` | 上传并预检 | 否 |
| `POST /api/v2/ontology/dataset-packages/import` | 确认后导入为新数据集 | 是 |

预检检查包身份、格式版本、完整性、项目数据结构版本、核心字段、内部身份、实例到类型的引用、名称冲突、外部资源、内部 URL、本地路径和来源 UE 工程。

## 4. 导入事务边界

1. 完整读取并预检，不写入。
2. 阻断项为零后生成新的外层项目/数据集 ID。
3. 保留类型 RID、实例 ID 和项目内部关系。
4. 写入完整项目快照，不激活、不绑定。
5. 更新“我的数据集”目录。
6. 写入或目录更新失败时撤销本次新项目，原激活项目保持不变。

JSON 存储通过原子文件替换完成整份项目写入；PostgreSQL 通过现有 `ProjectStorePG` 项目事务写入。两者共享同一逻辑包，不要求底层格式一致。

## 5. 绑定项目运行路由

| 能力 | 现状/本轮处理 |
|---|---|
| 实例、模型和资产快照 | 已按 UE 绑定项目读取 |
| Overlay | 已随绑定项目快照解析 |
| 空间帧、分区、漫游、路线 | 已按 UE 绑定项目生成场景运行投影 |
| 路线解说音频 | 本轮改为按 UE 绑定项目查找 |
| Web 交互运行投影与事件 | 本轮改为按 UE 绑定项目读取和归属 |
| Web 配置编辑、UE 写回 | 继续只允许当前激活项目 |

因此，Web 切换当前激活数据集不会改变已经绑定 UE 的只读运行内容；但需要修改配置时，用户仍须先激活对应数据集。

## 6. 前端交互

- 每个非内置数据集行增加“导出数据集包”。
- “导入数据集包”位于“我的数据集”底部、“新建空数据集”下方。
- 文件选择后先显示来源、版本、数量、外部资源、警告和阻断项。
- 预检通过后才开放目标名称与“确认导入”。
- 导入成功后提供“预览图谱”，不自动激活；页面提示由目标 UE 工程主动绑定。
- 所有新增交互沿用页面现有黑白灰按钮、行内提示、加载态和 Toast，不使用原生弹窗。

## 7. 已知边界

- v1 只有完整性校验，不提供数字签名、加密包或权限系统。
- 外部资源实际可用性需要在目标 UE 工程绑定和资源目录同步后最终确认。
- 语音、模型、贴图、媒体和 UE 工程本身不在数据集包内。
- JSON→隔离 PostgreSQL→JSON 的逻辑往返已自动验证；真实业务数据集、目标 UE 工程和跨电脑换机仍需在验收环境执行。
