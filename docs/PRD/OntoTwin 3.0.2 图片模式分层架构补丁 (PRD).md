# OntoTwin 3.0.2 图片模式分层架构补丁 (PRD)

## 1. 背景

3.0 已将坐标标定流程重构为：

```text
解析来源 -> 构件 -> 绑定身份 -> 铸造实例
```

其中“解析来源”可以是 CAD，也可以是平面图图片。二者在产品语义上是一回事：它们都只负责定位“哪里有什么匿名实物”，不直接产生可运维实例。

当前 CAD 模式已经基本按 3.0 运行：标定后进入构件列表，保存构件到当前项目，再去实例绑定台铸造实例。但图片模式仍停留在旧流程：标注后只能导出 CSV，或通过“导入至实例库”直接调用旧接口生成实例。这会绕过构件层，与 3.0 分层架构冲突。

## 2. 目标

1. 图片模式和 CAD 模式统一进入“构件”层。
2. 图片标注中的 ID 只作为设备编号线索，不直接作为实例 ID 铸造实例。
3. 图片标注保存后，构件进入当前项目的 `components`，后续由实例绑定台完成身份绑定和实例铸造。
4. 保留图片模式 CSV 导出作为可选文件导出，不作为主流程。

## 3. 统一术语

以后对外统一表达：

```text
CAD / 图片 / 其他来源 -> 构件 -> 绑定身份 -> 铸造实例
```

- CAD 块属性里的 `EQUIP_ID`：构件上的设备编号线索。
- 图片标注里的 ID：构件上的设备编号线索。
- 绑定台中的身份证号：实例主键。

图片标注 ID 不等于实例已经出生。

## 4. 范围

### 本补丁包含

- 图片模式步骤调整为：
  1. 上传与标定
  2. 标注构件
  3. 保存与导出
- “导入至实例库”改为“保存构件到项目”。
- 图片模式保存构件调用 `/api/v2/coord/save_components`。
- 后端保存构件接口支持 `mode=image` 与图片来源元数据。
- 图片标注类型下拉提交 `ObjectType.rid`，显示 `ObjectType.name`。

### 本补丁不包含

- 不做图片自动识别。
- 不做图片来源和 CAD 来源在同一项目中的多源空间融合。
- 不直接从图片标注铸造实例。
- 不新增数据库表结构。

## 5. 数据规则

图片标注转构件时：

```jsonc
{
  "block_name": "ri.obj.xxx",          // ObjectType rid
  "cad_xy": [pixel_x, pixel_y],        // 兼容旧字段，语义为来源坐标
  "source_xy": [pixel_x, pixel_y],
  "source_mode": "image",
  "attribs": {
    "EQUIP_ID": "用户填写的 ID",
    "LABEL": "用户填写的名称"
  }
}
```

后端保存为 component：

- `frame_id = frame_image`
- `source_mode = image`
- `source_label = image:<文件名>`
- `source_xy = [pixel_x, pixel_y]`
- `cad_xy` 保留兼容，但 UI 不再把它解释为 CAD 坐标
- `bound_instance_id = null`，等待绑定台处理

## 6. 交互规则

图片模式：

1. 上传图片。
2. 添加锚点并填写 UE 坐标，计算变换。
3. 标注构件，选择类型、填写名称和设备编号线索。
4. 进入“保存与导出”。
5. 主操作：保存构件到项目。
6. 可选操作：导出 CSV。
7. 保存成功后提示前往实例绑定台。

## 7. 验收标准

1. 图片模式不再出现“导入至实例库”。
2. 图片模式保存后，绑定台能看到这些构件。
3. 图片标注 ID 出现在构件属性中，可用于绑定台撮合。
4. 未绑定的图片构件不会直接进入实例运维，也不会直接被 UE 渲染。
5. 图片模式 CSV 导出仍可用。
6. CAD 模式原有保存构件流程不退化。
