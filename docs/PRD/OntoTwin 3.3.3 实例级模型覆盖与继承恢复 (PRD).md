# OntoTwin 3.3.3 实例级模型覆盖与继承恢复（PRD）

> 版本：3.3.3  
> 所属主线：OntoTwin Nexus  
> 所属模块：实例运维与监控 / 模型绑定 / UE 运行时同步  
> 父级需求：OntoTwin 3.3 运行时模型加载与 ArtStudio 资产同步  
> 前置需求：OntoTwin 3.3.1 资产模块模型绑定交互补丁、OntoTwin 3.3.2 ArtStudio 移库与资产源切换  
> 状态：已实现  
> 日期：2026-07-28

> 2026-07-28 缺陷复盘修订：模型优先级调整为“实例覆盖 ＞ 类型默认 ＞ 实例原始模型 ＞ 占位模型”；ArtStudio 改为 UE 项目级缓存，统一 PIE 与打包程序链路。

---

## 1. 版本关系

本需求延续 3.3.1 定义的模型绑定关系：

- 本体配置中心负责设备类型的默认模型。
- 类型默认模型用于同类型实例的批量继承。
- 历史 UE 迁移实例可能保留自身模型或复合装配信息。

3.3.2 已用于 ArtStudio 新库迁移，因此本需求顺延为 **3.3.3**。

---

## 2. 背景

当前模型绑定只在本体配置中心按设备类型配置。修改类型默认模型后，该类型下的普通实例统一使用同一个模型。

这种方式适合批量配置，但无法表达以下真实场景：

- 同一类型中，某一台设备因型号、附件或外观差异需要使用另一模型。
- 某个实例需要先配置模型，但所属类型暂时没有默认模型。
- 历史 UE 迁移的复合实例需要单独整体替换外观，同时保留原始装配以便恢复。
- 离线实例需要提前完成配置，等待 UE 重新连接后再自动生效。

实例运维与监控页面已经具备单实例选择、实时状态、位置编辑和运行时控制，但尚无正式、持久的单实例模型配置入口。

---

## 3. 问题定义

用户需要在不改变设备类型默认模型、不影响其他同类型实例的前提下，为当前选中的实例设置独立模型。

系统必须明确回答：

1. 当前实例实际使用哪个模型？
2. 该模型来自类型继承、实例覆盖、历史复合装配，还是占位模型？
3. 修改类型默认模型后，该实例是否继续保留自己的覆盖？
4. 如何清除实例覆盖并恢复正确的继承状态？

---

## 4. 目标

1. 在实例运维与监控页面新增独立的“模型配置”标签页。
2. 支持为当前单个实例设置持久模型覆盖。
3. 模型来源复用本体配置中心现有能力：
   - ArtStudio 公开资产库；
   - ArtStudio“我的资产”；
   - 路径直连，包括本地运行时模型和 UE 已打包资产引用。
4. 明确展示当前有效模型、来源和继承状态。
5. 支持清除实例覆盖：
   - 有类型默认模型时，普通实例和复合实例都恢复类型最新默认模型；
   - 类型未设置默认模型时，复合实例恢复迁移时的原始装配，其余实例显示占位模型。
6. 覆盖保存后通过现有快照轮询和 UE 热更换链路自动生效。
7. 复用实例现有 `render_config` JSONB，不新增数据库列，不改变 ProjectStore 顶层结构。

---

## 5. 非目标

- 本期不支持多实例批量换模。
- 本期不支持复合实例逐部件换模。
- 本期不在实例页面提供“设为类型默认模型”。
- 本期不实现 UE 临时预览后再确认的双阶段协议。
- 本期不新增模型格式转换能力。
- 本期不自动把历史普通实例的冻结模型迁移成显式覆盖。
- 本期不新增权限系统、操作审计表或异步任务队列。
- 本期不修改现有前端页面路由；UE 下载协议增加绑定版本与 UE 项目标识。

## 6. 术语

| 名称 | 含义 |
|---|---|
| 类型默认模型 | 在本体配置中心为设备类型配置的默认模型。 |
| 实例模型覆盖 | 用户为某个具体实例明确保存的独立模型。 |
| 有效模型 | 按优先级解析后，当前实际下发给 UE 的模型。 |
| 继承状态 | 实例未设置独立覆盖，按“类型默认 → 实例原始模型 → 占位模型”解析。 |
| 原始复合装配 | UE 迁移实例保存的 `render_parts` / `assembly_signature` 多部件表现。 |
| 取消实例模型覆盖 | 删除显式实例覆盖，重新按类型默认、实例原始模型或占位模型解析。 |
| 模型可获取 | ArtStudio 绑定已保存；当前 PIE 或打包程序首次使用时下载并写入自身缓存。 |

主界面文案不直接展示 `ObjectType`、`asset_id`、`ue_asset_path`、`render_config` 等技术字段；技术值放入详情折叠区。

## 7. 已决策的核心规则

### 7.1 生命周期

实例模型覆盖是持久配置：

- 保存后写入当前激活项目。
- 后端重启、页面刷新和 UE 重连后仍然有效。
- 只有用户执行“取消实例模型覆盖”才清除。
- 实例离线不阻止保存；重新连接后自动应用。
- 实例重新分类到其他设备类型后，显式覆盖仍然保留。

### 7.2 模型解析优先级

```text
实例 model_override
    > 类型默认模型
    > 原始复合装配
    > 占位模型
```

具体规则：

1. 存在显式实例覆盖时，普通实例和复合实例均使用覆盖模型。
2. 不存在覆盖且类型设置了默认模型时，普通实例和复合实例均实时继承类型当前默认模型。
3. 类型未设置默认模型且实例保存了复合装配时，使用原始 `render_parts`。
4. 实例覆盖、类型默认和实例原始模型都不存在时，使用占位模型。
5. 类型默认模型变化不会清除显式实例覆盖。

### 7.3 恢复规则

- 点击“取消实例模型覆盖”后，优先使用类型当时的最新默认模型。
- 类型没有默认模型时，复合实例重新启用保存的 `render_parts`，其余实例显示占位模型。
- 取消操作只删除 `model_override`，不得删除原始冻结值、迁移来源和装配数据。

### 7.4 类型能力约束

实例所属类型必须具备三维表现能力 `I3D_Representable`。

未启用时：

- “模型配置”显示禁用状态。
- 不允许保存或替换覆盖，但允许清除已有覆盖。
- 提供“前往本体配置中心”的入口。
- 不允许在实例页面自动修改整个类型的能力配置。

### 7.5 无类型默认模型

类型尚未设置默认模型时，仍允许为某个实例保存独立模型。其他同类型实例继续使用占位模型。

### 7.6 历史实例兼容

- 普通实例已有的顶层 `render_config.asset_id` / `ue_asset_path` 不自动视为新覆盖。
- 只有用户通过 3.3.3 页面明确保存后，才创建 `model_override`。
- 历史复合装配继续作为实例固有表现，优先于类型默认模型。
- 不执行批量数据迁移，不修改备份文件。

## 8. 页面与交互设计

### 8.1 页面位置

在实例运维与监控页面右侧工作区增加独立标签：

```text
实时推流 | 实例控制 | 模型配置 | 端点 JSON
```

“模型配置”是正式持久配置，不放入现有“热干预终端”。

### 8.2 页面信息结构

选中实例后，从上到下展示：

1. **当前有效模型**
   - 模型名称或可读标识；
   - 来源；
   - 当前状态；
   - 技术路径详情折叠区。

2. **绑定关系**
   - 当前为“类型默认”“实例已覆盖”“实例原始模型”或“暂无可用模型”；
   - 类型默认模型摘要；
   - 复合实例显示原始装配部件数量。

3. **操作区**
   - `更换此实例的模型`；
   - 存在覆盖时显示 `取消实例模型覆盖`；
   - 类型无三维能力时显示跳转入口。

### 8.3 状态文案

| 状态 | 主文案 | 辅助说明 |
|---|---|---|
| 继承类型 | 继承类型默认模型 | 类型模型变化后，此实例会同步更新。 |
| 实例覆盖 | 此实例使用独立模型 | 类型模型变化不会影响当前实例。 |
| 实例原始模型 | 使用迁移时的原始装配 | 仅在类型未设置默认模型时启用。 |
| 无模型 | 暂无可用模型 | 可以为此实例单独选择模型。 |
| 可获取 | 模型可获取 | 当前 UE 首次使用时下载并缓存。 |
| 离线待同步 | 已保存，等待实例重新连接 | 实例重新连接后自动应用。 |
| 能力未启用 | 当前类型未启用三维表现 | 请先在本体配置中心启用。 |

### 8.4 模型选择器

点击“更换此实例的模型”打开模态，不新建页面路由。选择器复用类型绑定的三个来源：

1. ArtStudio 资产库；
2. 我的资产；
3. 路径直连。

规则：

- “我的资产”复用 3.3.2 的 ArtStudio 账号连接状态。
- 不支持运行时加载的格式保持可见但禁用。
- 选择资产只更新待提交状态，不立即换模。
- 模态支持 Esc、遮罩关闭和关闭后焦点返回。
- 异步加载、搜索和登录均显示明确加载态与就近错误。

### 8.5 应用确认

选择模型后显示变更摘要：

```text
目标实例：Forklift-001
当前模型：叉车标准模型（继承类型）
新模型：叉车加长臂模型（ArtStudio）
影响范围：仅此实例
```

主操作：

```text
应用到此实例
```

用户确认后才持久化。保存过程中按钮显示“正在应用…”并禁用，成功后页面仍保留可继续编辑和恢复入口。

### 8.6 恢复确认

恢复操作使用产品模态，不使用原生 `confirm()`：

- 普通实例说明将恢复类型当前默认模型。
- 复合实例说明将恢复迁移时的多部件装配。
- 确认按钮使用明确动作文案，不使用“确定”。

### 8.7 UI 约束

- 延续现有实例页面结构，不重写页面框架。
- 使用黑、白、灰作为结构色，一个区域只保留一个黑色主按钮。
- 状态色仅用于小面积状态点、左边框或文字。
- 不使用 emoji、原生弹窗和大面积彩色状态卡片。
- 空态、加载态、禁用原因和错误均需有常驻文案。

## 9. 数据设计

### 9.1 存储位置

复用实例现有 `render_config`：

```jsonc
{
  "render_config": {
    "model_override": {
      "schema_version": 1,
      "asset_id": "337876966847811584",
      "ue_asset_path": "artstudio:337876966847811584:v1",
      "source": "artstudio",
      "label": "叉车加长臂模型",
      "revision": 1,
      "updated_at": "2026-07-28T10:00:00Z"
    }
  }
}
```

说明：

- `asset_id`：资产业务标识，超长 ArtStudio id 始终使用字符串。
- `ue_asset_path`：下发前使用的稳定模型标识。
- `source`：`artstudio`、`artstudio_mine`、`local` 或 `ue_cooked`。
- `label`：仅用于产品展示，不参与运行时解析。
- `revision`：实例覆盖的单调递增版本，用于触发增量快照更新。
- `updated_at`：用于状态说明，不实现完整操作审计。

### 9.2 清除规则

取消实例模型覆盖时只删除：

```text
render_config.model_override
```

以下字段不得修改：

- `render_config.render_parts`；
- `render_config.assembly_signature`；
- 历史 `render_config.asset_id` / `ue_asset_path`；
- `source_asset_path`；
- 实例空间状态和其他接口覆盖。

### 9.3 数据库边界

- PostgreSQL 继续使用 `instance.render_config` JSONB。
- JSON ProjectStore 继续把 `render_config` 保存于实例记录。
- 不新增数据库列，不执行 SQL 迁移。
- 不提升 ProjectStore 顶层 `schema_version`；`model_override` 是可选、向后兼容节点。

## 10. 后端设计

### 10.1 模块边界

新增独立模块：

```text
backend/instance_model_binding/
├── api.py
└── service.py
```

职责：

- 读取实例模型绑定摘要；
- 校验并保存显式覆盖；
- 清除覆盖；
- 解析有效模型与来源；
- 复用 ArtStudio、本地模型和 UE 资产的格式校验。

`app.py` 只负责注册路由，不继续堆叠业务实现。

### 10.2 ProjectStore 原子事务

实例模型服务复用现有 `ProjectStore.transact_active(updater)`，不扩充存储模块公开接口。

要求：

- 一次锁内完成读取、修改和持久化。
- 实例不存在时不创建隐式记录。
- 只修改 `render_config.model_override`。
- PostgreSQL 复用现有实例 upsert，不增加专用表。

### 10.3 有效模型解析

建议统一为纯函数：

```text
resolve_effective_instance_model(instance, object_type)
```

返回：

```jsonc
{
  "mode": "instance_override",
  "asset_id": "337876966847811584",
  "ue_asset_path": "artstudio:337876966847811584:v1",
  "source": "artstudio",
  "label": "叉车加长臂模型",
  "is_assembly": false
}
```

当实例覆盖复合装配时，快照不得同时下发旧 `render_parts`；清除覆盖后，先判断类型默认，类型未配置时才重新下发原装配数据。

### 10.4 ArtStudio 交付与缓存

- 保存 ArtStudio 覆盖后立即持久化。
- 快照始终下发 `artstudio:{id}:v{n}` 稳定标识，不替换成本机文件名或空路径。
- PIE 与打包程序通过后端下载代理获取 GLB，并分别写入自身 `Saved/ModelCache`。
- 本机默认后端地址统一使用 `http://localhost:5000`，规避 Docker Desktop 在 Windows 上对 IPv4 回环地址的端口转发冲突；远程部署仍可通过 `-OntoTwinBackendBaseUrl=` 显式覆盖。
- 后端不预取 ArtStudio 模型，不依赖某个 UE 工程映射的 `Models` 目录。
- 同一进程内相同稳定标识只下载一次；多个实例共享结果。
- 缓存采用 `.part` 临时文件、GLB 头与长度校验、原子替换、损坏删除和有限退避重试。
- `v{n}` 是绑定版本和缓存失效键；ArtStudio 原地升版后需显式重新绑定以生成新稳定标识。

## 11. API 契约

### 11.1 获取实例模型配置

```http
GET /api/v2/instances/{instance_id}/model-binding
```

响应示例：

```jsonc
{
  "instance_id": "Forklift-001",
  "object_type_rid": "ri.object.forklift",
  "capability_enabled": true,
  "online": false,
  "binding_mode": "instance_override",
  "model_status": "ready",
  "delivery_status": "waiting_for_instance",
  "effective_model": {
    "label": "叉车加长臂模型",
    "source": "artstudio",
    "asset_id": "337876966847811584",
    "ue_asset_path": "artstudio:337876966847811584:v1"
  },
  "type_default": {
    "label": "叉车标准模型",
    "source": "artstudio"
  },
  "instance_override": {
    "label": "叉车加长臂模型",
    "source": "artstudio"
  },
  "original_assembly": null
}
```

`binding_mode` 枚举：

```text
instance_override | original_assembly | type_default | placeholder
```

`model_status` 枚举：

```text
ready | preparing | failed | capability_blocked
```

`delivery_status` 枚举：

```text
applied | waiting_for_instance | not_applicable
```

### 11.2 保存实例模型覆盖

```http
PUT /api/v2/instances/{instance_id}/model-binding
Content-Type: application/json
```

请求：

```jsonc
{
  "file_number": "337876966847811584",
  "ue_asset_path": "",
  "expected_project_id": "project-001"
}
```

规则：

- 服务端重新查询并校验资产，不信任前端提交的来源和格式。
- ArtStudio 只允许当前运行时支持的 GLB 资产。
- 路径直连沿用类型绑定的本地模型和 `/Game/...` 校验规则。
- `expected_project_id` 与当前激活项目不一致时返回 409，防止页面切换项目后写错实例。
- 实例离线不构成保存失败。
- 类型未启用三维表现能力时返回 409，不自动修改类型。

成功响应：

```jsonc
{
  "status": "saved",
  "binding_mode": "instance_override",
  "model_status": "available",
  "delivery_status": "delivered",
  "message": "已为此实例保存模型覆盖。"
}
```

### 11.3 取消实例模型覆盖

```http
DELETE /api/v2/instances/{instance_id}/model-binding
Content-Type: application/json
```

请求：

```json
{
  "expected_project_id": "project-001"
}
```

成功响应：

```jsonc
{
  "status": "cleared",
  "binding_mode": "type_default",
  "message": "已取消实例模型覆盖，当前跟随类型默认模型。"
}
```

复合实例返回：

```jsonc
{
  "status": "cleared",
  "binding_mode": "original_assembly",
  "message": "已取消实例模型覆盖，当前使用实例原始模型。"
}
```

### 11.4 清除类型默认模型

```http
DELETE /api/v2/object-types/{object_type_rid}/model-binding
```

只清空该类型的 `asset_id` 和 `ue_asset_path`，不卸载三维表现能力，不修改实例覆盖、原始装配或其他接口配置。未设置实例覆盖的实例按“实例原始模型 → 占位模型”回退。

## 12. UE 与快照行为

### 12.1 普通实例

- 无覆盖：快照使用类型最新默认模型。
- 有覆盖：快照使用 `model_override`。
- 清除覆盖：下一轮快照恢复类型最新默认模型。

### 12.2 复合实例

- 无覆盖且类型有默认模型：快照下发类型默认单模型，不下发 `render_parts`。
- 无覆盖且类型没有默认模型：快照下发 `render_parts` 和 `assembly_signature`。
- 有覆盖：快照只下发覆盖后的单模型，不下发 `render_parts`。
- 清除覆盖：下一轮快照先按类型默认解析，类型未配置时恢复原始复合装配。

### 12.3 热更换

- 模型稳定标识变化后，复用现有 UE `asset_id` 变化检测和热重载机制。
- 下载请求附带绑定版本和 UE 项目标识；后端校验项目绑定与 ArtStudio 当前版本。
- 增量快照必须将有效模型变化识别为实例更新。
- ArtStudio 冷缓存由 UE 异步下载；同一稳定标识的所有等待实例在缓存原子落盘后切换到正式模型。

## 13. 异常与并发规则

| 场景 | 行为 |
|---|---|
| 实例不存在或已删除 | 返回 404，不写入。 |
| 当前项目已切换 | 返回 409，提示刷新后重试。 |
| 类型未启用三维表现能力 | 返回 409，引导前往本体配置中心。 |
| ArtStudio 未登录且选择“我的资产” | 保持 3.3.2 账号连接提示，不保存。 |
| 资产不存在或格式不支持 | 就近显示错误，不改变原有效模型。 |
| ArtStudio 下载失败 | 覆盖保持已保存；UE 保留占位模型并有限退避重试，损坏缓存不会进入正式文件。 |
| 实例离线 | 保存成功，状态为等待实例重新连接。 |
| Type 默认模型同时变化 | 显式实例覆盖不受影响。 |
| 实例重新分类到支持三维表现的 Type | 显式覆盖保留；清除后再继承新 Type。 |
| 实例重新分类到未启用三维表现的 Type | 覆盖数据保留但不下发，状态为 `capability_blocked`；允许清除，不允许保存新覆盖。 |
| 清除不存在的覆盖 | 幂等成功，返回当前实际继承状态。 |

## 14. 验收标准

### 14.1 页面与选择

1. 实例运维与监控页面新增“模型配置”标签页。
2. 未选择实例时显示明确空态，不展示可误操作按钮。
3. 页面能区分类型继承、实例覆盖、原始装配和占位模型。
4. 模型选择器包含 ArtStudio 资产库、我的资产和路径直连。
5. 选择模型后不会立即生效，必须点击“应用到此实例”。
6. 变更摘要明确显示目标实例、当前模型、新模型和“仅此实例”。
7. 页面不提供“设为类型默认模型”。
8. 本期不存在多实例批量换模入口。

### 14.2 继承与持久化

9. 普通实例保存覆盖后，其他同类型实例不受影响。
10. 后端重启和 UE 重连后，实例覆盖仍然有效。
11. Type 默认模型变化时，覆盖实例保持自己的模型，继承实例同步更新。
12. 普通实例清除覆盖后，使用 Type 当时的最新默认模型。
13. Type 没有默认模型时，允许实例设置覆盖；清除后恢复占位模型。
14. 实例重新分类后显式覆盖保留；新 Type 未启用三维表现能力时不下发模型，并显示能力阻塞状态。
15. 普通历史实例不会因为已有冻结 `render_config` 自动变成覆盖状态。

### 14.3 复合实例

16. 复合实例可以用单模型整体覆盖。
17. 覆盖期间快照不再下发原 `render_parts`。
18. 原始 `render_parts` 和 `assembly_signature` 未被删除或改写。
19. 清除覆盖后，有类型默认时使用类型默认；类型未配置时原始复合装配在下一轮快照恢复。
20. 本期不提供逐部件换模。

### 14.4 状态与失败

21. ArtStudio 模型显示“可获取”；PIE 与打包程序冷缓存时自动下载，完成后热切换。
22. 打包程序首次运行把 GLB 写入该程序的 `Saved/ModelCache`；使用同一用户目录再次运行时命中缓存，不重复下载。
23. 离线实例允许保存，并显示“等待实例重新连接”。
24. 类型未启用三维表现能力时禁止保存，并提供本体配置入口。
25. 无效资产、错误格式和项目切换冲突均不覆盖原配置。
26. 恢复操作使用产品模态，不使用原生 `confirm()`。

### 14.5 存储与回归

27. 实例覆盖只写入 `render_config.model_override`。
28. PostgreSQL 不新增列，ProjectStore 顶层结构不变。
29. 类型默认模型绑定、ArtStudio 登录、“我的资产”和路径直连能力不受影响。
30. 现有实例状态控制、位置微调、信息面板和端点 JSON 功能不受影响。
31. UE 无需新增接口，现有全量/增量快照均能识别模型变化。

## 15. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 实例覆盖与历史冻结值混淆 | 大量实例意外脱离类型继承 | 只识别显式 `model_override`。 |
| 复合实例覆盖时仍下发部件 | UE 同时出现单模型与原装配 | 覆盖生效时明确抑制 `render_parts`。 |
| 清除覆盖误删装配数据 | 历史迁移表现不可恢复 | 清除仅删除 `model_override` 节点。 |
| ArtStudio 大模型下载慢 | UE 暂时显示占位模型 | UE 共享一次下载，原子缓存后通知全部等待实例。 |
| 多实例同时下载同一模型 | 重复流量或缓存互相覆盖 | 按后端地址与稳定标识做进程级去重。 |
| 下载中断留下损坏文件 | 后续持续显示占位模型 | `.part` 写入、GLB 校验、原子替换、损坏删除和退避重试。 |
| 页面切换项目后继续提交 | 覆盖写入错误项目 | 请求携带并校验 `expected_project_id`。 |
| 单实例页面误触发类型修改 | 影响同类型全部实例 | 实例页不提供 Type 修改或提升入口。 |
| 技术字段过多 | 运维人员难以理解 | 主界面使用继承、覆盖、原始装配等产品文案。 |

## 17. Grill-me 决策记录

| 决策项 | 结论 |
|---|---|
| 覆盖生命周期 | 持久覆盖。 |
| 复合实例 | 允许单模型整体替换，不做逐部件覆盖。 |
| 模型来源 | 复用完整模型选择器。 |
| 批量能力 | 本期仅单实例。 |
| Type 默认变化 | 保留显式实例覆盖。 |
| Type 无默认模型 | 允许实例单独绑定。 |
| 存储位置 | `render_config.model_override`。 |
| 页面位置 | 独立“模型配置”标签页。 |
| 复合实例回退 | 类型默认优先；类型未配置时恢复原始复合装配。 |
| 应用方式 | 选择后查看摘要，再明确应用。 |
| ArtStudio 交付 | 立即保存稳定标识，由当前 UE 项目或程序首次使用时下载并缓存。 |
| 三维能力未启用 | 禁止保存并引导到本体配置中心。 |
| Type 提升入口 | 实例页面不提供。 |
| 历史普通冻结值 | 不自动迁移为覆盖。 |
| 离线实例 | 允许保存，重连后生效。 |
| 实例重新分类 | 保留显式实例覆盖。 |
