# OntoTwin 3.3.4 — Nexus 直传 ArtStudio 模型资产（PRD）

> 版本：3.3.4
> 所属主线：OntoTwin Nexus
> 所属模块：资产中台 / 类型模型绑定 / 实例模型覆盖
> 前置版本：3.3.2 ArtStudio 资产源切换、3.3.3 实例级模型覆盖
> 状态：开发中
> 日期：2026-08-26

---
## 1. 背景

当前用户可以在 OntoTwin 中浏览 ArtStudio 公共资产和“我的资产”，但新模型仍需先打开 ArtStudio 完成上传，再返回 OntoTwin 刷新和选择，打断了类型配置与实例换模流程。

3.3.4 在 OntoTwin 的既有模型选择器中增加 GLB 上传能力，并在浏览器端为模型生成默认封面。OntoTwin 只提供上传入口和流程编排，ArtStudio 继续保存文件、资产元数据、封面、所有权和可见性；UE 继续使用现有稳定标识、下载代理和运行时缓存，不新增本地资产真源。

## 2. 已确认决策

1. 上传入口同时出现在类型模型选择器和实例模型选择器的“我的资产”区域。
2. 上传时可以选择“公共资产”或“私人资产”，默认选择公共资产。
3. 公共资产不走审核：创建成功后立即上架并进入公共资产库。
4. 私人资产仅当前 ArtStudio 用户可见，不进入公共资产库。
5. 上传成功后自动切换到“我的资产”并选中新资产。
6. 上传成功不自动绑定。类型页面仍需点击绑定动作；实例页面仍需点击“应用到此实例”。
7. 第一版只支持单个、自包含的 GLB，不做格式转换。
8. 上传时自动按模型包围盒生成一张 512×512 默认视角封面；封面失败不阻断模型上传。

## 3. 目标

- 用户不离开 OntoTwin 即可上传模型到 ArtStudio。
- 公共/私人可见性在提交前清晰可选。
- 公共资产上传完成后直接处于已上架状态，不进入征集或审核状态。
- 上传结果无缝进入既有类型绑定和实例覆盖流程。
- 上传失败不改变当前类型或实例的有效模型。

## 4. 非目标

- 不建立 OntoTwin 本地模型库，不把上传文件写入 ProjectStore。
- 不支持 `.gltf + .bin + 贴图` 多文件组合。
- 不支持 FBX、OBJ、USD、Blender 等格式转换。
- 不生成多角度渲染图、线框图或人工精修封面；本期只生成单张默认视角封面。
- 不实现批量上传、上传历史、完整资产编辑和资产删除。
- 不改变 UE 快照、稳定标识和运行时下载协议。

## 5. 用户流程

### 5.1 类型默认模型

1. 用户进入本体配置中心并选择具备三维表现能力的类型。
2. 在“模型绑定 → 我的资产”点击“上传模型”。
3. 选择 GLB，填写名称和可选描述，选择公共或私人。
4. 点击“上传公共模型”或“上传私人模型”。
5. 上传成功后窗口关闭，“我的资产”刷新并自动选中新资产。
6. 用户明确点击现有绑定动作后，才修改类型默认模型。

### 5.2 实例模型覆盖

1. 用户在实例控制中打开“更换此实例的模型”。
2. 在“我的资产”点击“上传模型”并完成上传。
3. 新资产被自动选中，底部“待应用”显示新资产。
4. 用户点击“应用到此实例”后，才保存实例覆盖。

## 6. 可见性与发布规则

| 选择 | ArtStudio ownerType | visibility | 创建后状态 |
|---|---:|---:|---|
| 公共资产 | USER（2） | PUBLIC（1） | 立即调用上架接口，必须为 LISTED（2） |
| 私人资产 | USER（2） | USER_PRIVATE（4） | 仅本人可见，不调用上架接口 |

公共上架失败属于部分失败：文件和资产记录可能已创建，但产品不得显示“公共上传成功”。响应必须携带已创建资产摘要，界面就近说明“资产已创建，但公共上架失败”，且不得自动绑定。

## 7. 文件规则

- 单文件，扩展名必须为 `.glb`。
- GLB 魔数必须为 `glTF`，版本必须为 2。
- 文件头声明长度必须等于实际长度。
- 默认最大 500 MB，通过 `ARTSTUDIO_UPLOAD_MAX_MB` 配置。
- 名称必填，最大 64 个字符；默认取去除 `.glb` 的文件名。
- 描述可选，最大 1000 个字符。
- MIME 固定为 `model/gltf-binary`。
- 服务端计算 SHA-256，并复用 ArtStudio 去重、单文件或分片上传协议。

## 8. 后端设计

新增独立模块：

```text
backend/artstudio_upload/
├── __init__.py
├── api.py
└── service.py
```

新增接口：

```http
POST /api/v2/assets/uploads
Content-Type: multipart/form-data
```

字段：

```text
file        GLB 文件，必填
cover       浏览器生成的默认 JPEG 封面，选填；生成失败时省略
name        资产名称，必填
description 描述，选填
visibility  public | private，必填
```

后端流程：

1. 校验同源请求和 ArtStudio 登录身份。
2. 流式写入系统临时文件，同时计算 SHA-256 和大小。
3. 校验 GLB 文件头和声明长度。
4. 浏览器使用 Three.js 计算模型包围盒并生成默认视角 JPEG 封面；失败时继续第 5 步。
5. 调用 ArtStudio `/asset-uploads/init`，分别上传模型和封面文件。
6. 按上游结果执行去重、单文件 PUT 或分片 PUT。
7. 调用完成接口取得 `fileId`。
8. 调用 `/assets` 创建 3D 模型资产，并在上游支持时写入 `coverFileId`。
9. 公共资产调用 `/assets/{id}/list` 立即上架。
10. 返回与现有 `/api/v2/assets` 列表兼容的资产摘要；若返回 `coverUrl`，前端立即显示封面。
11. 无论成功失败均清理本地临时文件，日志不得记录 Token 或预签名地址。

成功响应：

```json
{
  "status": "created",
  "visibility": "public",
  "listing_status": "listed",
  "asset": {
    "file_number": "123456789",
    "name": "叉车模型",
    "format": "GLB",
    "formats": ["GLB"],
    "bindable": true,
    "cover_url": "",
    "current_version": 1
  }
}
```

## 9. 前端规则

- 只在已连接 ArtStudio 的“我的资产”区域显示“上传模型”。
- 使用产品模态，不使用 `alert()`、`confirm()` 或 `prompt()`。
- 模态支持 Esc、遮罩关闭和关闭后焦点返回；上传期间禁止关闭。
- 公共/私人使用单选卡片，公共默认选中。
- 主按钮文案随选择变化：“上传公共模型”或“上传私人模型”。
- 显示“检查文件 → 上传到 OntoTwin → 发布到 ArtStudio”阶段状态。
- 错误在模态内就近显示；成功使用 toast。
- 上传成功后自动选中，不触发类型或实例绑定请求。

## 10. 异常与安全

| 场景 | 行为 |
|---|---|
| 未连接 ArtStudio | 阻止上传并引导连接账号。 |
| 非 GLB、损坏或超限 | 422/413，就近显示原因。 |
| ArtStudio 去重命中 | 复用文件对象，仍创建新的资产记录。 |
| 上游上传失败 | 不创建资产，不修改绑定。 |
| 资产创建成功但公共上架失败 | 返回部分失败和资产摘要，不宣称公共上传成功。 |
| 浏览器跨源写请求 | 403。无 Origin 的本机脚本仍允许调用。 |
| 重试 | 未确认完成前允许重新提交；不得复用过期预签名地址。 |

## 11. 验收标准

1. 两个模型选择器均能从“我的资产”打开上传模态。
2. 用户可选择公共或私人，默认公共。
3. 合法 GLB 上传后出现在“我的资产”并被自动选中。
4. 合法 GLB 上传后生成默认视角封面；无法生成时模型仍可正常上传。
5. 公共资产立即出现在公共资产库，状态为已上架，不进入审核。
6. 私人资产不会出现在其他账号或公共资产库中。
7. 上传成功不会自动修改类型默认模型或实例覆盖。
8. 用户后续明确应用后，现有绑定服务生成正确稳定标识并由 UE 加载。
9. 非 GLB、损坏 GLB、超限文件、登录失效和上游失败均不覆盖原绑定。
10. 页面无原生弹窗、emoji 或大面积语义色块。
11. ProjectStore、PostgreSQL 表结构、快照协议和 UE 插件无需迁移。
