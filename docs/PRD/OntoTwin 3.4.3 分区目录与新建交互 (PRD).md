# OntoTwin 3.4.3 分区目录与新建交互 (PRD)

> 状态：已实施  
> 日期：2026-08-18  
> 主线：3.4 分区登记与实例路由  
> 关联：3.8/3.8.2 使用分区完成页面解析、业务范围与 UE 场景联动

## 1. 背景

3.4 已定义项目级分区目录、实例 `zone_id`、分区层级和 `ue_level`，当前后端也已具备分区目录保存与实例批量分配接口。但 Web“实例运维与监控 → 分区管理”仍把“目标分区 ID”暴露为自由文本。

这会造成三个问题：

1. 用户看见“能源区”，直接输入同名中文，实际新建了 `zone_id=能源区` 的临时分区，而项目中可能已经存在 `zone_id=scc_w19_1f_energy、name=能源区` 的正式分区。
2. UE 按稳定 ID 区分两者，只能显示为“能源区”和“能源区（能源区）”，看起来像重复项。
3. 自由输入产生的分区只有 ID，没有类型、上级分区和 UE Level，不能表达完整空间层级。

因此 3.4.3 将“选择已有分区”和“新建正式分区”拆成两个明确动作，禁止在实例分配动作中通过随意输入隐式创建分区。

## 2. 目标

- 用户分配实例时从已有分区中选择，不需要记忆或手敲 ID。
- 用户可以在分区管理弹窗内新建正式分区。
- 分区名称与分区 ID 分离：名称服务于人，ID 服务于接口和 UE。
- 新分区可表达楼栋、楼层、房间、区域四种类型及父子关系。
- `UE Level` 保留为可选高级设置，不干扰常用流程。
- 沿用现有项目 `zones` 数据和接口，不修改 `ProjectStore` 存储格式。

## 3. 编号说明

本功能编号为 **3.4.3**，原因如下：

- 分区登记表、`zone_id → ue_level` 和实例分区路由首次定义于 3.4。
- 3.4.1、3.4.2 已用于该主线的历史迁移与实例位置补丁。
- 3.8/3.8.2 是分区数据的业务交互消费者，不应承担分区目录的基础维护能力。

## 4. 产品边界

### 4.1 本期包含

- 在现有“分区管理”弹窗中增加“新建分区”入口。
- 新建字段：分区名称、分区 ID、类型、上级分区、UE Level。
- 实例分配目标由自由输入改为已有分区选择。
- 分区列表同时显示名称和稳定 ID，名称相同时仍可区分。
- 创建成功后自动选中新分区，但不自动移动实例；用户确认“应用分区”后才写入实例。
- 明确标识历史上由实例引用推导、但尚未登记到目录的分区。

### 4.2 本期不包含

- 分区重命名、修改 ID、删除和拖拽调整层级。
- 自动扫描或校验 UE 工程内的 Level 资产。
- Level Streaming、Data Layer、World Partition 或首次加载优化。
- 在 F8 业务编辑中修改实例分区。
- 将历史临时分区自动迁移为正式分区。

## 5. 信息模型

| 用户字段 | 存储字段 | 规则 |
| --- | --- | --- |
| 分区名称 | `name` | 必填，面向用户展示；允许中文，去除首尾空格 |
| 分区 ID | `zone_id` | 必填、项目内唯一、创建后不可修改；1–128 位，仅允许英文字母、数字、`_ . : / -` |
| 类型 | `level` | 必填：`building / floor / room / area` |
| 上级分区 | `parent_zone_id` | 楼栋为空；其他类型必填，并引用已登记分区 |
| UE Level | `ue_level` | 可选；高级设置；保存 UE Level 资产路径 |

### 5.1 ID 约定

ID 是稳定技术主键，不使用会随文案变化的中文名称。推荐使用项目、楼层和用途组成的小写英文标识，例如：

```text
scc_w19_building
scc_w19_1f
scc_w19_1f_energy
scc_w19_1f_quality_lab
```

显示名称可以分别为“SCC W19 厂房”“1F”“能源区”“质量实验室”。

### 5.2 类型与上级分区

- 楼栋：项目根级，不选择上级分区。
- 楼层：上级分区应为楼栋。
- 房间：上级分区应为楼层。
- 区域：上级分区应为楼层或房间。

前端按上述规则缩小候选范围；后端继续执行父节点存在、无循环、实例只能绑定叶子分区等基础校验。

## 6. 交互设计

### 6.1 分区管理主弹窗

弹窗仍由两部分组成：

1. 上半区按当前分区和设备类型筛选、勾选实例。
2. 下半区选择目标分区并应用。

目标分区区域调整为：

- 下拉框：显示“分区名称”，辅显分区 ID 和实例数量。
- “新建分区”次按钮：打开新建表单。
- “应用分区”主按钮：仅在已选择实例和有效叶子分区时可用。
- “解除分区”保持为独立次操作。

未登记分区仍出现在“当前分区”筛选和实例现状中，并标记“未登记”；它不作为新的分配目标，避免继续扩大脏数据。

### 6.2 新建分区表单

默认显示：

- 分区名称
- 分区 ID
- 类型
- 上级分区

“高级设置”折叠区中显示：

- UE Level

交互规则：

- 打开后聚焦“分区名称”。
- 选择“楼栋”时，上级分区禁用并清空。
- 其他类型没有合适上级分区时，明确提示先创建上级分区。
- ID 格式错误、ID 重复、名称为空时就近显示错误。
- 保存期间禁用重复提交，成功后关闭表单并在主弹窗中选中新分区。
- `Esc` 关闭新建表单并返回主弹窗；未提交内容不影响当前实例选择。

### 6.3 创建与分配分离

“创建分区”只写入项目分区目录，不移动任何实例。创建成功后：

1. 新分区成为当前目标分区。
2. 用户仍可检查已选实例和覆盖数量。
3. 用户点击“应用分区”后，实例的 `zone_id` 才发生变化。

该规则避免“创建”产生用户未确认的批量移动。

## 7. 接口与数据流

### 7.1 读取分区目录

```http
GET /api/v2/zones
```

每个条目应提供：

- `id`
- `name`
- `level`
- `parent_zone_id`
- `ue_level`
- `streaming`
- `instance_count`
- `registered`：是否正式登记在项目分区目录

### 7.2 保存正式分区

沿用：

```http
PUT /api/v2/zones/catalog
```

前端读取当前正式目录，追加新分区后整体提交，并携带 `expected_project_id`。保存不得把仅由实例推导出的未登记分区误写入正式目录。

### 7.3 分配实例

沿用：

```http
PUT /api/v2/zones/assignments
```

新 UI 只提交用户选择的已登记叶子分区 ID。后端继续兼容旧数据和旧客户端，不在本期强制删除已有中文临时 ID。

## 8. 异常与兼容

| 场景 | 处理 |
| --- | --- |
| ID 已存在 | 分区 ID 输入框就近报错，不覆盖原分区 |
| 名称重复、ID 不同 | 允许；下拉同时显示 ID 以区分 |
| 上级分区已被其他请求删除 | 保存失败并刷新目录 |
| 激活项目在保存期间切换 | 返回冲突，不向新项目写入 |
| 新建分区是非叶子节点 | 可建立层级，但不能作为实例分配目标 |
| 历史未登记分区 | 可筛选、可将其中实例迁出，不允许继续作为新目标 |
| UE 未配置对应 Level | 分区仍可用于业务和显隐；不承诺关卡流送 |

## 9. 验收标准

- [ ] “分区管理”不再要求用户直接输入目标分区 ID。
- [ ] 可从已有正式叶子分区中选择目标并批量应用。
- [ ] “新建分区”包含名称、ID、类型、上级分区和高级设置中的 UE Level。
- [ ] 楼栋不要求上级分区；其他类型必须选择符合类型的上级分区。
- [ ] ID 为空、格式错误或重复时不能提交，并显示就近错误。
- [ ] 创建成功后分区进入正式目录、自动成为目标，但实例仍未移动。
- [ ] 点击“应用分区”后所选实例才更新，UE 下一轮运行投影可读取新目录。
- [ ] 分区下拉以名称为主、ID 为辅，不再产生“把名称误当 ID”的路径。
- [ ] 未登记分区有明确标记，并可将实例迁移到正式分区。
- [ ] 创建或分配期间切换项目不会误写其他项目。
- [ ] 前端无原生 `alert/confirm/prompt`，支持加载态、Esc 和焦点返回。

## 11. 实施结果（2026-08-18）

- Web 分区管理的目标输入已改为正式叶子分区下拉。
- 新增“新建分区”表单及名称、稳定 ID、类型、上级分区和高级 UE Level 字段。
- 分区摘要增加 `registered` 标识，并补齐正式/未登记分区的统一展示字段。
- 正式目录保存接口校验稳定英文 ID；实例分配接口保留历史中文 ID 兼容性，便于迁移旧数据。
- 新建分区与实例分配保持两个独立确认动作。
- 后端分区管理单元测试 7 项通过；前端脚本语法和浏览器关键交互通过。
