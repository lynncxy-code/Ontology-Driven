# OntoTwin 4.0.1 人物出生规则补充设计（PRD）

> 状态：已确认，进入实施  
> 日期：2026-07-21  
> 归属：OntoTwin Nexus / 场景交互 / 人物漫游  
> 基线：《OntoTwin 4.0.1 配置驱动人物漫游闭环（PRD）》

---

## 1. 文档目的

本补充设计修正人物漫游页仍要求配置人员选择 UE 关卡出生锚点的问题，使人物出生位置与 4.0.1 已完成的项目空间底图、路线编辑和坐标投影链路保持一致。

已确认的产品规则：

1. 当前项目存在已启用、已就绪且可运行的默认项目路线时，人物优先从路线第一个有效点出生。
2. `auto_start` 只决定出生后是否立即沿路线行走，不改变出生位置。
3. 当前项目未启用默认路线，或项目明确不需要路线时，配置人员必须在已发布空间底图上手动设置一个出生点及朝向。
4. 已配置但处于待复核、不可用或缺失状态的默认路线属于配置错误，不得静默回退到手动出生点。
5. UE 关卡出生锚点不再作为业务配置人员的主入口，只保留旧项目兼容和开发回退能力。

本设计覆盖 4.0 与 4.0.1 中“人物出生锚点由 UE 项目维护”的旧交互，但不改变人物资产、皮肤、摄像机、路线点和 Overlay 的既有边界。

---

## 2. 用户与交付边界

主要用户仍是 OntoTwin 配置编辑人员，而不是 UE 项目集成人员。

因此：

- 正常配置人物出生位置不得要求打开 UE 编辑器、放置 Actor 或修改关卡。
- Web 页面关闭后，后端与 UE EXE 仍按已保存配置运行。
- UE 编辑器中的 `ATwinRoamingSpawnAnchor` 只服务旧项目兼容、开发调试和故障诊断。
- 人物出生点不是业务实例，不进入 OntoTwin Instance 列表，也不保存人物实时位置。

---

## 3. 核心规则

### 3.1 有效默认路线

同时满足以下条件时，默认路线可决定人物出生位置：

- 人物配置中的默认路线开关已启用。
- 选择的是当前激活项目中的项目路线，而不是仅存在于 UE 资源目录中的测试路线。
- 路线 `enabled = true`。
- 路线 `review_state = ready`。
- 路线至少包含两个有效点。
- 路线引用的空间底图仍为已发布状态，标定指纹一致。
- 路线绑定的 UE 项目、Level 和楼层与当前运行客户端一致。

满足条件后：

- 人物出生 XY 使用路线第一个有效点。
- 初始朝向使用路线第一段方向。
- Z 使用路线对应楼层地面基准，并由 UE 对路线起点执行可行走地面检测。
- `auto_start = true` 时出生后立即开始路线。
- `auto_start = false` 时人物停在路线起点，等待人工操作或后续开始命令。

### 3.2 无默认路线

以下情况进入手动出生点模式：

- 默认路线开关明确关闭。
- 未选择默认路线，且用户保存的是“项目不使用默认路线”的有效配置。

手动出生点必须包含：

- 已发布空间底图 `frame_id`。
- 图片像素位置 `source_px`。
- 规范空间位置 `canonical_position_mm`。
- 人物朝向 `yaw_deg`。
- 当前标定指纹 `calibration_fingerprint`。

手动打点只编辑 XY 和朝向，不允许在画布逐点输入 Z。Z 继承空间底图的楼层地面基准，并由 UE 向下检测实际地面。

### 3.3 路线异常

当用户已启用并选择默认路线，但路线进入 `needs_review`、`invalid`、被删除或绑定不匹配时：

- Web 显示明确错误和处理入口。
- “保存并应用”不可用于提交一份看似正常、实际会静默换出生来源的配置。
- UE 不自动使用旧手动点继续运行。
- 用户必须复核路线，或显式关闭默认路线后配置手动出生点。

### 3.4 可逆性

- 启用有效路线时，不删除项目中已保存的手动出生点。
- 以后显式关闭默认路线时，原手动点可以重新显示并继续编辑。
- 如果项目从未保存过手动点，关闭路线后必须先完成打点才能保存。
- 更换手动点所引用的空间底图会使原点位失去语义，前端必须二次确认后才清空点位。

## 4. 前端信息架构

人物漫游继续使用现有三栏工作台，不新增路由或顶部页签。

```text
左栏                    中栏：出生与默认路线                 右栏
人物选择                默认路线配置                         UE 运行状态
皮肤选择                当前出生来源                         移动参数
                        空间底图画布                         视角参数
                        楼层 / 朝向 / 校验状态               保存并应用
```

### 4.1 中栏顶部：默认路线配置

将当前右栏底部的“默认路线”区域移动到中栏顶部，包含：

- 启用默认路线。
- 默认路线选择。
- 进入后自动开始。
- 到达终点行为。
- 当前路线状态。

选择变化后，中栏画布立即切换对应呈现，不需要先保存。

### 4.2 有效路线画布

显示内容：

- 路线绑定的已发布空间底图。
- 完整路线的浅灰连线和方向。
- 高亮的第一个路线点。
- “从路线起点出生”状态点与文字。
- 路线名称、空间底图、楼层和标定状态。
- “编辑该路线”按钮。

人物漫游页中的路线画布为只读。路线点位置只能在“漫游路线”页面修改，避免两个页面同时成为路线事实来源。

### 4.3 手动出生点画布

显示内容与交互：

- 选择当前项目已发布空间底图。
- 使用与漫游路线相同的 `SpatialCanvas` 坐标、显示矩阵、缩放和平移能力。
- 鼠标左键设置或移动单个出生点。
- 拖动方向箭头调整人物朝向。
- 鼠标滚轮缩放。
- 中键、右键或 `Alt + 左键` 平移。
- “适应视图”和网格显示控制。
- 显示空间底图、楼层、朝向、标定状态和 UE 地面基准。

旧的静态 `contain` 出生点画布不得恢复使用；它不支持路线画布已具备的显示矩阵、缩放和平移，会重新产生两套坐标认知。

### 4.4 空状态与错误状态

- 无已发布空间底图：显示说明和“去发布空间底图”按钮。
- 尚未打点：显示画布操作提示，并在保存区就近显示“请设置人物出生点”。
- 路线待复核：显示状态点、原因、“去复核路线”和“关闭默认路线”入口。
- 图片加载失败：画布保留错误说明，使用 Toast 反馈，不使用原生弹窗。

### 4.5 视觉与交互规范

继续遵循 `ontotwin-ui`：

- 黑白灰结构色，语义色只用于小状态点、边线和错误文字。
- 一个区域最多一个黑色主按钮。
- 显式“保存并应用”，保存后仍可继续编辑。
- 切换会清空点位的操作使用模态确认。
- 加载、空状态和失败状态必须有可操作反馈。
- 禁止原生 `alert`、`confirm`、`prompt` 和 emoji。

## 5. 前端状态机

| 条件 | 有效出生来源 | 画布 | 保存条件 |
| --- | --- | --- | --- |
| 已启用有效项目路线 | 路线起点 | 路线只读预览 | 路线仍为 `ready` |
| 已关闭默认路线 | 手动出生点 | 单点可编辑 | 已发布底图 + 有效点位 |
| 默认路线未选择 | 手动出生点 | 单点可编辑 | 已发布底图 + 有效点位 |
| 已选择路线但待复核/无效 | 阻断 | 错误状态 | 不允许保存为可运行配置 |
| 没有已发布底图且无路线 | 缺失 | 空状态 | 不允许启用人物漫游 |
| 旧 `ue_anchor` 配置 | 兼容态 | 迁移提示 | 有路线则使用路线；无路线需补手动点 |

“有效出生来源”是派生状态，不由用户手工选择一个技术枚举。

## 6. 数据与兼容策略

### 6.1 不新增 ProjectStore 顶层结构

手动出生点沿用现有 `scene_interactions.roaming.config.spawn` 图片模式：

```json
{
  "spawn": {
    "mode": "image",
    "frame_id": "frame-...",
    "source_px": {"x": 640.0, "y": 480.0},
    "canonical_position_mm": {"x": 12000.0, "y": 8000.0},
    "yaw_deg": 90.0,
    "calibration_fingerprint": "sha256:..."
  }
}
```

路线起点是运行时派生的优先出生来源，不复制为另一份手动点，不保存固化 UE 世界坐标。

### 6.2 旧配置

- `spawn.mode = image`：恢复为可编辑手动点，不再标记为保存后必然丢弃的 legacy 数据。
- `spawn.mode = ue_anchor` 且存在有效项目路线：运行时使用路线起点，旧锚点仅保留兼容信息。
- `spawn.mode = ue_anchor` 且没有有效项目路线：Web 要求用户在空间底图上补充手动点；不静默伪造坐标。
- 不自动删除资源目录中的人物出生锚点。

## 7. 运行投影规则

运行配置生成优先级：

```text
有效项目默认路线起点
    ↓ 不存在
已验证的手动空间底图出生点
    ↓ 仅兼容/开发环境
UE 出生锚点
```

正式业务配置只允许前两级。

当有效项目路线存在时，运行投影应使 `spawn_ue` 指向路线起点。人物出生角度取第一段路线方向。UE 构建动态路线后再次以实际 Spline 起点和地面检测结果校正出生 Transform。

`auto_start` 不参与出生来源选择，只参与人物出生后的路线状态。

---

## 8. 校验规则

### 8.1 有路线

- 路线必须存在、启用、已就绪且至少两个点。
- 路线空间底图必须已发布且标定指纹一致。
- 不要求另行配置手动出生点。
- 路线异常时阻断运行投影，不静默回退。

### 8.2 无路线

- 必须引用已发布空间底图。
- `source_px` 必须位于图片边界内。
- `canonical_position_mm` 必须由后端根据当前标定重新计算，不能盲信前端值。
- 标定指纹必须与当前发布版本一致。
- 朝向必须是有限数值。

### 8.3 UE 运行时

- 路线起点或手动点附近必须能命中可行走地面。
- 胶囊体在出生位置必须有容纳空间。
- 地面检测失败时返回明确错误，不允许无限坠落或生成到屋顶后继续运行。

## 9. 实施范围

### 9.1 前端

- 重构 `frontend/interaction.html` 人物出生点区域。
- 默认路线配置移动到中栏。
- 恢复并保留图片出生配置，不再强制归一为 `ue_anchor`。
- 使用 `frontend/spatial_canvas.js` 完成与路线一致的画布交互。
- 增加路线只读预览、手动点编辑、空状态、错误状态和确认交互。

### 9.2 后端

- 调整人物配置校验：有效项目路线存在时允许没有手动出生点。
- 运行投影优先使用路线第一个点生成出生配置。
- 已选择但不可用的项目路线阻断运行，不回退手动点。
- 保留旧 `ue_anchor` 读取兼容。

### 9.3 UE

- 有有效运行时路线时始终从路线起点出生。
- `auto_start` 仅控制是否启动跟随。
- 无运行时路线时继续消费坐标出生配置。
- UE 锚点继续作为旧项目或开发回退。

## 10. 验收标准

- [ ] 人物漫游页不再以 UE 出生锚点卡片作为主要配置界面。
- [ ] 选择有效默认项目路线后，画布显示该路线及其空间底图，并高亮第一个点。
- [ ] 关闭“进入后自动开始”后，人物仍从路线起点出生，但不会自动行走。
- [ ] 关闭默认路线后，页面切换到手动出生点画布。
- [ ] 手动画布支持与路线画布一致的缩放、平移、旋转、翻转和适应视图。
- [ ] 用户可以设置一个出生点并拖动朝向箭头。
- [ ] 手动点保存后同时保留像素位置、规范位置和标定指纹。
- [ ] 更换底图前出现模态确认，取消后原点位保持不变。
- [ ] 启用路线不会删除已保存的手动点；再次关闭路线后可以继续编辑。
- [ ] 已选择但待复核的路线不会静默改用手动点。
- [ ] 无路线且无手动点时不能保存启用态人物配置。
- [ ] UE 在 `auto_start = false` 时仍从有效路线起点出生。
- [ ] UE 无有效路线时从手动点出生，并通过地面检测确定 Z。
- [ ] 标定变化后手动点和路线均进入明确复核/阻断状态。

---

## 11. 非目标

- 不新增多个人物出生点列表。
- 不按不同皮肤配置不同出生点。
- 不编辑逐点 Z，不支持跨楼层出生逻辑。
- 不在人物页直接编辑路线点。
- 不引入 NavMesh 自动绕障或跨层寻路。
- 不删除 UE 开发回退 Actor。

## 12. 实施与验证记录（2026-07-21）

本补充设计已完成前端、后端与 UE 运行链路实施：

- 人物漫游页已支持“有效项目路线起点优先 / 无路线手动底图打点”的派生出生来源。
- 后端运行投影已从默认项目路线前两个点派生出生坐标和朝向；`auto_start` 不再参与出生来源选择。
- UE 已在有效 Runtime Route 存在时始终使用路线起点，关闭自动开始后只停止跟随，不改变出生位置。
- 后端完整测试集共 53 项通过；浏览器已完成路线预览、手动打点、保存阻断和点位可逆性回归。
- `test0316Editor` 构建验证成功，未写入测试配置或提高项目交互 revision。

已知宿主环境问题：

- `D:\tmp_ue\test0316\Plugins\MetaverseClient` 是指向 `C:\Users\ADMIN\Desktop\unreal-client` 的失效 Junction。UnrealBuildTool 扫描插件目录时会先因目标不存在而失败。
- 本次验证仅在构建期间临时移开该 Junction，完成后已原样恢复。后续若要稳定编译宿主项目，应恢复它的目标目录，或由项目维护者确认后移除该失效链接；OntoTwin 不应擅自长期改动它。
