## 1. 定位

本 PRD 定义首期面向工业设备实时状态的平台通用行为库。它通过 4.5 核心层的模块化执行器契约提供可复用的动画、视觉状态、特效和提示行为；它不负责读取原始业务遥测、不负责归一化，也不替代项目自己的 Blueprint/Animation Blueprint 实现。行为库拥有独立生命周期，可单独版本化、验收、禁用和回滚。

行为库是可选的：未安装、未加载或被禁用时，核心路由仍必须使用静态安全回退完成同步。

业务验收从 Nexus 本体配置中心的当前类型卡片进入“表现验收向导”，不在左侧菜单另设“工业行为库验收”入口。向导以运行、故障、低电量、维护、离线和一次性动作等现场情景呈现结果，不要求验收人员输入内部行为 ID；UE 中的实际执行仍须在隔离工程 PIE/Cook 中单独确认。完整操作顺序以 [test0316 三个用例操作卡](../ACCEPTANCE/OntoTwin%204.5-4.6%20test0316%20三个用例操作卡.md) 为准。

## 2. 目标与非目标

### 目标

- 注册一组稳定的工业逻辑行为 ID。
- 使用受控表现槽位承接 Animation Blueprint、Blueprint 事件、材质/特效和状态指示器。
- 按项目显式实现 > 平台通用行为 > 静态安全回退提供确定性解析。
- 对一次性动作支持 `event_id` 去重，并保留可诊断的执行结果。
- 作为独立可选包交付、Cook、启停和回滚。

### 非目标

- 不实现通用规则引擎、任意脚本、流程时间轴或业务编排。
- 不把 UE 资产路径、软引用路径或项目私有类名下发到 Nexus。
- 不提供实例级行为路由覆盖。
- 不强制已有项目迁移到统一 Blueprint；项目显式实现始终优先。
- 不修改 `test0316` UE 母工程或其资产。

## 3. 执行器契约

行为库实现核心 PRD 定义的 `IOntoTwinPresentationExecutor`（精确命名和 C++ 签名在实施阶段冻结）模块化特征。注册信息至少包含：

- 执行器版本和兼容的核心协议版本；
- 支持的通道（`animation`、`visual`、`fx`、`label` 等）；
- 支持的逻辑行为 ID；
- 支持的受控槽位；
- 能力缺失、资产缺失和执行失败时的安全回退策略。

注册和解析要求：

1. 同一逻辑行为 ID 与槽位不得出现未定义优先级的重复注册；冲突必须在注册或启动诊断中明确暴露。
2. 执行器只接收已归一化的 `I3D_Presentation` 路由结果，不读取原始 `raw_state` 来自行推断业务语义。
3. 项目显式执行器可覆盖同一平台行为 ID，但覆盖关系必须由 ObjectType 的 `presentation_profile` 明确声明。
4. 执行器不得把一次性动作重新写回状态字段；动作只按 `event_id` 触发。

## 4. 首期行为与槽位（示例清单，资产审计时冻结）

建议的核心状态行为 ID：

| 类型 | 逻辑行为 ID 示例 | 语义 |
|---|---|---|
| 持续状态 | `industrial.machine.idle` | 待机 |
| 持续状态 | `industrial.machine.running` | 运行 |
| 持续状态 | `industrial.machine.fault` | 故障 |
| 持续状态 | `industrial.machine.offline` | 离线/失联 |
| 视觉修饰 | `industrial.visual.warning` | 警告指示 |
| 视觉修饰 | `industrial.visual.critical` | 严重告警指示 |
| 一次性动作 | `industrial.fx.warning_flash` | 告警闪烁 |
| 一次性动作 | `industrial.fx.start_pulse` | 启动脉冲 |

建议的受控槽位：`primary`、`motion`、`status_indicator`、`alarm`、`label`。槽位名称、允许的执行器类型、并发策略和缺省安全表现必须在实施前通过资产审计冻结；以上清单不授权直接新增资产或改动既有资产。

## 5. 路由与回退行为

对每个通道独立解析：

1. 若 ObjectType 的 `presentation_profile` 指定项目逻辑行为且项目执行器支持，则使用 `project`。
2. 否则若本包注册的平台行为支持，则使用 `platform`。
3. 否则使用 `safe_fallback`，例如保持当前安全姿态、停止循环、隐藏非必要特效或显示静态状态指示。

一个通道回退不得影响其他通道；行为库缺失不得导致快照拒绝或实例销毁。解析结果必须能在诊断中说明来源、行为 ID、槽位及失败原因。

## 6. 交付与部署

- 作为独立可选 UE 内容插件/包交付，与 `OntoTwinSync` 核心版本建立明确兼容矩阵。
- 核心插件不得硬编码本包资产路径或把本包设为必需依赖。
- 包安装、禁用、Cook 缺失和版本不兼容均需通过核心安全回退验收。
- 行为库的资产依赖、命名空间、槽位占用和授权边界必须在包清单中可审计。
- 交付不包含后端依赖新增；如确需新增 Python 依赖，必须先按项目规则征得确认并更新 requirements。

## 7. 验收摘要

- 包存在并加载时，工业核心行为 ID 可被发现、解析和执行。
- 包不存在或行为缺失时，每个通道均落到静态安全回退，且不影响同步。
- 项目显式实现优先级高于平台默认实现；冲突可诊断。
- `event_id` 重复投递不会重复触发一次性动作。
- 受控槽位之外的绑定被拒绝或回退，不允许任意资产路径注入。
- 升级、禁用、Cook 缺失和重连不会造成旧 Visual/Behavioral 字段双重执行。
- 测试只使用隔离工程或测试夹具，不触碰 `test0316` 母工程。

本 PRD 只确认独立包的职责和边界；具体资产、槽位全集、动画状态机图和执行器签名在 `4.6.0` 行为库实施契约冻结后确定，核心协议兼容性仍以 `OntoTwinSync 4.5.0` 为准。
