# OntoTwin CAD 空间底图草稿与发布补丁（PRD）

> 状态：已确认，进入实施  
> 日期：2026-08-18  
> 适用页面：`frontend/coord_workbench.html`  
> 关联基线：OntoTwin 3.1 三维坐标体系统一、OntoTwin 4.0.1 配置驱动人物漫游闭环

---

## 1. 背景

CAD 模式目前把“计算变换”和“保存构件”连成一条临时流程：锚点、变换矩阵和精度只保存在浏览器 24 小时会话缓存中；只有走到第 5 步并保存构件时，矩阵才随构件写入当前项目。

这与图片模式已经具备的“上传项目资产 → 保存标定草稿 → 发布空间底图 → 重新加载继续编辑”不一致，也不符合 3.1 中“CAD 标定后产生 CAD 帧”的设计。

## 2. 产品决策

CAD 标定不再只是生成构件前的临时过程，而是产生项目级、可恢复、可版本化的 **CAD 空间底图（SpatialFrame）**。

CAD 与图片模式统一使用两个明确动作：

1. **保存标定草稿**：保存尚可继续修改的 CAD 与标定数据。
2. **发布空间底图**：把当前草稿发布为项目可引用的稳定标定版本。

“发布空间底图”与“保存构件到项目”是两个独立动作：

- 空间底图保存坐标空间及来源资产。
- 构件保存图纸中识别出的匿名业务对象。

发布空间底图不得直接铸造实例，也不得替代第 5 步保存构件。

## 3. 目标

1. 原始 DXF、标定锚点、变换矩阵和精度进入当前项目，不再依赖浏览器缓存。
2. 用户关闭并重新打开页面后，可以加载服务器中的 CAD 空间底图继续编辑。
3. CAD 模式显示草稿、已发布和有未发布更改等明确状态。
4. 发布形成修订号与标定指纹，后续构件能够引用准确的 CAD 空间底图。
5. 保持现有类型审核、构件保存、JSON/CSV 导出链路不退化。

## 4. 非目标

- 本补丁不让人物漫游路线编辑器直接渲染 DXF；路线编辑器仍只消费图片空间底图。
- 不新增前端构建工具、异步队列或数据库表。
- 不改变现有图片空间底图的数据语义和发布门槛。
- 不把 CAD 块直接转换为实例。
- 不删除旧的 `frame_cad` 或历史构件兼容逻辑。

## 5. 用户流程

### 5.1 新建 CAD 空间底图

1. 用户上传 DXF。
2. 系统完成解析后，将原始 DXF 保存为当前项目的 CAD 空间底图草稿。
3. 用户完成类型审核、画布朝向、规范原点和锚点标定。
4. 用户点击“保存标定草稿”，服务器保存当前标定数据并递增草稿版本。
5. 标定达到发布门槛后，用户点击“发布空间底图”。
6. 发布成功后仍可继续编辑；再次修改锚点或底图信息时，状态变为“有未发布更改”。
7. 用户继续进入构件列表，并在第 5 步把构件保存到项目。

### 5.2 加载已有 CAD 空间底图

1. 第 1 步展示“已保存 CAD 空间底图”列表。
2. 用户选择并加载一项。
3. 系统从服务器读取原始 DXF、重新解析图元，并恢复锚点、矩阵、精度、草稿版本和发布状态。
4. 用户可继续编辑、再次保存或重新发布。

## 6. 界面设计

### 6.1 第 1 步：上传

在上传区下方增加“已保存 CAD 空间底图”：

- 下拉项显示：名称、草稿/已发布状态、楼层。
- “加载”按钮具有加载态，失败使用就近提示或 toast。
- 空列表显示“暂无已保存 CAD 空间底图”。

### 6.2 第 3 步：标定

锚点标定区域增加：

- 底图名称。
- 楼层。
- 可选 UE Level。
- 持久化状态：新底图尚未保存 / 标定草稿版本 N / 已发布版本 N / 有未发布更改。
- 次操作“保存标定草稿”。
- 主操作“发布空间底图”。

一个操作区域只保留一个黑底主按钮。异步期间按钮禁用并显示“保存中”或“发布中”。保存成功后编辑区保持可用。

### 6.3 发布门槛

CAD 空间底图满足以下条件才允许发布：

- 已绑定原始 DXF 项目资产。
- 至少 3 个不共线的有效锚点；现有“至少 2 个锚点”提示与 6 参数仿射求解不一致，本补丁一并修正。
- 已生成可逆变换矩阵。
- RMSE 小于 200 cm，与当前 CAD 工作台“可继续”门槛一致。

楼层默认使用 1；UE Level 本补丁作为可选元数据，不阻断 CAD 发布。

## 7. 数据模型

CAD 空间底图复用当前项目的 `frames` 容器，使用动态 ID，避免不同 CAD 来源互相覆盖。

```jsonc
{
  "id": "frame.cad.<uuid>",
  "name": "SCC W18 CAD",
  "kind": "cad",
  "unit": "mm",
  "status": "draft | published",
  "floor": 1,
  "floor_id": "floor-1",
  "bound_ue_project_id": "...",
  "ue_level": "",
  "cad": {
    "asset_id": "asset_<hash>",
    "sha256": "...",
    "storage_name": "asset_<hash>.dxf",
    "original_name": "SCC-W18.dxf",
    "size_bytes": 123456,
    "mime_type": "application/dxf"
  },
  "anchors": [
    {
      "id": "anchor-1",
      "source_xy_mm": [1000, 2000],
      "ue_world_cm": [100, 200]
    }
  ],
  "to_ue": {"method": "anchor", "matrix": [[1,0,0],[0,1,0],[0,0,1]]},
  "to_canonical": {"method": "origin", "matrix": [[1,0,0],[0,1,0],[0,0,1]]},
  "transform": {
    "type": "affine_2d",
    "source": "cad_mm",
    "target": "canonical_mm",
    "matrix": [[1,0,0],[0,1,0],[0,0,1]],
    "metrics": {"rmse_cm": 0}
  },
  "display": {"rotation_deg": 0, "flip": false},
  "canonical_origin": [0, 0],
  "draft_revision": 1,
  "calibration_revision": 1,
  "calibration_fingerprint": "sha256:..."
}
```

兼容规则：

- 图片帧继续使用 `kind=image` 与 `image` 元数据。
- CAD 构件优先引用动态 CAD frame ID；历史构件继续允许引用固定 `frame_cad`。
- `canonical_origin` 和 `display` 同时保留在项目空间剖面中；CAD frame 保存发布时的快照，用于恢复和审计。

## 8. 接口设计

### 8.1 新增

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/v2/spatial-frames/cad-assets` | POST | 上传 DXF，创建 CAD 空间底图草稿 |
| `/api/v2/spatial-frames/{frame_id}/source` | GET | 下载项目中保存的原始 CAD |

生产 CAD 文件可能达到数百 MB。DXF 项目资产上传采用流式落盘与增量哈希，单文件上限为 512 MB；服务端不得为保存项目草稿而把完整 DXF 一次性读入内存。

### 8.2 扩展

| 接口 | 调整 |
|---|---|
| `GET /api/v2/spatial-frames?kind=cad` | 只列出 CAD 空间底图 |
| `GET /api/v2/spatial-frames/{frame_id}` | 同时读取图片和 CAD 空间底图 |
| `PUT /api/v2/spatial-frames/{frame_id}/draft` | 根据 frame.kind 校验并保存对应草稿 |
| `POST /api/v2/spatial-frames/{frame_id}/publish` | 根据 frame.kind 执行对应发布门槛与指纹生成 |
| `POST /api/v2/coord/save_components` | 接收 CAD `frame_id`，构件引用已选 CAD 空间底图且不覆盖其发布元数据 |

写接口继续使用 `expected_draft_revision` 和 `expected_project_id` 防止覆盖其他项目或旧版本。

## 9. 状态与版本规则

- 上传成功：`status=draft`，`draft_revision=0`。
- 保存草稿：`status=draft`，`draft_revision += 1`。
- 发布成功：`status=published`，`calibration_revision += 1`，生成新指纹。
- 修改锚点、名称、楼层、UE Level、原点或朝向后：前端立即显示“有未发布更改”。
- 发布已过期草稿时返回 409，前端提示用户重新加载，不静默覆盖。
- 浏览器 IndexedDB 仅作为操作恢复缓存，项目中的 SpatialFrame 才是持久化事实来源。

## 10. 验收标准

1. 上传 DXF 后，刷新浏览器仍能在“已保存 CAD 空间底图”中找到该文件。
2. 保存草稿后，关闭并重开页面能恢复原始 DXF、锚点、矩阵和精度。
3. 发布成功后显示“已发布 · 标定版本 N”。
4. 修改已发布标定后，状态变为“有未发布更改”，再次发布版本递增。
5. 少于 3 个不共线锚点、RMSE 大于等于 200 cm 或矩阵不可逆时不能发布，并显示明确原因。
6. 同一项目可保存多张 CAD 空间底图，互不覆盖。
7. 第 5 步保存构件后，构件引用当前 CAD frame ID。
8. 发布空间底图不会直接产生实例；实例绑定台流程不变。
9. 图片空间底图的上传、草稿、发布、加载和人物漫游引用全部保持正常。
10. 无激活项目、版本冲突、源文件丢失时均显示明确错误，不出现空白或假成功。
11. 不超过 512 MB 的正式 DXF 可以创建项目草稿；大文件上传过程不依赖完整文件驻留内存。

## 11. 实施顺序

1. 扩展 `spatial_assets` 的 CAD 文件存储、草稿、发布和读取能力。
2. 增加服务测试，覆盖上传、保存、发布、重载、冲突和图片回归。
3. 改造 CAD 工作台的上传/加载、状态和两个持久化操作。
4. 让保存构件引用动态 CAD frame ID。
5. 执行完整 CAD 与图片模式回归。
