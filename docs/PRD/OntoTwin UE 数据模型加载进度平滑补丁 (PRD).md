# OntoTwin UE 数据模型加载进度平滑补丁（PRD）

## 1. 背景与问题

UE 首次进入场景时，`ATwinSceneManager` 会显示全屏数据模型加载层。当前实现存在两个连续阶段：

1. HTTP 请求尚未返回完整模型快照时，进度条保持不确定态，没有可见的累计进度。
2. 快照返回后，实例在同一个游戏线程回调内同步处理；虽然代码逐条计算 `Completed / Total`，Slate 在循环结束前没有刷新帧，因此用户通常只看到最后瞬间跳到 100%。

现象是等待约二十秒没有反馈，结束前一秒进度突然拉满。它不代表加载失败，但会让用户误判程序卡死。

## 2. 目标

- 加载期间持续提供可见、平稳且可解释的反馈。
- 已知实例总数后继续使用真实 `Completed / Total`，不伪造实例完成数量。
- 不改后端接口、项目存储结构、模型加载顺序或首轮基线完成条件。
- 保持现有 Screen Space 玻璃卡片、输入穿透和 Balanced → Performance 回退。

## 3. 非目标

- 本补丁不提供后端生成快照的服务器侧精确百分比。请求完整返回前总实例数未知，因此这段时间只能表达“正在等待”，不能声称是业务完成比例。
- 本补丁不把同步模型加载重构为异步任务队列，也不改变实例创建和资产加载语义。
- 不修改六种实例信息面板模板、World Space Widget 或 Web 编辑器。

## 4. 交互设计

加载层使用四个显示阶段：

| 阶段 | 显示范围 | 数据依据 | 文案 |
| --- | ---: | --- | --- |
| 等待模型数据 | 0%～15% | 本地经过时间，最多 15%，不显示数值百分比 | 正在等待模型数据… |
| 处理模型实例 | 15%～95% | `15% + 80% × Completed / Total` | 已处理 N / Total |
| 完成场景准备 | 95%～100% | 首轮基线已经成功 | 正在完成场景准备… |
| 完成 | 100% | 显示进度已经到达 100% | 已加载 Total / Total · 100% |

### 4.1 平滑规则

- 等待阶段以每秒约 `0.75%` 的速度增长，约二十秒到达 15%，之后保持 15%。
- 处理阶段只更新目标值，显示值逐帧以固定速度追赶，避免单帧跳变。
- 收到完成信号后，先平滑到 95%，再完成 95%～100% 的短过渡。
- 完成层至少保留足够时间让 100% 可被观察，然后由原生命周期自动关闭。
- 失败和自动重试保留明确文案；失败状态不倒退已有显示进度。

### 4.2 减少动态效果

当 `OntoTwin.Glass.ReduceMotion=1` 或项目设置启用减少动态效果时，不执行逐帧缓动；阶段目标直接生效，仍保留文字状态和真实实例计数。

## 5. 渲染与输入

- 加载层继续通过 `AddToViewport` 作为 Screen Space UMG 渲染。
- Balanced 使用 `UBackgroundBlur` 与深色玻璃表面；低质量环境继续使用现有 Performance 静态表面回退。
- 进度、文字和卡片装饰保持 `HitTestInvisible` / `SelfHitTestInvisible`，不接管鼠标、键盘或漫游输入。
- 不新增 SceneCapture、Retainer Box 或持续空闲折射动画。

## 6. 状态与异常

- `Total <= 0` 时仍允许完成空项目基线，文案显示 `0 / 0`。
- 重试期间不把进度条重置到 0，避免视觉倒退；重新取得快照后继续追赶新的目标。
- 只有 `CompleteInitialModelBaseline` 成功触发后才能进入 95%～100%；失败不得显示完成态。
- UI 平滑值仅是显示状态，不参与实例同步、交互解锁或业务判断。

## 7. 验收标准

1. 模拟二十秒 HTTP 等待时，进度条从 0 缓慢增长并在 15% 封顶，页面不再长期静止。
2. 等待阶段不显示虚假的业务百分比。
3. 快照返回后，进度条不会在同一帧从等待值跳到 100%。
4. 实例计数文案来自真实 `Completed / Total`。
5. 完成时可观察到 95%～100% 的短过渡和最终 100% 状态。
6. 失败、重试、空项目和 ReduceMotion 模式可用。
7. UE Editor Development 编译通过；相关自动化测试无回归。
8. 实际 `ZHHZ_NEW` 工程同步相同源码，后续 Development/Shipping 构建可使用该行为。
