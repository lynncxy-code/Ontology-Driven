# OntoTwin 实例状态语义拆分补丁（PRD）

## 1. 问题

实例运维中心当前把 `当前时间 - last_seen >= 3 秒` 统一显示为“失联”。该规则原本表示业务数据更新是否新鲜，但 CAD 铸造、UE 迁移等静态实例没有持续数据源，因此会在创建三秒后全部显示“失联”。这不能证明实例被删除、UE 离线或模型加载失败。

## 2. 设计结论

实例生命周期、数据新鲜度和实时通道健康必须分开表达：

- 静态实例：显示“静态实例”，不参加三秒失联判定。
- 已配置 WebSocket 实时通道的实例：以 UE 上报的通道和目标状态显示“实时在线 / HTTP 接管 / 目标失联 / 等待通道”。
- 旧 `status` 与快照 `online` 字段继续保留，供既有接口兼容；实例运维中心不再把它们直接翻译成“在线/失联”。
- 浏览器读取快照不得刷新 `last_seen`，避免用读请求伪造业务心跳。

本补丁只增加派生状态，不修改 `ProjectStore` 文件格式。

## 3. 接口投影

`GET /api/v2/instances` 为每个实例增加临时字段 `liveness`：

```json
{
  "mode": "static | realtime",
  "state": "static | online | degraded | offline | unknown",
  "label": "静态实例",
  "detail": "未配置实时数据源，不参与失联判定"
}
```

实时实例仍保留 `realtime_channel` 诊断明细。`liveness` 仅由请求时状态计算，不写入项目存储。

## 4. 页面交互

- 左侧实例卡片只显示一个主状态徽标，避免旧“失联”和实时通道状态互相矛盾。
- 静态实例使用灰色小圆点和中性徽标。
- 实时在线使用小面积绿色；目标失联使用小面积红色；HTTP 接管使用警示色；未知使用灰色。
- 选中实例后的标题区沿用同一状态投影，不再读取快照 `online` 直接显示“OntoTwin 失联”。

## 5. 验收标准

1. CAD/UE 迁移静态实例即使 `last_seen` 已超过三秒，也显示“静态实例”。
2. WebSocket 实例按通道状态分别显示实时在线、HTTP 接管、目标失联或等待通道。
3. 页面不再同时显示互相冲突的两个状态徽标。
4. 旧 `status`、`last_seen` 和快照 `online` 字段保持兼容。
5. 不启用模拟器、不刷新 `last_seen`，也能正确表达静态实例语义。
