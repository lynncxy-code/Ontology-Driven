# OntoTwin 待办清单

## 后续版本架构事项

### Zone 分区后续阶段

- [ ] **第二期：运行时多分区选择与楼层切换**
  - 将 UE Details 中的 `SceneId` 明确为“启动默认分区”，运行时由业务界面维护 `active_zone_ids`。
  - 快照接口支持一次请求一个或多个 Zone，能够表达“单层、若干层、整栋楼”三种范围。
  - `TwinSceneManager` 切换活动分区时对动态实例做差量卸载/加载；失败时保留原范围并允许重试。
  - 一个运行世界继续只使用一个主要 `TwinSceneManager`，不采用“每层同时放一个 Manager”的并行轮询方案。
  - 完成标准：单层切换、跨层组合、整楼恢复、断线恢复、无重复实例和加载失败回退均有验收记录。

- [ ] **第三期：业务视图加载前过滤与关卡流送**
  - 3.8 已建立独立 BusinessView、多对多成员规则以及运行时实例显隐；本阶段不再重复建设业务视图数据模型。
  - 将 3.8 的“活动 Zone + BusinessView”集合计算前移到快照与模型加载阶段，避免先全量加载再隐藏。
  - 对 UE 关卡中的静态建筑模型，使用 Level Streaming、Data Layer、World Partition 或 HLOD 管理，不把静态模型卸载职责交给 Zone API。
  - 完成标准：业务切换不改变空间分区；首次加载量、内存占用和切换耗时具备可比较指标。

### 3.8 Web Bridge 后续动作

- [ ] **WebSocket 配置变更通知**
  - 3.8 一期继续轮询独立 Web runtime revision；后续由 OntoTwin 后端通过 WebSocket 只推送“配置版本已变化”通知。
  - UE 收到通知后仍通过 HTTP 拉取完整配置；WebSocket 断开时继续使用轮询兜底。
  - 业务网页不参与配置通知链路。

- [ ] **同页面 Bridge 热切换上下文**
  - 3.8 默认在 page ID 或最终 URL 变化时重新加载；后续允许页面声明支持 `context_changed`。
  - 未声明能力或热切换失败时必须回退到 URL 重载，不能继续显示旧对象。

- [ ] **浏览器文件与设备能力**
  - 按实际业务需求评审文件上传/下载、剪贴板、摄像头、麦克风、地理位置和系统通知。
  - 每项能力单独定义权限、打包平台兼容性、失败提示和安全验收，不按完整桌面浏览器一次性开放。

- [ ] **D：通用动作扩展机制（禁止任意命令转发）**
  - 3.8 只内置 `select_instance`、`clear_selection`、`request_open_scope`、`request_open_page` 及其固定 Zone、BusinessView、Instance 场景效果。
  - 如需扩展更多 Web→UE 动作，只允许在平台注册表中逐项登记动作名、参数 Schema、权限和执行器。
  - 不允许把任意 JSON、Blueprint 调用、UE Console Command、JavaScript 或外部 API 请求直接转发执行。
  - 完成标准：未注册动作统一拒绝并记录诊断；新增动作必须经过独立评审和自动化契约测试。

- [ ] **多项目版本必须实现 Neo4j 项目隔离**（P1，架构升级门禁）
  - 当前第一版决策：客户侧只部署 ZHHZ；使用独立 Neo4j 容器，并从 ZHHZ 专属 registry/Cypher 初始化空图库，不复制开发环境的混合数据卷。
  - 触发条件：接入第二个客户项目、同一套后台承载多个项目，或开始设计集中式服务器部署时。
  - 当前原因：Neo4j 节点和关系没有 `project_id` / `dataset_id`，所有本体按 `rid` 合并在默认 `neo4j` 数据库中，无法按项目直接筛选导出。
  - 后续必须在以下方案中正式选型：
    1. 节点和关系增加 `project_id`，约束、索引及所有查询强制带项目作用域；
    2. 每个项目使用独立 Neo4j database；
    3. 每个客户/项目使用独立 Neo4j 容器。
  - 完成标准：具备旧图迁移脚本、跨项目隔离测试、项目级备份恢复、项目级导入导出，以及防串库验收记录。
  - 发布提醒：后续版本冻结前必须复查本项；未完成时不得宣称支持多项目共享部署。
