# OntoTwin 待办清单

## 后续版本架构事项

- [ ] **多项目版本必须实现 Neo4j 项目隔离**（P1，架构升级门禁）
  - 当前第一版决策：客户侧只部署 ZHHZ；使用独立 Neo4j 容器，并从 ZHHZ 专属 registry/Cypher 初始化空图库，不复制开发环境的混合数据卷。
  - 触发条件：接入第二个客户项目、同一套后台承载多个项目，或开始设计集中式服务器部署时。
  - 当前原因：Neo4j 节点和关系没有 `project_id` / `dataset_id`，所有本体按 `rid` 合并在默认 `neo4j` 数据库中，无法按项目直接筛选导出。
  - 后续必须在以下方案中正式选型：
    1. 节点和关系增加 `project_id`，约束、索引及所有查询强制带项目作用域；
    2. 每个项目使用独立 Neo4j database；
    3. 每个客户/项目使用独立 Neo4j 容器。
  - 完成标准：具备旧图迁移脚本、跨项目隔离测试、项目级备份恢复、项目级导入导出，以及防串库验收记录。
  - 发布提醒：后续版本冻结前必须复查本项；未完成时不得宣称支持多项目共享部署。
