# OntoTwin & FDE (Foundry Digital Twin Engine) 产品使用与 UE 开发手册

> **版本**：v3.4 (最新更新版)  
> **定位**：本体驱动的工业三维数字孪生底座  
> **面向对象**：数字孪生开发者、UE5 场景/蓝图开发人员、工厂部署调试工程师  

---

## 1. 宏观模块介绍 (五大核心支柱)

OntoTwin 的核心任务是将**物理世界中设备的业务属性与图纸几何进行匹配映射**，形成在 Unreal Engine (UE5) 中由数据库驱动的实时孪生场景。系统由以下五大模块组成：

```
                    【 语 义 图 谱 总 览 / 本 体 配 置 中 心 】 (Neo4j 本体层)
                                      │
                                      ▼
                      【 坐 标 标 定 工 作 台 】 (CAD 解析 & 构件标定)
                                      │
                                      ▼
                      【 实 例 绑 定 台 】 (业务 ID 绑定 & 实例铸造)
                                      │
                                      ▼
                    【 实 例 运 维 与 监 控 】 (运行态维护 & Override)
                                      │
                                      ▼
                 【 OntoTwinSync UE 插件 】 (UE5 渲染与编辑器联动侧)
```

### ① 数据定义 (本体定义与配置)
*   **语义图谱总览**：数字孪生系统的高维网络视图，展示“类型-接口-链接”的拓扑图，是系统管理类型库（数据集）的入口。
*   **本体配置中心**：用于为不同的**对象类型 (ObjectType)** 绑定**能力接口**（如 `I3D_Representable` 代表具有三维资产表现，`I3D_Spatial` 代表具有空间定位能力），并挂载监控所需的实时属性字段。

### ② 模型工坊 (几何空间标定)
*   **坐标标定工作台**：导入工业 CAD 图纸 (DXF/DWG) 进行几何解析。使用 4 点仿射变换矩阵，完成 **CAD 图纸坐标系** 到 **UE 世界坐标系** 的精密投影对齐，生成带有准确坐标的**匿名构件**。
*   **CAD 一键成模**：提供从解析的 CAD 二维线框快速拉伸生成三维墙体、路网和地板的程序化建模能力。

### ③ 实例接入 (业务身份赋予)
*   **实例绑定台**：孪生实例的唯一出生地。通过导入业务实例清单 (CSV) 或手动键入，将带有几何特征的**匿名构件**与具有业务标识的**实例编号 (EQUIP_ID)** 组合，并绑定至具体**分区 (Zone)** 最终**铸造 (Mint)** 为受控的孪生实例。

### ④ 运行守护 (数据路由与发布)
*   **实例运维与监控**：监控当前激活项目下所有实例的在线状态 (Online/Offline)、位姿、渲染参数。支持下发 Override 指令（如材质、变体、动画和特效状态）以测试孪生体性能。
*   **实时数据监控台**：实时动态心跳事件流 (SSE) 中转站，实时接收工业网关发送的数据并透传给 UE5 客户端。

### ⑤ UE 消费侧 (实时呈现与生产回写)
*   **OntoTwinSync 插件**：UE 关卡中的核心接收器。挂载 `TwinSceneManager`，无需烘焙或预置孪生 Actor 到关卡，完全通过轮询 API 根据激活的 **分区 (Zone)** 实现三维实例的自动加载 (Spawn)、空间校正 (ApplyTransform) 及动态卸载 (Despawn)。

## 2. 核心设计主线：类型 → 构件 → 实例

为彻底实现“数据驱动”，OntoTwin 将物理实体拆解为以下三层演进模型：

```
+--------------------+      绑定几何位置      +--------------------+      赋予业务身份      +--------------------+
|  ObjectType (类型) |  ------------------->  |  Component (构件)  |  ------------------->  |  Instance (实例)   |
|   (如: 桥式起重机)   |                        | (无身份的某台起重机) |                        |  (如: 起重机 CR-007) |
+--------------------+                        +--------------------+                        +--------------------+
```

1.  **类型 (ObjectType)**：
    *   *定义*：描述一类物体“是什么”。定义其拥有哪些属性（如：功率、温度）以及支持的三维表现形式（拥有哪些注入接口）。
2.  **构件 (Component)**：
    *   *定义*：经过 CAD 图纸标定后解析出的匿名物体。它拥有准确的**规范系空间三维坐标 (Canonical Transform)** 和关联的三维模型，但**没有业务身份**。
3.  **实例 (Instance)**：
    *   *定义*：由“构件”绑定了具体的“业务清单 ID”（例如设备编号 `DW-007`）并指定“分区 (Zone)”后，铸造产生的完整数字孪生体。
    *   *准则*：**UE5 渲染与实时驱动只认已成功铸造的“实例”，未绑定的构件不会在 UE 运行时出现**。

## 3. UE5 插件安装与基本配置

### 3.1 引入插件
`OntoTwinSync` 插件源码已与项目工程进行了 Junction 软直连，在进行修改后，请务必在编辑器中关闭后重新编译：
1. 关闭 UE 编辑器。
2. 在 Visual Studio 或 Rider 中打开工程解决方案。
3. 选择 `Development Editor` 编译配置并右键项目点击 **Build**。
4. 重开编辑器，确认细节面板展示出 `孪生管理器|预览` 和 `孪生管理器|迁移` 两个属性大组。

### 3.2 挂载 Manager
1. 打开目标子关卡，在关卡大纲中搜索并拖入 `TwinSceneManager` (孪生场景管理器) Actor。
2. 选中 Manager，在 **Details (细节)** 面板中进行基本配置：
   *   **后端基础URL**：填入后端服务器的 API 接入地址（本地默认为 `http://127.0.0.1:5000`）。
   *   **分区ID (Zone ID)**：填入当前子关卡对应的分区标识（例如 `zone_floor_5`）。**注意**：在未划定分区或初次测试时请**保持留空**，此时 Manager 将拉取后端全部激活实例，不按分区过滤。
   *   **孪生体蓝图类**：绑定你项目中的实例渲染载体类（默认指定为继承自 `ATwinInstance` 的 `BP_TwinInstance_Advanced`）。

## 4. UE 编辑器操作先后顺序与三段工作流

在 3.4 版本中，传统的“快照固化到关卡”机制已被正式废弃，全面改为**“纯数据库驱动”**。这意味着孪生 Actor 不再保存在 `.umap` 文件中，开发阶段只使用 **Transient（临时/易失性）预览 Actor**，避免因 glTFRuntime 动态生成的网格无法持久化而导致关卡保存崩溃。

基于此，开发和运维涉及以下三大工作流，操作顺序必须严格按照清单执行：

### 🛠️ 工作流一：FR-4 编辑器临时预览与清除

用于在不需要点击 Play 运行的情况下，快速核对当前后端数据库里的三维孪生体是否能在 UE 中正确对齐展示。

```
[单独选中 Manager] ──> [点 从数据库拉取预览] ──> (检查与交互验证) ──> [点 清除预览]
```

1.  **单独选中 Manager**：在关卡大纲中只选择 `TwinSceneManager` Actor（不要多选其他静态网格 Actor，否则 Manager 专属按钮会被隐藏）。
2.  **点击“从数据库拉取预览”**：
    *   *UE 响应*：Manager 触发 HTTP GET 请求 `/api/v2/state/snapshots`，在 `TwinPreview` 文件夹下生成临时 Actor `[预览] <InstanceId>`。
    *   *校验点*：大纲及关卡中出现带有 3D 文本标签的临时设备。屏幕左上角弹出绿字提示 `预览已生成 N 个 (transient，不会存进关卡)`。
3.  **验证临时属性**：
    *   *操作*：此时可以任意点击生成的预览 Actor，或者点击保存关卡并重启编辑器。
    *   *预期*：重新打开关卡后，这些预览 Actor 会自动清空消失。它们在内存中被赋予了 `RF_Transient` 标记，绝对不会污染 `.umap` 关卡。
4.  **点击“清除预览”**：一键将所有 `[预览] xxx` Actor 从当前场景中安全销毁。

---

### 💾 工作流二：FR-5 空间位置回写 (编辑器校准)

当导入的 CAD 坐标在 UE 实际的厂房美术场景中出现几厘米的偏差、或有微小的浮空，需要手动调整，并将校准后的坐标传回后端数据库。

```
[拉取预览] ──> [移动/旋转预览 Actor] ──> [单独选中 Manager] ──> [点 提交空间变更(回写)]
```

1.  **点“从数据库拉取预览”**：
    *   *内部原理*：生成预览时，插件会自动克隆并保存每个实例当前的位置与姿态，作为“基线位置 (Baseline)”。
2.  **手动调整位姿**：使用移动工具 (W)、旋转工具 (E) 对关卡中的 `[预览] <InstanceId>` Actor 进行空间校正。
3.  **安全回写防重**：
    *   *操作*：在不调整任何东西时，直接点击 **“提交空间变更(回写)”**，屏幕将弹出黄字提示 `没有检测到位置变更`。这能有效防止开发无意间产生的重复零偏提交。
4.  **点击“提交空间变更(回写)”**：
    *   *UE 响应*：插件会比对预览 Actor 当前的 Transform 与基线 Transform，只提取发生过变化的实例，将其发送至后端 `/api/v2/state/override`。
    *   *校验点*：屏幕弹出青字 `正在提交 1 处空间变更...`，随后显示绿字 `回写完成：成功 1 处`。
5.  **落库验证**：
    *   *操作*：点击 **“清除预览”** 后再次点击 **“从数据库拉取预览”**。
    *   *预期*：刚才被移动的设备以更新后的位置出现在关卡中，表明数据库已完成同步。
    *   *落点逻辑细节*：如果是绑定了 CAD 构件的实例，回写时后端会自动通过标定逆矩阵，将 UE 坐标换算回 CAD 规范坐标写入底座 `canonical_*` 中，确保未来即便执行全场重算，修改也绝对不会丢失。

---

### 🚚 工作流三：FR-6 存量历史设备数据迁移 (收编)

若关卡中已存在以前由美术手工摆放的很多 StaticMeshActor（不属于数字孪生库管理，无身份无接口），需要一键将其转换为受 OntoTwin 统一驱动的数据库实例。

```
[大纲新建文件夹 ToMigrate] ──> [将历史 Actor 拖入] ──> [Manager 点 导出待迁移Actor]
                                                                     │
[点 从数据库拉取预览 闭环验证] <── [Manager 点 清除已迁移Actor] <── [跑 backend/tools 离线脚本]
```

1.  **规划与归档**：
    *   在关卡大纲中新建一个文件夹，命名为 `ToMigrate`（此文件夹名可在 Manager 属性中进行自定义修改）。
    *   将所有想转换的 StaticMeshActor 拖入该文件夹中。
2.  **点击“① 导出待迁移Actor”**：
    *   *UE 响应*：Manager 扫描并提取 `ToMigrate` 文件夹下的 Actor 的 StaticMesh 路径、Guid 以及 Transform，导出成标准 JSON 并存储到本地：`Saved\OntoTwinMigration\ue_actors_export.json`。
3.  **执行离线迁移脚本**：
    *   *操作*：将该 JSON 拷贝到后端的 `backend/tools/` 下。运行以下终端命令：
        ```bash
        docker compose run --rm backend python -m tools.migrate_ue_actors
        ```
    *   *脚本原理与幂等*：
        *   脚本会根据资产名在 `mesh_type_mapping.json` 中比对相应的本体 ObjectType。
        *   **如果匹配成功**：分配对应的 ObjectType；
        *   **如果匹配失败**：将其分配给统一的 `legacy.unclassified` (Legacy 未分类) 桶作为兜底，等待将来在前端人工重分类。
        *   **幂等运行**：首次运行会返回 `{'new': 3}`。如果不改变配置重新运行，它将识别 GUID 并返回 `{'updated': 3}`，这保证了迁移的安全性。
        *   *数据集结构追加*：脚本在执行时，不仅会在 PG 的 `instance` 表中新建记录，还会将 `legacy.unclassified` 节点注册到当前项目数据集（`dataset`）之 `graph_data["nodes"]` 中，彻底解决因数据集隔离而导致前端无法看到迁移后实例的 Bug。
    *   *结果生成*：在同级目录下输出 `ue_migration_result.json`，其中包含了 `ActorGuid` 到新 `InstanceId` 的映射对。
4.  **重启后端生效**：由于后端容器缓存在内存中，迁移结束后，须使用 `docker compose restart backend` 重启进程使配置刷新。
5.  **点击“③ 清除已迁移Actor”**：
    *   *操作*：将 `ue_migration_result.json` 拷贝到关卡对应的 `Saved\OntoTwinMigration\` 目录下。点击此按钮。
    *   *UE 响应*：插件会定位那些被导出的旧 Actor 并将其从关卡中永久 Destroy（因为它们即将被数据库版本替换）。完成后保存当前关卡。
6.  **闭环拉取预览**：
    *   *操作*：点击 **“从数据库拉取预览”**。
    *   *结果*：那些被抹除的设备重新在完全一致的位置被 Spawn 生成，但现在它们已变成带有 InstanceId、能够响应后端监控与 Override 覆盖的、由数据库完全驱动的合格数字孪生体！

## 5. 深入技术细节查询

<details>
<summary><b>🔍 细节点 1：CAD 仿射变换与多坐标系转换原理</b></summary>
<p>
为解决图纸千差万别的图层比例和坐标偏差，OntoTwin 在标定阶段使用以下转换机制：
</p>

*   **标定方法**：用户在 CAD 画面与 UE 实际坐标中各找至少 3 个点（推荐 4 点），计算得到 2D Affine Transform 仿射矩阵（平移、旋转、缩放），RMSE 用于给出精度偏差反馈。
*   **空间剖面机制**：在微调位置时，OntoTwin 支持多坐标系联动。
    *   **规范系 (Canonical)**：CAD 直出毫米数值，底座唯一真源。
    *   **UE 世界系 (UE System)**：厘米数值，UE 本地渲染使用。
    *   当在 UE 中通过回写或在面板上修改任意一系数值时，公式会自动重算其余所有值。当发生全场坐标剖面重校正时，由于真源存的是规范系，重新应用矩阵即可重绘场景，极具抗抖动性。
*   **回写矩阵逆变换**：
    $$X_{canonical} = M^{-1} \cdot X_{ue}$$
    回写时自动还原为规范系，防止数据被后续重算覆盖。

</details>

<details>
<summary><b>🔍 细节点 2：本体图数据库 (Neo4j) 与运行底座 (Postgres) 双真源策略</b></summary>
<p>
为了使系统能对接工业级的上游“灵枢”本体注册中心，3.4 版本采用了如下存储拓扑：
</p>

*   **语义本体层 (真源：Neo4j)**：
    *   使用 Cypher 图查询语言进行节点和边管理，严格只读（不支持从 OntoTwin 运行时通过 API 乱写入，只能通过上游的本体工具链一键生成 Cypher 导入）。
    *   「本体图库」直连 Neo4j，自动解析呈现高维度知识图谱。
*   **运行底座 (真源：PostgreSQL)**：
    *   负责管理动态实例 (Instance)、分区 (Zone) 和具体的项目绑定状态。
    *   **单向同步**：`tools/sync_types_from_graph.py` 提供单向通道。将 Neo4j 的最新语义定义（字段类型、名称）同步到 Postgres 的 `object_type` 中作为**类型绑定缓存**，而 asset_id (三维资产定位)、ue_asset_path 等在 OntoTwin 独有的绑定字段在同步时会受到严格锁定保护，不会被冲洗。
*   **故障容灾降级**：
    *   如果 Neo4j 服务未启动或无法连接，前端相关接口会优雅返回 503，此时系统会退化为直接从 Postgres 本地缓存中读取类型信息，不影响主流程（实例运维和标定）的开展。

</details>

<details>
<summary><b>🔍 细节点 3：模型网络同步预取与 glTFRuntime 本地挂载缓存</b></summary>
<p>
为彻底解决 UE 从 HTTP 代理并发拉取大型三维包时的卡顿、连接数爆炸与丢包限制，3.3 版本对模型加载流程进行了革新：
</p>

*   **网络隔离与预取**：
    *   当实例需要从 ArtStudio 云端下载资产时，由 Flask 后端担当代理。通过 TTL 缓存查询当前模型版本，如果是新版，由后端异步将 `glb` 下载并写入绑定的物理目录 `/models`。
*   **容器挂载与本地读取**：
    *   利用 Docker 挂载，将 UE 侧固定的 Models 物理宿主机目录（如 `D:/SCC/DigitalFactoryBase_SCC/Models`）和后端的 `/models` 直连。
    *   后端下载完成后直接下发**本地文件名**。UE 侧通过 glTFRuntime 进行文件级本地加载，彻底规避了三维客户端的并发网络负担。

</details>

<details>
<summary><b>🔍 细节点 4：本地空间覆盖锁 (bLocalOverrideLock)</b></summary>
<p>
为了保证美术调整与后端驱动的最终一致性：
</p>

*   **锁定作用域**：仅针对 Transform。
*   在 `ATwinInstance::ApplySpatialFromSnapshot` 执行时，若 `bLocalOverrideLock` 被勾选为 `True`，该 Actor 将在 Tick 和快照应用时直接拦截后端的空间变换推送，保持关卡中编辑的位置不动。
*   **警告**：动画、材质变体和 3D 文字标签不受此锁限制，依然接受后端的完全调度，保证孪生体的状态一致。

</details>

## 6. 常见故障排查表 (Troubleshooting)

| 报错或现象 | 可能原因 | 解决办法 |
| :--- | :--- | :--- |
| **UE Manager 细节面板看不到任何按钮** | 选中了多个 Actor 或者多选了静态网格。 | 在大纲点空白处清空，有且仅有**单独选中** `TwinSceneManager`。 |
| **“从数据库拉取预览”点击后报红字/失败** | 后端服务未开启，或者基础 URL 未对齐。 | 检查 `docker compose ps` 确认 backend 状态；在浏览器输入 `http://127.0.0.1:5000/api/v2/state/snapshots` 确保有返回值。 |
| **拉取预览显示“预览已生成 0 个”** | 1. 实例尚未在“实例绑定台”铸造；2. Manager 里的 **SceneId/ZoneId** 误填了未匹配的值。 | 确认网页实例运维列表里该项目下存在已发布的实例；清空 Manager 的 SceneId (保持为空) 再拉取。 |
| **回写时报红“回写失败：Instance not found”** | 预览 Actor 上的 `InstanceId` 被误改，或该实例在后端网页上已被删除。 | 确认实例没有在网页上做软删，重新拉取预览后再修改回写。 |
| **“① 导出待迁移Actor”提示“导出 0 个”** | 关卡大纲里的“待迁移文件夹”名与 Manager 属性中的 `待迁移文件夹名`（默认 `ToMigrate`）不一致。 | 修改两者使其完全对齐（注意大小写），确保历史 Actor 均在文件夹内。 |
