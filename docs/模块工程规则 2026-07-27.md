# OntoTwin Nexus 模块工程规则

> 日期：2026-07-27
> 范围：**仅 Nexus 主线后端 + 前端 + UE 插件**（不含 lite/scenes）
> 用途：给「改这个模块时该守什么」立标尺；可提炼进 `~/.claude/rules/`。
> 依据：本文的依赖关系均为**实测 import**，非推断。

---

## 0 · 顶层规则：分层依赖方向（最重要）

这套后端**已经是分层架构**，只是藏在扁平目录里。以下依赖方向是铁律——**只能自上而下依赖，禁止反向或跨层回指**：

```
第 2 层  组装根        app.py
                          │  import 所有下层；不被任何模块 import
第 1 层  编排/适配      writeback · parser_dxf · project_store_pg
                          │  只依赖第 0 层
第 0 层  纯核/叶子      coord_transform · project_store · mapping_store
                        db/pg · db/graph · ontology_parser
                        coord_filter_rules · artstudio_client · ue_project_binding
                          │  只依赖第三方库 / stdlib，彼此不横向依赖
旁路     一次性工具      tools/*（import 存储与 db，但绝不挂路由）
```

**准入表（谁能 import 谁）：**

| 模块 | 允许依赖 | 禁止依赖 |
| :-- | :-- | :-- |
| `app.py` | 任意下层模块 | —— |
| `writeback.py` | `coord_transform` | **Flask / app / project_store**（store 走参数传入） |
| `project_store.py` | stdlib only | 任何 Nexus 内部模块、Flask |
| `project_store_pg.py` | `project_store` + `db.pg` | Flask、app |
| `coord_transform.py` | numpy | **一切内部模块**（必须保持纯叶子） |
| `db/graph.py` | neo4j | 写图逻辑（只读！） |
| `tools/*` | 存储 / db / mapping_store | 被 app import、挂成路由 |

> 违反这张表 = 破坏可测试性与可复用性。任何新增模块，先想清楚它落在哪一层。

## 1 · 存储层

### `project_store.py` —— 单一事实来源（核）
- **职责**：一个 Project = 一厂区全部自洽数据（object_types + instances + components + roster + calibration + frames）。内存只保留当前激活项目一份。
- **实测依赖**：零内部依赖，纯 stdlib。**这是它最大的资产，务必保持。**
- **铁律**：
  1. **唯一可见性规则**——一切只认当前激活项目；任何查询/过滤不得跨项目。
  2. 不得 import Flask 或任何业务模块（否则无法被 tools/ 和 PG 版复用）。
  3. 文件格式（`data/projects/{id}.json`）是禁改结构项（CLAUDE.md）。
- **优化点**：`_default_raw_state` 里的 I3D 字段可从 `mapping_store.INTERFACES` 派生（见方案 D）。

### `project_store_pg.py` —— PG 后端
- **职责**：继承 `ProjectStore`，**只覆盖 IO 原语**（读/写/激活/列举/删除），复用全部内存逻辑。
- **铁律**：
  1. 对外方法签名与 JSON 版**逐字一致**（app.py 80+ 处调用不得因切换后端而改）。
  2. **只覆盖 IO，不重写业务逻辑**——一旦在 PG 版里复制内存逻辑，两版立即漂移。
  3. PG 不可达时不得让 app 崩溃（降级为无激活）。
- **债务**：JSON 版仍是默认（`ONTOTWIN_STORE` 未设时）。**两版等价性无测试** → 任何存储相关改动应两个后端各验一遍，或补一个跑两遍的等价性断言。

## 2 · 坐标标定链（CAD → UE）

### `coord_transform.py` —— 仿射数学核（纯叶子）
- **职责**：numpy 最小二乘求 2D 仿射矩阵 + 正/逆变换。被 `app` 与 `writeback` **共享**。
- **铁律**：
  1. **保持零内部依赖**——它被 HTTP 层和业务层同时消费，任何内部 import 都会污染这条复用链。
  2. 与前端 `coord_transform.js` **算法对称**：改了一边必须同步另一边。
- **债务**：前后端双份是**刻意对称**，不是重复，**不要合并**；但**缺一致性测试**——应补 round-trip 断言（规范系→UE→逆变换回规范系，误差 < 阈值）。这是全仓库投产比最高的一处测试。

### `parser_dxf.py` + `coord_filter_rules.py` —— DXF 扫描与过滤
- **职责**：扫 INSERT 块 → 候选 ObjectType；按图层/块黑名单过滤。无状态。
- **规则**：过滤规则集中在 `coord_filter_rules`，不要把黑名单散进 parser 或路由。

---

## 3 · UE 交互边界

### `writeback.py` —— UE→ontotwin 空间回写（传输中立）
- **职责**：把 UE cm 变换按「绑定构件 / 自由实例」分类落回真源。
- **实测依赖**：**仅** `coord_transform`——印证 docstring 的「不依赖 Flask/app」。**这是设计亮点，守住。**
- **铁律**：
  1. **两套契约的翻译边界**：入参 `tx/ty/tz`（UE 线格式）↔ `raw_state.translation_x`（存储格式）。这**不是命名漂移**，两个命名空间都不能擅自统一。
  2. store 通过**参数**传入，模块内不得 import 具体 store。
  3. 绑定实例必须逆变换回 `canonical_*`（规范系真源），否则 `_rederive_components` 会冲掉回写。
  4. 仿射退化（profile 未标定）→ 拒绝写入，不得落垃圾坐标。

### `ue_project_binding.py` —— UE 工程身份绑定
- **职责**：数据集 ↔ 一个 UE 工程身份的绑定校验（防串台）。
- **规则**：浏览器来源放行读，UE 来源校验 header 身份；这套判定集中在此模块，不要散进路由。

---

## 4 · 本体与语义层

### `mapping_store.py` —— 系统级静态定义
- **职责**：`INTERFACES`（I3D 两层接口，**权威声明源**）+ `OBJECT_TYPES` + `MOCK_ASSETS` + `MockInstanceSimulator`。
- **铁律**：
  1. `INTERFACES` 是 I3D 字段的**单一声明源**（已被 `build_ontology_json`、`sync_types_from_graph` import）——**不许在别处 fork 一份手写副本**。
  2. `INTERFACES` 必须保持 **stdlib-only 可安全 import**（tools 依赖这一点）。
- **债务**：`OBJECT_TYPES` + `MOCK_ASSETS` ~2100 行硬编码 → 建议搬进 `data/*.json`（方案 B），`INTERFACES` 暂留。

### `db/graph.py` —— Neo4j 读层
- **铁律**：**只读**。写图唯一通道是 `本体 JSON → generate_ontology_cypher → cypher-shell`。任何「运行时写 Neo4j」的代码都是违规。
- **规则**：图库不可达 → 调用方降级 503，不拖垮主功能。

### `ontology_parser.py` —— CSV → ECharts
- **规则**：6 张 CSV 中 4 必需 2 可选的契约固定；解析产物结构（`{nodes,links,categories}`）被前端和发布链复用，不得随意改字段。

---

## 5 · 组装根

### `app.py` —— 唯一 Flask app
- **铁律**：
  1. **只做组装 + 薄路由**：路由体应薄薄几行委托给存储/业务模块，业务逻辑不得泄漏进路由（现状基本做到了，保持）。
  2. **新功能放独立子目录/模块，不再往 app.py 里塞**（CLAUDE.md）。
  3. app 是叶子的反面——**它 import 所有人，任何模块都不许 import app**（防循环）。
- **债务**：
  - `get_graph_data()` 内联 ~1200 行 demo 图 → 搬 `data/demo_graph.json`（方案 B）。
  - 87 路由域边界清晰（ontology 19 / coord 11 / binding 9…）但**暂不建议拆 Blueprint**：单人开发收益低于 churn 风险，等 B 瘦身后再评。

---

## 6 · 旁路：一次性工具

### `tools/*`
- **铁律**：
  1. **绝不挂路由**——工具是 CLI，独立跑，不进请求路径。
  2. **幂等可重跑**（迁移脚本按 GUID/api_name 去重）。
  3. RID 一次生成写进 `ontology_registry/*` 并进 git，**永不重发**——这是本体身份稳定的根基。
- **规则**：`ontology_registry/` 是生成产物，但**必须提交**（RID 靠它保持稳定）。

## 7 · 横切规则（跨模块）

| 主题 | 规则 |
| :-- | :-- |
| **可见性** | 前端 / UE / 投产，一切只认当前激活项目。 |
| **编码** | 所有读写文件强制 `encoding='utf-8'`（大量中文内容）。 |
| **依赖** | 新增 Python 依赖**先问用户**并改 `requirements.txt`；前端走 CDN，不引构建工具。 |
| **禁改结构** | `ProjectStore` 文件格式 / `mapping_rules.json` / `lite_*` 表 / 前端路由 / 现有 HTML——未确认不动。 |
| **响应形态**（债务） | 99 处 `jsonify` 有 `{"status":"ok"}` / `{"error":...}` / 裸对象三态并存；**新增路由建议统一信封**，但不为此回改存量（churn 大、单人优先级低）。 |
| **激活守卫**（债务） | `_require_active_project()` 三行守卫复制 15+ 遍 → 可抽装饰器（小而实在的优化）。 |

## 8 · 提炼进 `~/.claude/rules/` 的候选

以下 6 条最硬、最易被违反，建议提炼成 project 级或 python 级 rule 条目：

1. **分层依赖方向**（§0 准入表）——不可反向/跨层依赖。
2. **`coord_transform` 保持纯叶子**——零内部依赖，前后端算法对称。
3. **`writeback` 传输中立**——不 import Flask/store，store 走参数；tx/ty 与 translation_x 是两套契约不得统一。
4. **`project_store_pg` 只覆盖 IO**——签名与 JSON 版逐字一致，不重写业务逻辑。
5. **Neo4j 只读**——写图唯一走工具链；`INTERFACES` 是 I3D 单一声明源，不 fork。
6. **tools/ 不挂路由、幂等、RID 永不重发**。

> 这些是**在现有代码里已经成立、但没被写下来**的约束。把它们固化，价值在于：下次你或 AI 改代码时，破坏分层/契约会被规则拦住，而不是等运行时静默出错才发现。
